## 0.0 现行规格摘要（必读）

> 本摘要与 `src/` 同步（核对日期 2026-11-21）。验证入口为 `node rules.mjs` 与 `node test.mjs`。

> 当前可玩模式为标准轮、骰子轮盘和加速模式。游戏默认英文，可用右上角语言按钮切换到中文并保存选择。累计主动转距是成绩，送球阈值为每 7 格。

### 0.0.1 三个模式

| 模式 | id | 格数 N | 几何 (r, c) | 时长 | 节奏倍率曲线参数 | tempoRef | 段位线 C/B/A/S/SS |
|---|---|---|---|---|---|---|---|
| 标准轮 | standard | 28 | 4, 6 | 90s | 2.20 → 1.55 → 1.02 | 11000 | 0 / 8600 / 11400 / 12600 / 13600 |
| 骰子轮盘 | dice | 32 | 4.6, 6.5 | 110s | 2.30 → 1.60 → 1.06 | 26000 | 0 / 21000 / 25700 / 29100 / 33000 |
| 加速模式 | speed | 28 | 4, 6 | 90s | 2.20 → 1.55 → 1.02 | 11000 | 0 / 240 / 360 / 500 / 650 |

所有模式 `layout: 1`、`nozzleOff = [0]`（椭圆 0 号槽 = 顶部正中）、只有一个 3 颗待发队列。`L = 4C + 2πR`、`Δ = L/N`、`ρ = Δ/2` 仍成立。

### 0.0.2 核心数值

加速模式沿用标准轮三消和主动转距计分。转盘速度上限为 18 格/秒，基础飞行时间约 1.07 秒，每主动转动 7 格发射一颗。

- 物理速度上限为 `13 格/秒`。按住达到 `0.42 × vMax` 的基础档，快速连按可接近满速。松手后转速回落到模式的漂移速度。
- 主动转动每满 7 格立即出一颗，超出的距离留给下一发。主动转速越高，发球间隔越短。松手漂移不累计出球转距。
- 飞行：`nozzleGap 6.2 / flightSpeed 4.2 ≈ 1.48s`。高速转动时最短约 0.98s，软降使飞行进度临时提高为 4 倍。
- 节奏倍率和配乐随时间、得分推进，出球间隔由主动转距决定。
- 基础球用洋红菱形、柠黄方块、橙红星形和青蓝三角识别。高对比选项提供原对比配色与额外的图底分离。
- 特殊球包括万能、爆破和锈球。标准轮从第 24 秒起每 8 秒注入一颗锈球。骰子另有翻面骰，扑克另有染花牌。
- 计分：`BASE_SCORE = 3→300 / 4→700 / 5→1500+700×(n−5)`；基础连锁倍率 `[1, 1.6, 2.6, 4.2, 6.5, 9.0]`（骰子/扑克 `[1,2,4,8,12,12]`）；连消 3 秒窗口、20 颗封顶 5.3×；节奏倍率 1→1.45；清空跑道 +1500×tempoMult；爆破基础 220。
- 结算：时间到 = 本局正常结算（`kill('time')`，平衡测试计为「存活」）；珠子数 ≥ 本模式 N 且需要插入 = 爆仓失败（`kill('overflow')`）。**没有目标分、没有过关、没有双喷头断口。**
- 输入：A/D 或 ←/→ 转盘，按住 S / ↓ 加速落球，Enter 开局／重开，Esc 暂停，M 静音，B 切换配乐，V 高对比。空格没有游戏操作。
- 音频默认使用小星星（96→142 BPM）。配乐按钮或 B 键可切换两首 CC0 轻音乐（98.5 BPM），曲目见 `assets/audio/licenses.json`。

## 0. 三处必须拍板的底层定义

原方案最大的问题不是数值，而是**三件事没说清**，而这三件事决定其余全部实现。本文档先定死，后面所有内容从这三点推导。

### 0.1 发射权：炮口自动开火，玩家只控制"落点"

这是"反向"玩法的全部意义。**玩家不是射手，是接球方。**

- 炮口按关卡节拍**自动**发射，不需要也不允许玩家按开火键。
- 玩家唯一能改变的是**跑道相位**——也就是"这一发会落在哪一格"。
- 因此"放空"是一个**真实存在的动作**：把空隙转到落点上，让球飞过去。

原文档同时写了"自动节拍（2.10s 周期）"和"瞄准/急停/插入/插进两颗同色球正中"，等于把玩家当成射手，两套模型并存，无法编码。**本版只保留接球模型。**

> 反例检验：如果是手动发射，那么"放空累计 3 发惩罚"这条规则毫无意义（不按开火键就够了），而它占了数值表一整行——说明设计者的本意就是自动开火。

### 0.2 珠子与皮带：柔性珠链，可沿带自由滑动

- 珠子**焊死在皮带上**的话，插入必然撕裂皮带 → 物理不成立。
- 所以珠子是**可沿带自由滑动的珠子**，带速只决定整体相位。

推论（后续章节全部依赖）：
- 插入 = 落点两侧各推开半格，向最近的空位方向整体推移；
- 消除 = 断口两侧以 0.14s 合拢，空位被"挤"到别处；
- 容量 = 珠子总数，达 28 即爆仓，与空位在哪无关。

### 0.3 双喷头 = 同一个环上的两个落点，产生两个断口

- 两个落点相距**半圈 = 14 格**（验算：49.1327 / 2 / 1.7547 = 14.0）。
- 因此 L3 之后环上**同时存在两个断口**，不是一条"蛇"。
- 术语统一：**轮盘 / 珠链 / 槽位 / 落点 / 接球 / 放空**。"蛇身"一词全部废弃（它暗示一条有头有尾的链，与闭环矛盾）。

**这三条一旦定了，原文档里 60% 的歧义自动消失。**

> **【已废弃 · 见 §36】** 双喷头 / 双断口 /「落空即占格」已在回退轮整体移除。现行是**单喷头 + 单环**（`layout: 1`、`nozzleOff = [0]`），落空会吸附进链而不是占空位。本小节保留 M1 期的几何推导作为留痕；读现行几何请看 §0.0 与 §36。

## 2. 核心循环

一拍（beat）= 一个关卡节拍周期。所有状态都在这 6 步里循环：

```
[1] 充能 CHARGE      炮口蓄力，颜色已确定并可见（预警 ≥ 0.6×拍长）
        ↓
[2] 发射 FIRE        球以 32 u/s 沿弹道飞向落点，飞行 0.203s
        ↓
[3] 判落 LAND        到达瞬间判定落点格：有珠 → 插入；空位 → 放空
        ↓
[4] 结算 RESOLVE     插入后判 ≥3 同色；消除 → 记分 → 断口 0.14s 合拢
        ↓
[5] 连锁 CHAIN       合拢后再次 ≥3 → 倍率升级，回到 [4]
        ↓
[6] 检查 CHECK       爆仓 / 达标 / 超时，任一命中即结算关卡
```

**关键时序约束**：逻辑层在第 4–5 步**瞬时结算**（同一帧内算完所有连锁），表现层再用 0.30s/级 的动画依次播放。逻辑不等待动画。理由见 §5.4。

## 3. 玩家能动性模型

玩家只有 **1 个连续自由度**：跑道相位 φ ∈ [0, L)。

```
φ' = φ + v · dt
v' = clamp(v + input · a · dt, -v_max, +v_max)
input ∈ {-1, 0, +1}
```

- 松手时 `v *= exp(-k·dt)`，k = 9.049 /s（等价 60fps 下 ×0.86/帧，但**帧率无关**）
- 无输入且 |v| < 0.15 格/s → 直接归零（防抖）

**为什么只有一个自由度是对的**：接球类玩法的乐趣来自"预测 + 提前量"，不是"多键组合"。任何第二个自由度（喷头摆角、第二根独立跑道）都会稀释因果直觉。原方案 L2 给喷头加了 ±12° 摆动，等于引入第二个自由度，**与"转到对的位置"这个核心动作抢戏**——本版删除，改为由节拍与可达半径制造难度。

## 4. 空间模型

### 4.1 几何（已逐项验算）

| 符号 | 值 | 单位 | 推导 |
|---|---|---|---|
| r | 4.0 | u | 轮半径 |
| d | 12.0 | u | 两轮中心距 |
| **L** | **49.1327** | u | 闭合带长 = 2d + 2πr = 24 + 25.1327 |
| **N** | **28** | slot | 槽位数（设计定值） |
| **Δ** | **1.7547** | u | 槽距 = L / N |
| ρ | 0.8774 | u | 珠子半径 = Δ/2（相切，无重叠） |
| 喷头 A | (0, −10.5) | u | 落点 (0, −4)，射程 6.5 u |
| 喷头 B | (0, +10.5) | u | 落点 (0, +4)，射程 6.5 u |
| 两落点弧距 | 24.566 | u | = L/2 = **14 格** |

验算结论：`49.1327 / 1.7547 = 28.000`，`28 / 14 = 2.0s`（满圈时间）——原文档这三个数自洽，可以用。

### 4.2 槽位坐标

一维弧长坐标 `s ∈ [0, L)`，从喷头 A 落点起算，顺时针为正。

```
槽 i 的中心： s_i = (i + 0.5) · Δ
喷头 A 落点： s = 0
喷头 B 落点： s = L/2（第 14 号槽边界）
```

> 注意：落点落在**槽的边界**上，不是槽心。这意味着接球判定天然是"落在两格之间"，需要一个明确规则。**本版规定：落点对齐到"顺时针一侧"的槽心**，即落点所在格 = `floor((s_at_impact mod L) / Δ)`。这条必须写死，否则插入位置会随浮点误差抖动。

### 4.3 双喷头

- L1–L2：仅喷头 A。
- L3+：A/B 交替，**同一时刻只有一颗球在飞**（拍长 0.85s > 飞行 0.203s，天然不重叠）。
- 两个落点共用同一个相位 φ → 转一次同时影响两个落点。这正是 L3 的核心技巧"一转双消"的来源。

### 4.4 可达半径 —— 本方案真正的难度主旋钮

一拍之内，跑道最多能转多远？

```
最大位移 R = s_acc + (T − τ) · v_max
其中 τ = v_max / a = 0.2917s，s_acc = ½·a·τ² = 2.042 格
```

| 关卡 | 节拍 T | v·T（理想） | **R（含加速）** | 半圈覆盖率 = min(R,14)/14 |
|---|---|---|---|---|
| L1 | 2.10s | 29.4 | **27.36** | 100% |
| L2 | 1.75s | 24.5 | **22.46** | 100% |
| L3 | 1.20s | 16.8 | **14.76** | 100% |
| L4 | 1.00s | 14.0 | **11.96** | 85.4% |
| L5 | 0.85s | 11.9 | **9.86** | 70.4% |

**这张表暴露了原方案最大的结构性缺陷**：闭环上任意两点的最远距离是 14 格（半圈），而前三关的 R 全部 ≥14.76 → **L1–L3 的转轮没有任何"够不到"的压力**，难度 100% 来自节拍，转轮沦为装饰。真正的空间决策只从 L4 才开始。

**修正**：把 R 提升为显式关卡参数，五关按 20 → 17 → 15 → 12 → 10 递减（通过降 v_max 而非只压节拍）。这样每一关都同时有"反应压力"和"空间压力"，且曲线连续。

> **【已废弃 · 见 §36】** §4.3 的双喷头 / 两落点、§4.4 的"关卡可达半径 / 半圈覆盖率"都已随回退删除。现行只有单落点、无关卡，`R` 不是显式参数；难度由分数驱动的节拍曲线与各模式 `vMax` 承担（§0.0.2）。`L = 4C + 2πR`、`Δ = L/N`、`ρ = Δ/2` 三条几何关系仍成立。

## 5. 时间模型

### 5.1 关键时长

| 阶段 | 时长 | 备注 |
|---|---|---|
| 充能预警 | ≥ 0.6 × T | 颜色 + 弹道虚线段可见 |
| 飞行 | **0.2031s** | 6.5 u / 32 u·s⁻¹ |
| 插入推挤 | 0.12s | 期间不接受新插入 |
| 消除爆裂 | 0.16s | 纯表现 |
| 断口合拢 | 0.14s | 纯表现，逻辑已结算 |
| 连锁单级 | 0.30s | = 0.16 + 0.14，仅表现层 |

### 5.2 飞行期的相位漂移 —— 原方案的隐藏 bug

飞行 0.203s 内，跑道最多位移 `14 × 0.2031 = 2.84 格`，而急停磁吸容差只有 ±0.25 格——**相差 11 倍**。

所以"发射瞬间算好的落点"和"球到达时的落点"根本不是同一格。原方案没定义按哪个判定，两种实现都能写出来，但手感完全不同：

- **方案 A（发射快照）**：球锁定发射瞬间的槽位，飞行中跑道从球下面滑过。视觉上"球穿模"。
- **方案 B（到达判定）**：球落在到达时的槽位上。这才是"接球"的正确语义。

**本版采用 B**，并且必须补一个原方案完全没有的 UI：

> **落点预测环**：在落点上游显示一条随速度伸缩的虚线刻度，标出 `t_flight` 之后会到达落点的 3 个槽位（1 个主判 + 2 个次判）。没有这个元件，2.84 格的漂移就是纯随机，玩家会觉得"我明明对准了"。

这是全案**性价比最高的一个改动**：一个 UI 元件把"不可控"变成"可预判"。

### 5.3 连锁期间的时间

原方案给了 0.30s/级 的动画，却没说什么 5 连消（1.5s）期间新球怎么办。L5 拍长 0.85s，1.5s 内会来 1.76 颗球。

三种解法里只有一种是对的：

| 解法 | 问题 |
|---|---|
| 连锁期间暂停发球 | 节奏断裂，高手会利用它刷分 |
| 全局 timeScale 0.3 | 影响确定性，且"变慢"会让操作手感漂移 |
| **逻辑瞬时 + 表现排队** | ✅ 逻辑零等待，动画可重叠，确定性最好 |

本版取第三种。表现层允许动画重叠/降级（同屏 >3 组连锁时合并爆裂特效）。

### 5.4 固定步长

- 逻辑步长固定 `1/60s`，累加器最多补 5 步（超出则丢弃，防 tab 切回后的死亡螺旋）。
- 输入在**每个子步**采样一次，不在渲染帧采样。
- 表现层用 `alpha = acc / dt` 插值渲染，避免 60Hz 逻辑在 144Hz 屏上的抖动。

| 蓝 | `#3FA9FF` | 62 | ▲ 三角 |
| 金 | `#FFC53D` | 78 | ■ 方块 |
| 紫 | `#B26BFF` | 52 | ◆ 菱形 |

红/紫亮度接近（55 vs 52），**必须靠形符区分**。原方案只有色相，色盲玩家与低端屏会直接玩不了。

### 6.2 特殊球

| 球 | 权重 | 效果 | 触发关卡 |
|---|---|---|---|
| 彩虹 | 8% | 插入后**分别**与左右两侧结算，可同时消两侧 | L2+ |
| 炸弹 | 7% | 参与消除时额外炸掉左右各 1 颗（含锈球） | L2+ |
| 狂热金 | 5% | 消除后 7s 全局得分 ×2 | L2+ |
| 锁色 | 5% | 消除后**接下来 3 发**强制为场上最多色（增益，非惩罚） | L2+ |
| 锈球 | — | 不可消除，仅能被相邻消除震碎；占 1 格 | 放空惩罚 |

> **命名修正**：原文档叫"锁色球"却给的是增益，名字暗示惩罚。改叫**同色球 / 归色球**。名字与效果反了，实现时一定有人写错。

### 6.3 发色权重（防脸黑）

```
if 场上珠子数 ≥ 20:                 # 濒危保护
    最多色 65% | 彩虹/炸弹 20% | 其他 15%
else:
    按现存色数量加权 70% | 缺色球 15% | 特殊球 15%
连续非现存色上限：2 发（第 3 发强制回到现存色）
```

权重必须**基于当前盘面**计算，不能用纯随机。这是 Zuma 类游戏"看起来随机其实不气人"的关键。

## 7. 消除、连锁、断口

### 7.1 判定

插入后，从插入点向**两侧**各扩展同色连续段：

```
run = 1 + leftRun + rightRun
if run ≥ 3 and 该段不全是锈球: 消除
```

彩虹球：插入后分别与左段、右段独立判定，两侧可同时成立（这是最爽的一击，必须做）。

### 7.2 消除结算顺序（确定性要求）

同一帧内有多个可消除段时，**必须按固定顺序**结算，否则回放/排行榜不可复现：

1. 插入点触发的主消除
2. 断口合拢后，从合拢点向两侧扫描的连锁消除
3. 炸弹球附带的额外炸除
4. 多个候选段同时成立 → **按弧长坐标 s 升序**

### 7.3 连锁倍率

| 连锁级 | 1 | 2 | 3 | 4 | 5+ |
|---|---|---|---|---|---|
| 倍率 | ×1 | ×2 | ×4 | ×8 | ×12 |
| 续时 | 0 | +2.5s | +4.0s | +6.0s | +8.0s |

### 7.4 断口合拢

- 消除后，断口两侧珠子以 0.14s 缓动靠拢，空位被"挤"向最近的另一断口。
- **双断口时**：优先向较近断口合拢；等距时向顺时针侧合拢（写死，别让浮点决定）。
- 合拢完成后立即做一次连锁扫描。

## 8. 输入与手感

### 8.1 键位

| 输入 | 动作 |
|---|---|
| A / ← | 逆时针加速 |
| D / → | 顺时针加速 |
| Space | 急停（见 8.4） |
| 滚轮 | **删除**（理由见 8.4） |
| Esc / P | 暂停 |

### 8.2 物理参数（帧率无关）

```
a        = 48.0 slot/s²      # 线加速度（原文档误标为"角加速度"）
v_max    = 14.0 slot/s       # 建议按关卡下调，见 §4.4
k        = 9.049 /s          # 阻尼系数，等价 60fps 下每帧 ×0.86
停机阈值 = 0.15 slot/s
```

**原方案的 `v *= 0.86` 是逐帧乘法，直接绑定 60fps。** 在 144Hz 屏上停得比 60Hz 快 2.4 倍，手感完全变样。必须改成 `v *= exp(-k·dt)`。

顺带修正一个数据错误：原文档说"约 0.16s 停稳"。实测从 v_max 松手，0.16s 时速度仍有 **3.29 格/s**，真正停到 <1 格/s 需要 **0.29s**，滑行距离 **1.55 格**。这 1.55 格不是小事——它约等于一个槽距的 88%，是"刹车早了/晚了"的全部操作空间。

### 8.3 刹车的意义

滑行 1.55 格 + 加速 2.04 格，意味着"急转急停"一次操作要吃掉 3.6 格的空间。这是本作操作深度的真正来源：**你要提前 3.6 格开始规划**。这比"按一下停一下"有意思得多。

### 8.4 关于 Space 与滚轮：删掉滚轮

原方案有三套互相抵消的精确输入：

| 机制 | 性质 | 问题 |
|---|---|---|
| 惯性 + 阻尼 | 模拟量，考手感 | — |
| 滚轮 ±1.0 格 | 离散精确 | **一格格拨，等于关掉了手感** |
| Space 急停 + ±0.25 磁吸 | 自动瞄准 | **等于关掉了时机** |

三种同时存在，最优解永远是"滚轮拨到位 → 点 Space"。转轮就死了。

**本版处理**：
- **删除滚轮**。它是给触屏/无障碍留的后路，桌面版不需要。
- **Space 保留，但磁吸改为有条件**：仅当 |v| ≤ 4 格/s 时生效，容差 ±0.25 格；高速按 Space 只是硬刹车，无磁吸。

理由：v = 14 时，±0.25 格的窗口只有 **36ms**，等价于音游判定，此时磁吸等于送分；v ≤ 4 时窗口 125ms，磁吸只是"防手抖"。这样 Space 的定位清晰了——**它是精修工具，不是万能键**。

## 9. 计分

### 9.1 公式

```
单次消除 = 组内球数分 × 连锁倍率 × 精准系数 × 倍槽系数 × 狂热系数 × 关卡系数 k_L
```

| 项 | 值 |
|---|---|
| 组内球数分 | 3 球 300 / 4 球 500 / 5 球 800 / 6+ 球 800 + 400×(n−5) |
| 连锁倍率 | ×1 / ×2 / ×4 / ×8 / ×12 |
| 精准系数 | 插入两同色正中 ×1.5（要求两侧同色且长度相等） |
| 倍槽系数 | ×2.0（L4+） |
| 狂热系数 | ×2.0（7s） |
| **关卡系数 k_L** | **1.0 / 1.15 / 1.30 / 1.50 / 1.70** |

### 9.2 为什么必须有关卡系数

原方案没有 k_L，靠"目标分涨 10 倍"制造后期感。但分数上限由**发球数**决定，发球数由节拍决定，于是目标分直接变成了难度要求。反推原方案隐含的"平均连锁倍率"：

| 关卡 | 发球数 | 无连消上限（122 分/球） | 原目标分 | **隐含平均倍率** |
|---|---|---|---|---|
| L1 | 29 | 3,538 | 4,500 | **1.27** |
| L2 | 43 | 5,246 | 10,000 | **1.91** |
| L3 | 71 | 8,662 | 18,000 | **2.08** |
| L4 | 90 | 10,980 | 28,000 | **2.55** |
| L5 | 112 | 13,664 | 45,000 | **3.29** |

倍率阶梯是 1/2/4/8/12。**平均 3.29 意味着几乎每一波都得是 4 连以上**——这是顶尖玩家的线，被设成了 L5 的通关线。而 L1 要 1.27，对第一次玩的人等于"教学关就要求你会连锁"。

**这解释了为什么原方案读起来"很完整"但实际不可玩：所有目标分都是按理想操作拍的，没有一个是跑出来的。**

### 9.3 重定目标分（按"参考跑分 × 0.75"定通关线）

| 关卡 | 建议目标分 | 说明 |
|---|---|---|
| L1 | **2,650** | 会接球就能过，连锁是加分项 |
| L2 | **4,500** | 需要 2–3 次有效连锁 |
| L3 | **8,400** | 需要理解"一转双落点" |
| L4 | **12,300** | 需要主动布置倍槽 |
| L5 | **17,400** | 需要 4 连以上 |

**评级线**（单局总分，用于段位，不做通关门槛）：

| 段位 | 门槛 | 含义 |
|---|---|---|
| C | < 0.75× | 通关线以下 |
| B | 0.75×–1.0× | 及格 |
| A | 1.0×–1.4× | 熟练 |
| S | 1.4×–2.0× | 精通 |
| SS | > 2.0× | 极限 |

这样"通关"和"高分"分开了：**通关是 0.75 分位，SS 是 2 倍分位**。原方案把两者混成了一个数字。

### 9.4 续时

| 连锁级 | 续时 |
|---|---|
| 2 | +2.5s |
| 3 | +4.0s |
| 4 | +6.0s |
| 5+ | +8.0s |

**必须加封顶**：单关续时总量 ≤ 基础时长 × 50%（L1 最多 +30s）。

原方案续时无上限。在 60s、29 发的关里，只要每 2.5s 出一次连锁就能无限续命；配合"容量 28 很宽松"，结果是**高手永远不会输**——没有失败条件的游戏，压力全是假的。

### 9.5 全清奖励

- 一击把珠子清零：+3,000 × k_L，+5.0s，立刻补 5 颗（`红-蓝-蓝-红-金`）。
- 注意补的这 5 颗**不构成三消**，是给你下一波的引子，别写成直接送分。

### 9.6 放空的经济模型（本版核心修正）

原方案：放空累计 3 发 → 塞 1 颗锈球。问题：

> 环形跑道上的空位会随相位一起转。所以**任何时刻玩家都能把空位转到落点下面**，放空是零成本的。L1 甚至明写"无锈球惩罚"。于是最优策略 = 只接完美球，其余全放。容量永远填不满，接球压力消失。

**修正规则（M0 实装版，已取代原设想）**：

1. **球永远会落下**，不存在"让球飞过去"的动作。落点若压在已有珠上 → 插入并推开；落点若在空档 → 球直接停在空皮带上，成为一颗**孤立珠**。
2. 所以"放空"的真实含义是**把球停进空档**：不污染已有色段，但白占一格，且暂时接不上任何色段。
3. 每次占位都实打实消耗容量 → 容量成为每发的硬成本，三消是唯一的回收手段。

> 这条修改的原因：M0 实现时发现，若"落点为空 = 球飞走"，那么在 10 珠 / 28 格的盘面上，78% 的球会飞走，游戏第一秒就崩。而"落点为空 = 停在空皮带"既解决了这个问题，又保留了"我要不要让这颗球进链"的取舍——它只是把代价从"锈球惩罚"换成了"占格 + 孤立"。
>
> **原方案的"锈球"系统在 M0 中已删除**：它要解决的问题（放空无代价）已经被"落点必占格"从根上解决，再叠一层惩罚是重复设计。

## 10. 关卡脚本

设计原则仍然是"每关只引入 1 个新变量"。**原方案 L3 同时引入双喷头和同步福利，违反了自己的原则**，本版拆开。

| 关卡 | 时长 | 节拍 | 喷头 | 颜色 | 初始 | **v_max（新）** | **R（新）** | 新变量 | 目标分 |
|---|---|---|---|---|---|---|---|---|---|
| L1 启轮 | 60s | 2.10s | A | 3 色 | 6 | 20 | 20.0 | 基础循环 | 2,650 |
| L2 变奏 | 75s | 1.60s | A | 4 色 | 8 | 17 | 13.6 | 第 4 色 + 特殊球 | 4,500 |
| L3 双响 | 85s | 1.20s | A+B | 4 色 | 8 | 15 | 12.6 | 第二落点 | 8,400 |
| L4 倍槽 | 90s | 1.05s | A+B | 4 色 | 10 | 12 | 9.1 | 发光 ×2 槽 | 12,300 |
| L5 极速 | 95s | 0.90s | A+B | 4 色 | 10 | 10 | 6.8 | 节拍压缩 + 狂热翻倍 | 17,400 |

> R 全部 < 14，五关都有真实空间压力，曲线 20 → 6.8 连续递减，不再出现"前三关转轮白转"。

**无尽模式**：初始 90s，节拍 1.15s，每 25s 压 0.06s（下限 0.62s）；v_max 从 14 每 40s −0.8（下限 9）；每日种子固定。冲榜只看单局总分。

## 11. 失败、预警、保护

### 11.1 失败三条件（判定顺序写死）

1. **达标**：`score ≥ target` → 立刻过关（即使同帧爆仓，以达标优先）
2. **爆仓**：珠子数 = 28 且需要插入 → 失败
3. **超时**：计时 ≤ 0 → 失败

### 11.2 爆仓预警（原方案缺失）

- 剩 6 格：跑道外圈亮起琥珀色呼吸光
- 剩 4 格：边框脉冲 + 低频嗡鸣
- 剩 2 格：屏幕边缘红晕 + 每拍心跳音
- 剩 1 格：全场降饱和，只留球色

**没有这三段预警，爆仓就是"突然死亡"，玩家只会觉得被坑。**

### 11.3 软锁防护

若同时满足「未达标」+「不会爆仓」+「不断续时」，关卡可能无限延长。硬性规则：

- 单关续时封顶（§9.4）
- **绝对时限 = 基础时长 × 2.0**，到点强制结算（未达标则失败）

### 11.4 濒危保护

珠子 ≥ 20 时，发色权重切到"最多色 + 功能球"模式（§6.3）。把"运气差致死"改成"残局翻盘"。

## 12. 状态机

```
BOOT
 └→ TITLE ──(start)──→ LEVEL_INTRO (1.2s 关卡名 + 目标分)
                          └→ PLAY
                              ├→ PAUSED ──(resume)──→ PLAY
                              ├→ LEVEL_CLEAR ──→ RESULT ──→ next LEVEL_INTRO / TITLE
                              └→ LEVEL_FAIL  ──→ RESULT ──→ retry / TITLE
```

PLAY 内部子状态（单拍）：

```
CHARGE ─(T−t_flight)→ FIRE ─(0.203s)→ LAND ─→ RESOLVE ─(有连锁)→ CHAIN ─┐
  ↑                                                                      │
  └──────────────────── 无连锁 ←────────────────────────────────────────┘
```

约束：
- `PAUSED` 期间累加器清零，恢复时重新计时，不补帧。
- `LAND` 到 `RESOLVE` 之间不接受新的相位输入覆盖（球已落地，输入只影响下一拍）。
- 所有状态迁移都是**逻辑帧内**发生，表现层跟随，不反向驱动。

## 13. 数据结构

### 13.1 珠链（推荐：本地坐标 + 全局相位）

```js
// 不要用原方案的"单一 offset"模型：它假设珠子焊在带上，
// 一旦需要"插入推挤"和"断口合拢"的逐珠动画就崩。
const belt = {
  phase: 0,                    // 全局相位 [0, L)
  beads: [                     // 按 sLocal 升序，最多 28 个
    { id, color, sLocal, state } // state: IDLE | PUSH | CLEAR | MERGE
  ]
};

// 世界坐标 = (sLocal + phase) mod L
// 旋转：只改 phase（O(1)）
// 插入/消除：只改 sLocal（O(n)，n ≤ 28，无所谓）
```

这个拆分的好处：旋转是 O(1) 且不产生浮点漂移；局部动画只动受影响的珠子；渲染时统一 `(sLocal + phase) % L`。

### 13.2 事件队列

逻辑层不碰渲染/音频，只 push 事件：

```js
{ type: 'insert', slot, color }
{ type: 'clear',  ids: [], chainLevel, scoreDelta }
{ type: 'whiff',  color }
{ type: 'overflow' }
{ type: 'levelClear', score }
```

### 13.3 确定性要求

- 随机数：`mulberry32(seed)`，种子 = `hash(日期, 关卡)`。
- 逻辑层禁止 `Math.random()`、`Date.now()`、`performance.now()`。
- 同种子 + 同输入序列 → 逐帧一致（用于回放校验与榜单防作弊）。

## 14. 渲染与音频

### 14.1 渲染技术选型

**建议 Canvas2D，不建议 Three.js。**

理由：全场景是"一个平面上的 28 个圆 + 粒子 + 飘字"，2D 立即模式足够，60fps 毫无压力；Three.js 会为了 3 个后处理效果引入 600KB 运行时和一整套矩阵/材质心智负担。旧方案用 Three 是因为它是 3D 弹幕，本作不是。

如果一定要 3D 球体质感：用 WebGL 单 pass，**后处理只在半分辨率做一次 bloom**，别开 EffectComposer 全链路。

### 14.2 图层顺序

```
0  背景（暗场 + 双轮轮廓 + 齿轮齿纹，慢速自转）
1  轨道（内外描边 + 槽位刻度，刻度随 R 高亮可及范围）
2  珠链（球体 / 高光 / 形符）
3  落点预测环 ★ 核心 UI
4  弹道（虚线 + 落点准心 + 充能进度）
5  特效（爆裂粒子 / 涟漪 / 飘字）
6  HUD（分数 / 计时 / 目标进度 / 连击）
```

### 14.3 落点预测环（必做）

在落点上游按 `t_flight` 画 3 个渐隐圆环，标出"0.2s 后会到这里的槽"。随 |v| 增大，环间距按 `v·t_flight` 拉开。**这是全作唯一必须做到完美的表现元件。**

### 14.4 音频

| 事件 | 设计 |
|---|---|
| 转轮摩擦 | 滤波噪声，音高 ∝ |v|，v=0 时静音 |
| 棘轮咔哒 | **不要每格一次**（14 格/s = 14 次/s，会变成嗡嗡声）；改为 <4 格/s 每格、4–10 每 2 格、>10 用摩擦音替代 |
| 接球 | 短促木质击打，音高随槽位微调 |
| 连锁 | 五声音阶 C5-D5-E5-G5-A5-C6 逐级升调 |
| 放空 | 低频漏气 + 短混响 |
| 爆仓预警 | 心跳式低频脉冲，频率随剩余格数加快 |
| BGM | 120 BPM，节拍与关卡节拍对齐（L1 2.10s ≈ 2 小节） |

**音乐必须与发球节拍同源**，让"听节奏"成为可用的辅助输入。原方案没提这件事，浪费了最大的免费难度调节器。

## 18. M0 落地纪要（实现推翻了哪些设计假设）

原型在 `bicycle-chain/src/`，可直接 `npm run dev` 跑。以下是"设计时以为"和"实现后实测"的差异，**后续开发以本节为准**。

### 18.1 必须加"基础带速"（原方案没有）

**现象**：玩家完全不操作时，球反复落在同一格，把同色珠一路推开堆叠，40 秒白拿 4500 分。

**原因**：闭环珠链静止时，"往同一点反复插"等价于"往同色堆里塞"——祖玛类游戏的"链在动"不是演出，是**防堆叠机制**。

**实装**：`CFG.drift = 1.35` 格/秒。皮带永远在走，玩家是在它之上加减速，松手只会回落到带速而不是停死。这同时让"自行车链条"的名字第一次有了物理依据。

### 18.2 "28 格爆仓"在结构上几乎不可达

**现象**：机器人 20 局里，瞄准型 0 次爆仓、挂机型 0 次爆仓，最高只到 26/28 就自动回落。

**原因**：盘面越满 → 可凑三消的位置越多 → 下一发几乎必消。**密度本身就是解药**，所以容量永远够不到 28。

**结论**：容量不是失败条件，是**计分约束**（满载时你没法做长链布局，只能被迫清场）。真正的失败条件只有超时。原方案把"塞满 28 格"当核心威胁，是误判。

**影响**：关卡曲线必须靠**节拍 + 目标分**施压，不能靠容量。

### 18.3 "选位置"的收益低于"选时机"

**实测**：每发时刻，28 个落点里平均只有 **2.88 个**能直接凑成三消（10.3%），16% 的发球**一个好位置都没有**。

**含义**：
- 技巧空间是真实存在的（乱放 10% vs 瞄准 40%+），但**上限不在"选哪里"，而在"能不能在节拍内把那个位置转到落点"**。
- 所以本作的技巧本质是**提前量 + 刹车距离**，不是空间解谜。这决定了后续所有关卡设计都该压节拍，而不是加几何复杂度。

### 18.4 M0 实装参数（可玩版本 baseline）

| 参数 | 值 | 说明 |
|---|---|---|
| 关卡时长 | 90s | 原 120s 太长，90s 更适合迭代 |
| 节拍 | 2.40s → 1.30s 线性 | 90s 内压完 |
| 起始珠数 | 10 | 18 珠版本 60 局挂机死 60 局，太苛刻 |
| 颜色 | 3 色 → 25s 后 4 色 | 3 色期把"接球"教会，4 色期才考布局 |
| 最大带速 | 13 格/s | 冲一圈 2.15s |
| 带速漂移 | 1.35 格/s | 见 18.1 |
| 加速 / 阻尼 | 55 格/s² / k=9.0 | 刹车滑行 1.44 格 |
| 目标分 | 10,000 | 挂机 baseline ≈ 6,500，目标线压在它之上 |
| 评级 | B 5k / A 8k / S 13k / SS 18k | 待人类玩家校准 |

### 18.5 遗留问题（M1 要解决）

1. **挂机 baseline 偏高**（6,500/10,000）。原因是三消太容易，需要靠"连锁质量"拉开差距——目前连锁平均只有 2.3 级。
2. **连锁收益不明显**。×1/×2/×4 的阶梯在 90 秒里几乎摸不到 ×4，倍率设计需要重估（或改成"跨发连击"）。
3. **双喷头未实装**。M0 只有顶部喷头，L3 的核心技巧"一转双落点"还没验证。
4. **没有存档与排行榜**，也没接 OpenGame SDK。

## 19. M1 落地纪要：双喷头

M0 的核心缺陷是**没有压力源**：单个落点、容量永远塞不满、挂机与瞄准得分几乎相同（6,530 vs 6,545）。M1 用双喷头同时解决"没有取舍"和"没有压力"。

### 19.1 双喷头的几何解法：共用同一个 phase

两个落点在 slot 坐标下相距半圈（`NOZZLE_OFF = [0, 14]`），但**共用同一个 `phase`**：

```
落点A = mod(round(-phase) + 0,  N)
落点B = mod(round(-phase) + 14, N)
```

这一条是整个 M1 的关键。它意味着：

- 玩家操作的仍是**一个**转轮盘，不是两套控制；
- 但一次转动会**同时**改变两个落点的格局；
- 两个落点相距 14 格，节拍只有 2–3 秒，**结构上不可能两边都照顾到**。

机会成本不是靠惩罚规则堆出来的，是几何内生出来的。这是本作和普通祖玛最本质的区别。

### 19.2 落点为空时，球吸附进链（不是钉在空皮带上）

M0 的实现是"落点是空槽 → 球停在空皮带上变成孤立珠"。实测这条让 **46–54% 的落球都变成了孤立珠**，直接导致：

1. 玩家转轮盘失去意义（落点附近没珠，转了也白转）；
2. 盘面被孤立珠填满，形成不可解的死锁。

**修正**：落点为空时，球吸附到最近的珠子、插进链里（`snap()`）。这是祖玛的正统行为——球永远属于某条链。"接空"的代价从"占一格"变成"插到了你不想要的位置"，这个代价更符合直觉，也更能被玩家理解。

配套的渲染：落点为空时，从炮口指向画一条虚线连到实际插入点，并在插到位画一个小环。**不做这个可视化，玩家会以为球钉在了空处。**

### 19.3 单喷头教学期

双喷头第一秒就要求玩家同时看两个地方，实测乱按 20/20 全灭。加入 20 秒的单喷头期（`nozzle2At = 20`）：先教会"接球"，再教"取舍"。

### 19.4 五色的引入必须强制

`pickColor()` 原本 22% 概率做均匀抽样来引入新颜色。实测 5 色解锁后，青色在整局里几乎不出现——因为它在盘面上 count 为 0，永远进不了"按存量加权"的候选池，只能等那 22% × 20% ≈ 4.4% 的运气。

**修正**：当 `present.length < maxCi`（有颜色缺席）时，38% 概率直接返回缺席色。这一条同时修好了"某色被消光后不再出现"的问题。

### 19.5 M1 实装参数

| 参数 | M0 | M1 | 理由 |
|---|---|---|---|
| 喷头数 | 1 | 2（20s 后） | 压力源 + 取舍 |
| 落点间距 | — | 14 格（半圈） | 一个 phase 无法同时满足两边 |
| 节拍 | 2.40→1.30s | 3.40→2.05s | 每拍落 2 球，信息量翻倍，必须放松 |
| 起始珠数 | 10 | 8（两段各 4） | 两段落点各自有货可接 |
| 颜色 | 3 色 → 25s 后 4 色 | 4 色起手 → 45s 后 5 色 | 3 色太容易消，盘面会被抽干 |
| 目标分 | 10,000 | 5,500 | 按 M1 实测 baseline 重定 |
| 评级 | B5k/A8k/S13k/SS18k | B2.8k/A4.5k/S6.2k/SS8k | 同上 |

### 19.6 M1 实测（20 局 × 90 秒）

| 玩法 | 爆仓 | 存活 | 平均分 | 消除/落球 |
|---|---|---|---|---|
| 挂机（零输入） | 10/10 | 0/10 | 990 | 0.10 |
| 乱按（每 14 帧随机换向） | 20/20 | 0/20 | 1,390 | 0.12 |
| 瞄准机器人 | 1/20 | **19/20** | **5,585** | 0.28 |

**这是 M0 → M1 最关键的读数变化**：

| | M0 | M1 |
|---|---|---|
| 挂机 vs 瞄准 得分比 | 1.00× | **5.6×** |
| 挂机存活率 | 10/10 | **0/10** |
| 乱按存活率 | — | **0/20** |

M0 里"瞄准"完全不兑现成分数；M1 里它直接决定生死。

### 19.7 技巧空间量化

在每次发球时刻，遍历全部 28 个整相位，计算两个落点的总收益：

| 指标 | 数值 |
|---|---|
| 最优相位收益 | 119.6 |
| 随机相位收益 | 32.0 |
| **技巧倍率** | **3.74×** |
| 两个落点同时可消的相位占比 | **1%** |

最后一行是设计结论：**99% 的节拍里，玩家必须主动放弃一边**。这不是难度失衡，这就是玩法本身。

### 19.8 M1 遗留问题

1. **连锁仍然起不来**（平均 1.8–2.1 段）。原因是双喷头每拍两颗球，落点分散，很难让"第一次消除后的合拢"恰好拼出第二组。倍率阶梯（×1/×2/×4/×8/×12）实际上摸不到 ×4。**M2 需要重做连锁：改成"跨节拍连击"而不是"单次落球内的连锁"。**
2. **吸附率仍偏高**（39–44%）。根因是珠子在闭环上会聚成段、留下大段空白，落点常落在空白里。真正的解法是让珠子沿环均匀化，但那会破坏"推挤-合拢"的手感，暂不动。
3. **没有真人数据**。所有平衡数字都来自机器人，必须用真人 5 局校准。
4. 无存档、无排行榜、未接 OpenGame SDK。

## 20. M2 落地纪要：多模式、球种编码、连消、音频

M1 的遗留问题里，最硬的一条是「连锁起不来」。M2 没有绕过去加系统，而是先改掉了产生这个问题的规则，再补齐模式、可读性与表现。

### 20.1 几何必须参数化，否则「大小轮」只能靠复制代码

原实现里 `R / C / N / L / D` 是模块常量，`NOZZLE_POS` 与 `IMPACTS` 直接写死在渲染层。M2 把它们全部改成可配置：

```js
// geom.js
export let R = 4, C = 6, N = 28, L = 4*C + 2*Math.PI*R, D = L / N;
export function configure({ r, c, n }) { ... }
```

用的是 **ES 模块 live binding**：`export let` 被重新赋值后，所有 `import { N }` 的模块读到的都是新值。代价是同一时刻只能有一个 `Game` 实例——本项目成立，测试里也按模式串行跑。

炮口位置不再写死，而是由落点沿**外法向**推出：

```
nozzle = pointAt(off*D) + normalAt(off*D) * 3.7
```

`normalAt` 用「法向与位矢点乘」判朝向：跑道是闭合凸形，质心在环内，与位矢同向的那一支一定朝外。这样三射口模式下位于圆弧上的炮口也能自动朝外，不需要为每个模式写坐标。

### 20.2 四个模式

| 模式 | 格数 | 射口 | 节拍 | 时长 | 目标分 |
|---|---|---|---|---|---|
| 标准双轮 | 28 | 2（半圈） | 3.40→2.05s | 90s | 5,200 |
| 小轮练习 | 20 | 1 | 2.50→1.50s | 60s | 3,200 |
| 大轮长跑 | 40 | 2（半圈） | 3.80→2.20s | 120s | 9,000 |
| 三射口 | 30 | 3（三分环，轮转两发） | 3.90→2.60s | 75s | 4,500 |

所有参数集中在 `modes.js`，`sim.js` 只执行，界面只展示。调平衡不需要碰逻辑。

### 20.3 三射口不能「三球齐发」

这是 M2 唯一一个**结构性**判断。三消净减 2 颗，每拍落 3 球意味着每拍要凑出 3 组三消；30 格盘面在 4 色下根本给不出这么多位置。直接做必然每局 20 秒内爆仓。

做法：**轮转两发**。每拍有且只有一个口休息，下一拍换一个口休息。

```js
const idxs = [];
for (let k = 0; k < 2; k++) idxs.push((this.volleyIndex + k) % n);
this.volleyIndex = (this.volleyIndex + 1) % n;
```

三个落点仍然全部参与（每个口每 3 拍休 1 拍），压力却回到 2 球/拍。玩家能看见哪个口在休息（`REST` 标记），也能靠预览队列提前知道下一拍谁来。

> **这段方案已在 §30 整体废弃。**"轮转两发"仍然是齐射（每拍两颗同时出膛），
> 只是换哪两个口。真正的问题是"两颗球共享一个落点时刻"，
> 所以后来的解法是每拍只出一颗、口与口轮流。`REST` 标记、`volley`/`rotate` 字段一起删掉了。

### 20.4 三球预览队列

每个射口一个长度 3 的队列：`queues[i][0]` 是待发球，`[1][2]` 是预览。发球时 `shift()` 再 `push(pickColor())`。

实现上有两个细节：

1. **未激活的射口不消耗队列**。这样第 20 秒副炮上线时，玩家早就看见它要发什么颜色，而不是上线瞬间才第一次看到。
2. 预览必须画在**炮口切线方向**而不是法向外侧。法向外侧对顶部炮口是向上（会撞标题区），对底部炮口是向下（会撞连消条）；切线方向贴着跑道外缘排开，任意角度都不会侵入 HUD。

### 20.5 球的四重编码

原来只有色相 + 形符，色弱玩家仍然要靠色相猜。M2 改成四重：

| 维度 | 作用 |
|---|---|
| 色相 | 正常玩家的第一通道 |
| 明度 | 灰度下仍能区分（金/青亮，红/蓝/紫暗） |
| 内部纹样 | 环、斜纹、方板、六点、双环——轮廓之外的冗余 |
| 中心形符 | 实心圆、三角、方、菱、十字——最高对比通道 |

`V` 键切「高对比模式」：形符放进白色圆底徽章、用黑符，形状成为主要信息，颜色退成外圈。截图验证过五种形符在 40 格满盘下仍可逐一分辨。

### 20.6 连消：把「每拍都消」改成「窗口制」

M1 的连击规则是「连续每一拍都有消除才涨」。实测每拍平均只有 **0.56 次**消除，这个条件等于永远拿不到加成——机器人峰值连击只有 3.6，倍率几乎没上过 1.6×。

M2 改成：

- **按消掉的颗数累加**（一次四消直接 +4）；
- **3 秒内没有新消除才断**；
- 倍率表最多 5.3×（连消 20 颗）。

改完机器人峰值连消 6.5–14.8，倍率真正参与结算。这是 M2 对分数曲线影响最大的一处。

清空跑道额外 +1500，并给一次全屏冲击波——它鼓励「敢把盘面打空」，和「密度即解药」的结构正好互补。

### 20.7 特效与音频

消除事件现在携带 `s0 / len / chain / combo`，表现层据此生成：

- 沿跑道的**光带**（按弧长采样，跟随弯道）；
- 扩散**冲击环** + 粒子；
- 屏幕震动与瞬时闪光，强度随连锁与连消递增；
- 飘字：`+分数`、`连锁 ×N`、`连消 ×N`。

音频全部程序化合成，两条总线（music / sfx）。BGM 是 32 个八分音符的循环（96 BPM），用 `ctx.currentTime` 提前 0.2 秒调度，不随帧率漂移。强度由盘面占用率驱动：越挤，琶音越亮、踩镲越密。

### 20.8 M2 实测（每模式 12 局）

| 模式 | 瞄准得分 | 瞄准存活 | 乱按存活 | 挂机存活 | 技巧倍率 |
|---|---|---|---|---|---|
| 标准双轮 | 9,233 | 12/12 | 0/12 | 0/12 | 3.02× |
| 小轮练习 | 4,346 | 12/12 | 4/12 | 4/12 | 4.84× |
| 大轮长跑 | 12,146 | 12/12 | 1/12 | 1/12 | 4.74× |
| 三射口 | 6,950 | 12/12 | 2/12 | 1/12 | 3.98× |

不变量检查 38,455 项全部通过（队列长度、槽位占用上限、相位范围、分数有限性）。

### 20.9 M2 遗留

1. **小轮仍可挂机 4/12**。它是练习关，刻意留了容错；但「不操作也能过三分之一」还是偏高，M3 要么缩短时长，要么在 45 秒后强制提速。
2. **40 格满盘时珠子刚好相切**，视觉上偏挤。若要更松弛，需要把 D 与 BEAD_R 的比例从 0.94 降到 0.88，代价是「珠链感」变弱。
3. **连锁仍以 1–2 段为主**。合拢后的二次匹配天然稀少，这是几何决定的，不是参数问题。要让连锁常见，得引入「同色磁吸」之类的规则，但那会改变玩法内核，暂不做。
4. 仍无真人数据、无排行榜、未接 OpenGame SDK。

## 21. 飞行时长：0.203 → 0.34s，以及它带来的连锁改动

> **【历史 · 数字已被 §24 → §30.4 两次取代】** 文末写的「最终值 0.80s」也不是终点：现行起手飞行 = `nozzleGap 4.6 / flightSpeed 3.5 = 1.31s`，满速 `beat × 0.86 = 0.88s`（§0.0.2）。本节保留「飞行越久 → 落点漂移越大 → 必须给预告」这条仍然成立的因果链。

> **本节已被 §24 取代。** 0.34s 仍被玩家认为太快，最终值是 0.80s。保留本节是因为它记录的那条因果链（飞行越久 → 落点漂移越大 → 必须给预告）依然成立，只是当时对"屏幕速度"的理解是错的，见 §24.1。

需求原话是"射出的球追到链条的时间要慢一点"。这不是一个纯视觉参数 —— 球在飞的时候链条一直在动，**飞行越久，落点离"你按下那一刻对准的位置"越远**。

### 21.1 先算清楚代价

落点是在 `land()` 用**当帧 phase** 算的，所以飞行期的位移直接决定命中：

| 飞行时长 | 静止时漂移位移 | 满速时的位移 |
|---|---|---|
| 0.203s（旧） | 0.27 槽（在 ±0.5 取整窗口内） | 2.6 槽 |
| 0.34s（新） | **0.46 槽**（贴到窗口边缘） | 4.4 槽 |

第三列说明：**只要玩家在球飞行时还在转轮盘，落点就会被自己的输入带偏**。这不是 bug，是"提前量"这个技能的物理来源；但 0.34s 下它变成了必须遵守的纪律。

### 21.2 实测：三种控制方式的存活率（标准模式，32 局）

| 控制方式 | 存活 | 均分 |
|---|---|---|
| 边飞边改（持续追最优相位） | 8/32 | 6,228 |
| 发射后收手（飞行期不动） | 24/32 | 7,270 |
| 旧参数 0.203s + 边飞边改 | 30/32 | 7,612 |

结论：**球变慢不是"难度变高"，是"操作节奏变了"** —— 需要从"持续微调"改成"发射 → 松手 → 落地 → 再动"。所以渲染层必须把这条规则教给玩家，否则就是纯挫败。

### 21.3 三条配套修正（缺一不可）

1. **落点预告环**：在链条上圈住"球落地时会被击中的那颗珠"（白环 + 珠色外发光）。
   - 只在**开火前 0.55 秒到落地之间**显示 —— 没有球在飞时，松手预测要跨过整整一拍（4 格以上），那不是玩家正在做的决定。
   - 只给**真正会开火的口**画环。三射口模式有一个口在轮休，给它也画环等于骗人。
   - 预测公式与 sim 的 `land()` 完全一致（用阻尼解析积分算"松手后滑多远"），实测 **404 次落点，0 次偏差**。

2. **珠链命中高亮的方向修正**：`arrivalAlpha()` 原来把峰值放在 `dist=0`，也就是**即将离开炮口**的那颗珠。球越快这个错越不明显（0.203s 时误差小于半格），球一慢就原形毕露 —— 玩家会发现自己一直瞄的是"上一颗"。现在峰值落在 `dist≈|coast|`，即真正会被击中的那颗。

3. **飞行轨迹**：沿**切线**方向起弧 + 「半线性半 smoothstep」缓动。
   - 弧线原来沿外法向鼓，正好顶在前进方向的反面，球看起来像卡在炮口没动。
   - 纯 smoothstep 的峰值速度是平均值的 1.5 倍，那一下"窜"正是"一闪就到"的来源；混一半线性后接近匀速。

### 21.4 新的操作纪律

**发射 → 松手 → 落地 → 再动。**

球在空中时继续转轮盘，会把这一发打偏。这条规则由"预告环亮起"来提示：环亮 = 你已经进入承诺期。

### 21.5 改完的数据（每模式 12 局）

| 模式 | 瞄准得分 | 存活 | 对比 M2 |
|---|---|---|---|
| 标准双轮 | 8,815 | 10/12 | 9,233 / 12/12 |
| 小轮练习 | 4,855 | 12/12 | 4,346 / 12/12 |
| 大轮长跑 | 10,644 | 12/12 | 12,146 / 12/12 |
| 三射口 | 5,952 | 12/12 | 6,950 / 12/12 |

标准模式掉了 2 局，其余持平或更好；四个目标分仍然全部可达。

**注意**：本轮同时改了测试机器人的控制律（加入"发射后收手"、给 `1/T` 增益加下限 0.30）。改动前它每帧满速乱撞，会把难度高估一倍。

## 22. 分数段与段位反馈

### 22.1 「按分数段变色」这个提议只对了一半

颜色是**状态**，不是**动机**。把分数从白色改成金色，玩家看到的是"我现在是什么颜色"，而不是"我要去打更高"。持续状态不会产生驱动力，只会变成装饰；更糟的是，如果阈值定得不对，它还会传递错误信息（"随便打打就是 SS"）。

真正能推动复玩的是三件事，缺一不可：

1. **可见的下一档**（目标梯度效应：离目标越近，投入越强）
2. **跨档那一瞬间的爆发**（事件才形成记忆点）
3. **跨局的身份**（"我在这关是 S"，而不是"我打了 8,200 分"）

所以本轮做的是三件套，颜色只是其中最低成本的一层。

### 22.2 落地清单

| 位置 | 内容 | 作用 |
|---|---|---|
| HUD 分数 | 数字按档位着色 + 段位徽章（C/B/A/S/SS） | 状态识别，余光可读 |
| HUD 分数下方 | 档内进度条 + 右端"下一档"刻度（越近越亮） | 目标梯度，告诉玩家"就差一点" |
| HUD 进度条下 | `NEXT A −1,240` | 把"差多少"变成确切数字，不说模糊的"加油" |
| 跨档瞬间 | `RANK A` 浮字 + 冲击波 + 闪光 + 上行琶音 | 把状态变化变成事件 |
| 结算页 | `距 S 还差 420 分` | 复玩钩子：差得越少，重开率越高 |
| 标题页卡片 | 右上角历史最高段位徽章 | 跨局身份，存档有意义 |

SS 段额外加了呼吸明灭（`0.74 + 0.26·sin(4t)`），让最高档"看起来在烧"，和下面四档拉开体感差异。

### 22.3 阈值怎么定：分位数 + 人类左移

每个模式跑 20 局完美瞄准机器人（**1/120 真实步长**），取分位数：

| 模式 | p10 | p25 | p50 | p75 | p90 |
|---|---|---|---|---|---|
| 标准双轮 | 3,900 | 6,500 | 7,800 | 9,600 | 10,800 |
| 小轮练习 | 3,400 | 3,800 | 4,300 | 5,000 | 6,200 |
| 大轮长跑 | 7,900 | 9,000 | 9,300 | 11,000 | 13,100 |
| 三射口 | 4,600 | 4,900 | 5,400 | 7,300 | 8,500 |

映射规则：**B≈p10 / A≈p25 / S≈p50 / SS≈p75~p85**。

关键在"为什么不用 p90 当 SS"。机器人每帧计算最优相位、零反应延迟，人类达不到它的水平。如果把机器人 p90 定为 SS，人类最好的玩家也只能摸到 S —— **拿不到的顶级等于不存在**，玩家会直接放弃追求。所以整条分位映射要往左移一档，让机器人当"人类高手"的替身。

另一条约束：**档间距不窄于总分的一成**。三射口和大轮的中段分布很密（p25 到 p50 只差 400~500 分），按原始分位画线会导致"一次三消跨两档"，跨档演出就不稀缺了。

### 22.4 颜色选型的两个硬约束

1. **不能和球色撞**。球已占用红/蓝/黄/紫/青五色，并靠色相 + 明度 + 纹样 + 形符四重编码。分数段若用紫色，会和球紫混淆。所以走「等级色阶」惯例：灰 → 绿 → 蓝 → 橙 → 白热，避开紫。
2. **不能和警告撞**。右侧 CHAIN LOAD 用红（危险）/黄（警告），TIME 最后 15 秒也转红。这些是**紧急信号**，优先级必须高于段位。段位是静态色、警告是闪烁色，位置也分离（左上 vs 右侧），才不打架。

C 段原本用 `#8B9BB4`，实测在深底上几乎读不出来，提亮到 `#AEBED2`。**深色主题下"低调"和"看不见"只差一档**。

### 22.5 顺手修掉的一个真 bug：测试步长 ≠ 运行步长

做分档时发现同一批种子对不上，查明：`main.js` 用 `DT = 1/120`，而 `test.mjs` 用 `1/60`。

这个游戏是"精确相位对准"，对时序混沌敏感。实测同一个种子在两种步长下会走向完全不同的分支：

| seed | 1/60 得分 | 1/120 得分 |
|---|---|---|
| 19 | 6,600 | 14,469 |
| 13 | 11,181 | 6,537 |
| 4 | 8,637 | 3,015 |

也就是说，**§21.5 那张表、以及之前所有平衡结论，测的都是"另一个游戏"**。已把 `test.mjs` 统一到 `1/120`，并重跑全部数据。

顺带修掉：`?ff=` 快进到死时直接切结果页、不写 `best`，导致调试截图与真实游玩战绩不一致。现在统一走 `finishRun()`。

### 22.6 当前段位分布（瞄准机器人，12 局）

| 模式 | C | B | A | S | SS |
|---|---|---|---|---|---|
| 标准双轮 | 1 | 1 | 5 | 2 | 3 |
| 小轮练习 | 2 | 3 | 1 | 2 | 4 |
| 大轮长跑 | 2 | 4 | 2 | 1 | 3 |
| 三射口 | 1 | 5 | 2 | 3 | 1 |

乱按玩家的分布：标准/大轮/三射口全部落 C，小轮 8/12 落 C、偶尔摸到 B/A。**C 档是有效的兜底，没有出现"乱按也能 B"的失真。**

SS 占比 8%~33%。机器人本来就该在 SS 附近聚集（它就是"人类高手"的替身），真正的检验要等真人数据。

### 23.2 品类不是 Zuma 发明的

- 1998 年 Mitchell Corporation 街机《Puzz Loop》（北美名 Ballistic，DS 名 Magnetica）是该品类的源头。

### 23.3 本作天然具备的防御性差异

万一被比对，以下几个差异点是结构性成立的，不是贴皮：

1. **视角反转**：玩家是接球方，炮口自动开火，玩家只控制落点相位。原品类是玩家当射手。
2. **闭环双轮**：跑道首尾相接，两个落点共用同一 `phase`，机会成本由几何内生（见 §0.1、M1 纪要）。
3. **吸附而非孤立珠**：落点为空时球插进最近的珠子，保留"球永远属于某条链"的品类正统性。
4. **视觉体系完全不同**：几何光效 + 球种四重编码 + 色弱模式；无阿兹特克、无石蛙、无神庙、无骷髅口。
5. **独立创作证据链**：完整的设计文档演进（§18~§22 的每次推翻）+ git 提交历史，可证明从零推导而非照搬。

第 5 条最实用。**git 历史就是最便宜的原创证据**，不要 squash 掉。

## 24. 飞行时长第二刀：0.34 → 0.80s，以及一个骗了很久的机器人缺陷

> **【历史 · 0.80s 不是终点】** 已被 §30.4 取代：`nozzleGap 3.7→4.6`、`flightSpeed 4.6→3.5`，起手飞行 1.31s；§31.3 又把它改成 `min(1.31, beat × 0.86)`（标准满速 0.88s）。本节「加长飞行几乎不增加难度 + 机器人控制律缺陷」的结论仍成立。

### 24.1 先把问题重新定义对

上一轮（§21）把"球到得太快"当成"球飞得快"，于是把 `flightTime` 从 0.203 拉到 0.34。玩家仍然反馈"追上末尾球的时间太短"。

第二次才想清楚：屏幕上的速度不是球的速度，是**球的位移 + 链条迎面滑过来的位移**之和。

| 项 | 0.34s | 0.80s |
|---|---|---|
| 球速（炮口→跑道约 113px） | 332 px/s | 141 px/s |
| 链条迎面速度（drift 1.35 槽/s） | 72 px/s | 72 px/s |
| **眼睛看到的接近速度** | **404 px/s ≈ 8 球径/秒** | **213 px/s ≈ 3 球径/秒** |

8 球径/秒超出人眼追踪单体的舒适区，玩家只能看到"一闪"，看不到"追"这个动作。3 球径/秒才留得住过程。

### 24.2 反直觉结论：加长飞行几乎不增加难度

这是本轮最有价值的一条，也是它一开始让我不敢下手的原因。

改完 0.66 之后我准备重调所有平衡，结果发现 `flightTime` 从 0.66 到 0.80，四模式的机器人得分差异在 1% 以内：

| 模式 | 0.66s | 0.80s |
|---|---|---|
| 标准双轮 | 7,648 | 7,648 |
| 小轮练习 | 4,643 | 4,643 |
| 大轮长跑 | 10,171 | 10,010 |
| 三射口 | 6,447 | 6,447 |

三个模式的 12 局分数**逐位相同**。原因是落点漂移完全可解析（`coast = drift·T + (v−drift)(1−e^{−kT})/k`），完美玩家会提前补偿，所以"球在空中多久"对它没有影响。

**飞行时长只消耗人类的预判窗口，不改变游戏的数学难度。** 这正好是我们要的：让反应慢的玩家看得清，而不是把游戏改简单或改难。

### 24.3 但它炸出了机器人控制律的真实缺陷

在拿到上面这个结论之前，我先踩了一个坑：`flightTime` 改成 0.66 时，标准模式的机器人爆仓 10/12、得分从 8,586 掉到 4,227。

第一反应是"飞行期滑移 0.9 格，游戏变难了"，于是去降 `drift`（1.35 → 0.90）。结果**更糟**：标准 4,370，大轮 6,584。降速本该让游戏更简单，反而更差——这个矛盾说明问题不在游戏，在测量工具。

查下去发现 `bot.js` 的控制律是一阶近似：

```js
nv = drift + err / T          // 旧
```

它把 `drift` 同时当成了"基础推进力"和"漂移量"。真实的位移是指数衰减的，`err/T` 只在 `T` 很小时成立。`flightTime` 从 0.34 拉到 0.66，`T` 变大，近似误差被放大到无法忽略；而降 `drift` 直接抽掉了这个公式的底座。

改成解析反解：

```js
// coast(v,T) = drift·T + (v−drift)(1−e^{−kT})/k  = gap
// ⇒ v = drift + (gap − drift·T)·k/(1−e^{−kT})
```

同一份 `flightTime = 0.66`，同一批种子：

| | 旧控制律 | 精确反解 |
|---|---|---|
| 标准双轮 | 4,227（爆仓 10/12） | **7,648（12/12 存活）** |
| 大轮长跑 | 7,597（爆仓 4/12） | **10,171（12/12）** |
| 三射口 | 5,867（爆仓 1/12） | **6,447（12/12）** |

也就是说，**"游戏变难了"这个判断完全是假的**，是机器人自己不会瞄准。

这是第三次同类事故：

| 次数 | 表面结论 | 真因 |
|---|---|---|
| REVIEW §12.3 | 难度曲线不合理 | 机器人边飞边改，把落点带偏 |
| §22.5 | 分数分布不对 | 测试步长 1/60 ≠ 运行 1/120 |
| §24.3 | 加长飞行导致爆仓 | 控制律用一阶近似，T 变大后失效 |

三次都不是游戏的问题，都是**用代理去判断体验时，代理本身失真**。规律很清楚：只要动了"时间尺度"或"控制回路"的参数，就必须先验证代理在这个新尺度下还算不算数。

|---|---|---|---|---|---|---|
| 标准双轮 | 6,105 | 6,861 | 7,704 | 8,412 | 9,741 | 5,700 / 6,800 / 7,900 / 9,600 |
| 小轮练习 | 3,375 | 3,870 | 4,107 | 5,028 | 6,612 | 3,400 / 4,050 / 4,750 / 5,700 |

### 24.5 代价与遗留

1. **链条在飞行期间滑过 1.1 格**（超过一整格）。落点预告环从"辅助"变成"必需品"，关掉它这个时长就没法玩。目前没有关闭选项，等于隐性强制。
2. **小轮模式的拍长最短 1.5s，飞行占 53%**。球还没落地下一拍就要来了，画面上会有两批球交替。机器人不受影响，人类可能会觉得挤。
3. **0.80s 是估算的终点，不是验证过的终点**。舒适区在 0.6~0.9 之间，只有真人能定。如果还嫌快，下一档应该动炮口距离（把 3.7 单位拉远），而不是继续拉时间——时间再长，节奏会散。

## 25. 三消演出的时间预算：0.4s → 0.7s

### 25.1 先列清单，再动数值

"三消表现时间慢一些"不是一个参数，是四条并行的线。只拉其中一条，看起来会像"画面在回放、别的东西先走了"。

| 元素 | 原时长 | 现时长 | 作用 |
|---|---|---|---|
| 光带 beam | 0.36s | 0.62s | 告诉玩家"消的是这一段" |
| 冲击波 shock | 0.40s | 0.68s | 把能量推到周围 |
| 球体消散 ghost | 无 | 0.52s | 补上"大球碎成小点"之间断掉的那一拍 |
| 粒子 | 0.30~0.66s | 0.46~0.98s | 碎屑，负责密度 |
| 分数浮字 | 1.05s | 1.30s | 确认"这一下值多少" |
| 消除音效尾音 | 0.16s | 0.24s | 与视觉同收 |

浮字必须最长。如果数字先消失，玩家会处在"看到爆炸但不知道赚了多少"的状态——比不做特效更糟。

### 25.2 粒子要"减速"，不是"延长"

第一版只把粒子的 `life` 从 0.3~0.66 拉到 0.46~0.98，结果碎片飞得到处都是，甚至越过跑道压到 HUD 上，看起来像漏液。

初速不变而寿命变长，位移就是线性增加。所以正确做法是三件事一起做：

| 参数 | 原值 | 新值 |
|---|---|---|
| 初速 | 60 + rand·260 | 44 + rand·196 |
| 阻尼 | 2.6 | 2.0 |
| 重力 | 420 | 320 |

**"慢"是让同样的距离走更久，不是让它走更远。** 这一条在 §24 调球的飞行时也同样成立（那里是改成拉长时间而不是提高速度），但当时没抽象出来，这里才写清楚。

### 25.3 球消失的动画做了三次才对

这是本轮唯一反复的地方，三次都不对：

| 尝试 | 做法 | 结果 |
|---|---|---|
| 1 | 扩散光圈，半径 1.4 倍 | 消除后 `compact()` 会把后面的珠子前移占住原位，光圈必然和球重叠，读起来是"珠子描了一圈色" |
| 2 | 把光圈 alpha 压到 0.36 做成雾 | 几乎看不见，等于没做 |
| 3 | **原球原地缩小 + 全程叠白** | 成立 |

前两次的根因是同一个：**想用"新东西"去表示"消失"**。而消除后原位置立刻会被新珠子占据，任何画在原地的图形都会被读成新珠子的属性。

第三次改成让那颗球自己缩掉，语义就没有歧义了。但只缩小还不够——静态看缩小的球仍然是完整的球（有高光、有纹样），像"跑道上多了几颗小球"。所以叠了一层持续上升的白：白度 `k^0.7`，随缩小同步。读起来才是"过载 → 湮灭"。

白化只在尾段做也不够（第一版从 `k>0.25` 才开始），因为前半段缩短的球已经能被误认成小球了。

### 25.4 冲击波走缓出

半径原来是线性 `r = r0 + (r1−r0)·k`。线性扩张在整段时间里速度不变，观感是"匀速飘走"；改成缓出 `1−(1−k)²` 之后，前半程铺开、后半程几乎停住。**同样 0.68s，体感明显更慢，而且更有分量。**

这是个便宜的技巧：想让某个特效"变慢"，先看它的缓动，再看时长。线性运动的"慢"要靠加时间，缓出的"慢"不用。

### 25.5 遗留

1. **连续消除会叠加**。实测每拍平均 0.5~1 次消除，0.7s 的演出重叠概率不低。理论上会糊，但"糊"在消除品类里通常被读成"打得好"，这一条只能真人判断。
2. **三射口模式同时三个落点**，一次连锁最多 9 颗球同时消散。粒子上限没有做，帧率在低端机上可能掉。目前没测过真机。
3. **`?cb=1` 色弱模式下的对比度没复验**。白色叠加会降低球色辨识度，色弱玩家可能更难分辨"正在消失的是哪一色"。但这个信息在消失瞬间不重要（玩家已经看到消除了），暂不处理。

## 26. 七种球体与机械底盘

### 26.1 为什么把形状提成第一编码

上一版的球是「圆盘 + 内部纹样 + 中心形符」，四种区分全压在同一块圆形画布里的细节上。

问题在于**细节是最先丢失的通道**：珠子在跑道上移动、尺寸只有 50px、玩家用余光看的是"下一发该打哪"。远处、运动、色弱这三种情况叠加，纹样和形符会同时糊掉，剩下的只有色相——而色相恰恰是色弱玩家最不可靠的通道。等于说，这套编码在最需要它的时候最不可靠。

这一版让 7 种球有 7 个互不相似的**剪影**：

| 球 | 形状 | 剪影特征 |
|---|---|---|
| 紫 | 八面体菱晶 | 竖长的菱形，竖棱分左右明暗 |
| 金 | 倒角琥珀方核 | 圆角方 + 下沉内面 |
| 红 | 星芒棱刺火核 | 10 根棱刺的外轮廓 |
| 青 | 三角棱锥晶 | 向上尖的三角 + Y 形棱线 |
| 万能 | 彩虹五角星 | 五角 + 外侧金色椭圆光环 |
| 爆破 | 暗钛机械雷 | 圆 + 一圈铆钉 + 熔橙核心 |
| 锈 | 锈铁块 | 不规则多边形 + 麻点，**零发光** |

剪影识别走的是「类别 → 个体」两级：先分"尖的 / 方的 / 带刺的 / 三角的"，再用颜色定"哪一个"。所以**高对比模式（V）不再需要额外形符**，只做图底分离（给球加暗底光晕）就够了。形符那套东西被删掉了：当形状本身已经唯一，再叠一层符号是噪音。

### 26.2 一条视觉规则：会发光 = 可消

盘面上所有发光的东西都是"可消资源"。锈球**刻意做成零自发光**（无 shadowBlur、无高光、无 inner glow），玩家第一眼就知道它不参与匹配——这比在石头上写个"不可消"的符号更早被眼睛接收到。

同理，爆破球的核心是全场最亮的橙色，因为它是"一次性的强动作"；万能球是全场唯一的多色物体，因为它的语义就是"任意色"。

### 26.3 万能球：落地即定型，不在链上保留彩虹态

标准做法是让万能球在链条上继续保持"可变色"，匹配时任意替代。这里没有这么做，原因是**判定唯一性**：

`findMatch` 是一条横扫的游程扫描。一旦允许"链上的球仍可变色"，同一个盘面就有多组解，消哪一段取决于扫描顺序，玩家无法预测。这类不可预测性在消除游戏里是致命的——玩家会把"没消掉"归因为游戏坏了。

落地定型把歧义消灭在落地那一刻：吸附到最终槽位之后，按"左右各能连多少颗同色"选出最优色，一次定死。玩家看到的仍然是"我把它变成了需要的色"，观感和"万能"完全一致，但判定是唯一的、可复盘的。

### 26.4 爆破球的代价不在颜色，在那一发

爆破球落地即炸，清掉落点两侧最多 5 格（含跨色），不给分颜色。

它的成本不是"少一个颜色"，而是**那一发**：两球一拍里，你用掉了一颗本该用来补洞的球。所以威力只给 5 格——再大就等于给了一个"随时清盘"的按钮，盘面压力会被抹平。基础分 220 也刻意低于一次三消（300），否则最优解会变成"一直等炸弹"。

### 26.5 锈球：难度从哪里来

美术规格把基础色从 5 种收到 4 种。这在观感上是好事（更好认），但在数值上是**难度直降**：第 5 色原本承担"45 秒后变难"的阶梯，现在没了。

锈球是补上这个支点的东西，而且它比"多一个颜色"更好：

1. **不参与匹配**，哪怕 4 颗锈球挨在一起也不会自己消掉；
2. **打断同色连续段**，本来能三消的地方变成两消；
3. 唯一出口是**被相邻消除震碎**（并进同一段清除，否则链条中间会留洞）或**被炸弹炸掉**。

于是"清盘"从"顺手"变成"要专门去做"：你得把消除安排在锈球旁边，而不是打在空处。

实测挂机（不操作）从"能活 5/12"掉到**大轮长跑 0/12 存活、标准 2/12**。锈球是唯一能惩罚"什么都不做"的机制。

### 26.6 底盘分层

绘制顺序固定为：托盘 → 飞轮 → 凹槽导轨 → 双倍槽 → 珠子。

- **托盘**：拉丝金属，比导轨宽一圈。拉丝线的行距用质数（`yy*37 % 17`），否则会和屏幕像素栅格产生摩尔纹，在暗部看成一圈圈脏渐变。
- **飞轮**：位置就是两个半圆的圆心，所以它读起来是"链条绕过的那两个轮"，不是贴上去的装饰。转速直接取 `phase`：链条走多少，轮就转多少。玩家按方向键时能看到轮跟手转——这是整台机器"活着"的凭据。
- **凹槽**：中间压一条更暗的窄带，形成"两条平行轨"的错觉；内侧透青色底光。珠子必须看起来是**嵌进去**的，所以槽底要比珠子暗得多。
- **炮筒**：在局部坐标系里画（局部 +Y 指向跑道），所以"上方单炮"和"下方复制 180°"复用同一个函数——拆解图里"复制旋转 180°"那句话的代码形态就是这一行 `rotate(atan2(nz.nx, -nz.ny))`。

### 26.7 ×2 槽：判定在消除段的中心弧长

> **【已废弃 · 见 §28.4；后续 §33.5 / §34.6 以新判据回归】** 基础模式的 ×2 槽已在 §28.4 下线。骰子模式的 ×2 镀金 / +1 翻面槽、扑克模式的筹码槽是**把状态写在骰子/牌上**的新机制，不是这里"每 20 秒换位的基础槽"复活。

槽位按**弧长**固定在世界坐标上，不跟珠子走。判定点是消除段的中心，不是落点——玩家要瞄的是"让这一下消在槽里"，而不是"把球打进槽里"。

每 20 秒整体换位，且与炮口落点至少隔 1.4 格：槽如果压在炮口上，玩家什么都不用做就能吃双倍，这个机制就变成白送分。

实测命中率 **8%~19%**（每局 2~3 次），带来约 **+20% 总分**。这个数字说明它现在是"偶得奖励"，还不是"策略"——见 §26.9。

### 26.8 数据（40 局/模式，1/120 步长）

| 模式 | p10 | p25 | p50 | p75 | p85 | 新段位线 B/A/S/SS |
|---|---|---|---|---|---|---|
| 标准双轮 | 11,723 | 13,769 | 15,333 | 18,633 | 21,727 | 11,800 / 13,800 / 15,800 / 20,000 |
| 小轮练习 | 5,286 | 5,969 | 6,793 | 8,454 | 9,490 | 5,300 / 6,000 / 6,900 / 9,000 |
| 大轮长跑 | 14,252 | 15,847 | 17,330 | 19,956 | 20,780 | 14,300 / 15,900 / 17,400 / 20,800 |

段位分布（12 局）：标准 C4 B2 A3 S3 SS0；小轮 C1 B2 A6 S1 SS2；大轮 C0 B1 A5 S5 SS1；三射口 C1 B2 A2 S5 SS2。乱按几乎全 C（三射口 12/12 C），兜底仍然有效。

**必须强调的一点**：分数对种子极度敏感。同一份代码，种子 4000 批次的标准模式中位数 13,690，种子 9200 批次 17,623——差了 29%。所以段位线只能用**大批次合并分位**（这轮用 40 局），单批 12 局的分布只能当作"没有明显失真"的快速检查，不能当成校准依据。

分数整体上移约 55%（7,648 → 11,800 量级）。这**不是**难度调整，是"5 色变 4 色"这个设计规格变化带来的必然结果。段位线是相对的，绝对分不重要。

### 26.9 遗留

1. **×2 槽还不是策略**。命中靠"槽恰好落在你打的那一段"，玩家没法主动规划。要变成策略，得让槽的位置可预测地靠近炮口落点（例如固定在落点 ±1.6~2.6 格），代价是双倍变成"几乎必得"，总分要再涨一轮。这一轮没有做，因为无法用机器人验证"人类是否觉得这是个决策"。
2. **4 色让后半段变简单**。原本第 5 色在 45 秒出现，现在没有对应的阶梯。下一刀建议给 `rustEvery` 加时间阶梯（24s 起 9 秒一颗 → 50s 起 6 秒 → 75s 起 4.5 秒），而不是把第 5 色加回来——颜色加回去等于把形状编码的收益吐出去一半。
3. **小轮只有 20 格**，塞 4 色 + 锈球时空间极紧，锈球频率已被调到 11 秒一颗（60 秒局最多 3 颗）。它是四模式里最可能"难到不讲理"的一个。
4. **万能球在链上不可见**。落地定型之后它就是一颗普通色球，所以"我用了个万能球"这件事只存在于玩家的记忆里，没有留下痕迹。要不要给一次性的"转化"特效（定型瞬间的白闪），需要真人判断是否干扰读盘。

## 27. 双炮同向，以及一次完整的视觉重构

这一节只回答两个问题：为什么把两座炮口从"顶+底对射"改成"并列顶置"，以及
在不动玩法的前提下，画面是怎么一层层补上"这是台机器"的。

### 27.1 双炮必须同向

设计图给的做法是"第 3 关起复制旋转 180° 放底部"。真跑起来是另一回事：

- 上面那座朝下打，下面那座朝上打。玩家要**同时**维持两个"这个口朝哪"的模型，
  而这两个模型的方向是反的；
- 视线被劈成上下两半。链条绕一圈，玩家得在两个半场之间来回切；
- 更糟的是"下面那个口"离 HUD 底部（连消条、操作提示）只有几十像素，
  炮口和浮字、控制台挤在同一片区域，实战里经常糊成一团。

改成并列顶置之后，玩家只需要一个模型：**炮口朝下，转轮盘把目标送到炮口下**。
这是所有直线射击游戏的默认直觉，不需要教学。

代价是真实的，不遮掩：**落点间距从 N/2 格缩到 2k 格**（标准局 14 格 → 6 格）。
两个落点挨近之后，一次转盘要同时照顾两处，做不到就一起失手——数据上表现为
下四分位明显下压（见 27.3）。

### 27.2 k = floor(C / D)：让炮身正着

两座炮放在 `[N-k, k]`，`k = floor(C / D)`。取足 k 有两个作用：

1. 两座炮都还在**直道**上。直道的法向是垂直的，炮身才是正着的——只要偏出去
   一格，法向就开始倾斜，两门炮会变成"V"字，又回到"两个方向"。
2. 落点尽量拉开。k 已经是直道容量的上限，再想拉远就得上弯道。

这个数是算出来的，不是调出来的：`C / D = 6 / 1.755 = 3.42`，取 3，
两座炮距中心 ±5.27 世界单位，直道半长 6。

### 27.3 平衡实测：中位没动，下四分位塌了

40 局（两批种子各 20）合并分位：

| 模式 | p10 | p25 | p50 | p75 | p85 | 存活 |
|---|---|---|---|---|---|---|
| 标准（改前 p50≈13690） | 11355 | 12079 | **13721** | 17369 | 19229 | 38/40 |
| 小轮 | 5286 | 6123 | 6862 | 8791 | 8964 | 40/40 |
| 大轮 | 14087 | 16387 | 18245 | 19633 | 24079 | 40/40 |
| 三射口（未改） | 6672 | 8052 | 8862 | 10371 | 10915 | 40/40 |

标准局的中位数几乎没动（13690 → 13721），但 p25 从 13800 掉到 12079，
并且首次出现 2/40 爆仓。**"平均没变"不等于"没变"**——真正被改动的是分布的形状：
尾部变厚了，说明有两个落点相近时存在"一次转错、两处一起崩"的路径。
段位线因此整体下调（B/A/S 三档），SS 单独按 p80 落在 18500。

### 27.4 托盘：把"厚度"拆成四笔

上一版只有一道 0.12 的外圈描边，整台机器在暗底上读不出边界，像贴纸。
厚度不是一个渐变能解决的，它是**四笔不同性质的光**：

1. **落影**：纯黑、46 模糊、向下偏移 16 —— 它落在地面上，说明机器离地；
2. **外发光**：青色、50 模糊 —— 机器自己往四周散的光；
3. **受光上沿**：只画上半圈的一道亮线。整圈描亮会变成"发光的圈"，
   只有上沿亮才是"被照亮的边"；
4. **一排螺栓**：沿外沿等距 14 颗。等距的点是"这块板是人装上去的"最省字的一句话，
   顺手还把边框的曲率标了出来。

### 27.5 飞轮：让转动看得见

16 颗齿是旋转对称的——**转一格和没转一模一样**。上一版的齿轮其实一直在转，
但玩家看不见，因为整圈齿在任何相位下都长得一样。修法是一颗偏心的琥珀色相位标记：
转多少，一眼就能读出来。这一个点比给齿做任何倒角都值。

辐条也从"五根深色线"改成"五条挖空槽 + 槽上沿亮边"：线是涂黑，槽是镂空，
远看的差别是"甜甜圈"和"轮子"。

### 27.6 机芯：一根轴，不是一块屏

两只飞轮之间原本是纯黑。第一次补的是一块下沉面板 + 内发光横条，
结果它读成显示器——"暗底 + 内发光横条"就是屏幕的语汇。

机器的心不是屏，是**一根轴**：一根把两个飞轮连起来的传动轴，中间一个
会随节拍胀缩的轴承。细、暗、有结构，才不会被误读成 UI。
节拍环是全场唯一"从中心往外"的时间信号，余光能感到下一发快到了。

### 27.7 双炮挂架：三稿都错，结论是"不要连"

| 稿 | 画法 | 读成什么 |
|---|---|---|
| 1 | 细横梁挑两门炮 | 一副哑铃，还是个跨栏 |
| 2 | 400px 宽的整体机匣 | 一块窗台板，两头挂两个头，中间空得没道理 |
| 3 | 两块挂板 + 下垂软管 | 一根电线横跨空地，中间的指示灯像线上挂了颗珠子 |
| 4 | 两块挂板，不连 | 两台同型炮台，同向。够了 |

结论：**一件东西重复两次，本身就是一组**。要表达"同一台机器"，靠的是
同型、同姿态、同材质，不是硬加一根横梁把它们焊在一起。

### 27.8 ×2 光带：四稿，每次都是"多画一点就变成另一个东西"

| 稿 | 画法 | 读成什么 |
|---|---|---|
| 1 | 金色薄涂 | 轨道上一块来路不明的黄斑 |
| 2 | 暗底 + 金涂 | 一根实心芥末条，把珠子全压住 |
| 3 | 三道递减线 | 没有珠子盖着的地方露出两三根平行金线，像布了线 |
| 4 | 外沿一道 + 短端刻 | "这一段边上亮着"，长度即判定范围 |

关键约束是几何的：珠子半径是 **0.443 倍槽宽**，只有贴着外沿的 0.478 那一道
不会被珠子吃掉。所以"这段有多长"只能由最外那道线读，往里画多少都是浪费。

### 27.9 珠子的落影

上一版的珠子没有影子，整条链读起来像贴在跑道平面上的贴纸。补一层偏下
0.26r 的椭圆落影之后，同一颗珠子旁边的同色珠子也分开了——**影子同时解决了
"立体"和"分组"两件事**，这比给珠子加描边便宜得多。

方核（金）的受光也改了：上一版上方压 0.55 的纯白，读成"上面米色、下面金色"的按钮。
改成同色相提亮（琥珀色的光，不是白光），才像"同一块料被照亮"。

### 27.10 浮字分列

"×2 换位"撞"连消"、再撞"清空跑道"，上一版三行糊成一句。现在按 x 分列、
同列从下往上排，任意两条之间至少留一个行高。浮字可以飘，但不能叠。

### 27.11 遗留

1. **单射口/三射口没有挂板**。挂板只在"两门炮同向"时画，因为它是为并排这件事
   存在的；三射口仍然是三个方向，这是模式的定位（三分环），不是遗漏。
2. **托盘尺寸撞到上限**。`S = min(34, 300/(R+3.2), 790/(2(C+R)))` 里，
   横向约束在标准局是 39.5、纵向 41.7，真正卡住的是 34 这个硬上限——
   再大，炮口中心会吃掉顶部标题行。要更大就得改画布比例，不是改系数。
3. **色弱模式仍未实测**。红·星芒与万能·五角星都是星形，这一轮没动它们的剪影。

## 28. 补位改成恒速，×2 槽下线

这一节回答两件事：为什么珠子补位要从"指数衰减"改成"恒速"，以及
为什么把 ×2 得分槽整个拆掉，而不是调一调参数留着。

### 28.1 指数衰减 = 指定时间，只是看不出来

珠子被推挤时记一个 `dx`（"我视觉上还在旧位置"），渲染时画在 `slot + dx`。
上一版的衰减是一行：

```js
const decay = Math.exp(-dt * 26);
for (const b of this.slots) if (b) b.dx *= decay;
```

看起来像"每帧乘个系数"，实际上是一条**时间常数固定**的曲线：τ = 1/26 ≈ 0.038s，
不管位移多大，都在约 0.15 秒内衰减到 2% 以下。

问题出在**初速和位移成正比**：

| dx | 初速 | 到位时间 |
|---|---|---|
| 1 格 | 26 格/秒 | 0.15s |
| 6 格 | 156 格/秒 | 0.15s |

位移大的那颗是"嗖"一下飞过去的，位移小的那颗是"晃"过去的，**但它们同时停下**。
观众看到的是"一整列珠子啪一下全体归位"，中间没有"追"的过程。

### 28.2 恒速之后，位移决定时长

```js
const step = CFG.dxSpeed * dt;
b.dx = b.dx > 0 ? Math.max(0, b.dx - step) : Math.min(0, b.dx + step);
```

现在 dx 每秒固定减 `dxSpeed` 格：

| dx | 到位时间（dxSpeed = 11） |
|---|---|
| 1 格 | 0.09s（几乎无感） |
| 3 格 | 0.27s |
| 5 格 | 0.45s（看得见滑过去） |

一整列被推挤的珠子会**依次**归位：最前面那颗只挪一格，先停；后面那颗要挪五格，
继续追。这才是"追上去"该有的形状。

`dxSpeed` 先试了 7，5 格要 0.71s——滑是滑了，但珠子会长时间叠在邻居身上，
读起来像"珠子堆住了"而不是"珠子在追"。11 是"看得见但不过分"的那个点。

### 28.3 飞行时长也改成了速度

`flightTime: 0.80` 换成 `nozzleGap: 3.7` + `flightSpeed: 4.6`，时长由 `dist/speed`
推出来。现在两者等价（炮口到轨道间距恒定），但语义正过来了：以后拉长炮管、
或者改成斜射，速度不用重调。

同一次改动里把飞行曲线从"半线性 + 半 smoothstep"改成**纯线性**，并去掉了
那点横向弧线。理由不是不好看，是那条曲线让"球多快"没法用一个数说清——
你调的是时长，看到的却是变速（中段 1.5 倍速）。现在进度就是时间比例，
速度一个数管全程。

调试参数也跟着换了：`?ft=秒` → `?fs=速度`。

### 28.4 ×2 槽：一个自己承认过"不是策略"的机制

> **【范围修正】** 这里删的是**基础模式**的 ×2 槽。§33.5 的骰子镀金槽（0s ×2 / 20s +1 / 70s ×2）与 §34.6 的扑克筹码槽（55s / 80s）后来以不同判据回归；`Game.pads` / `padHits` 在现行代码里存在（§0.0.2），不要按"字段已连根拔"去读。

上一轮 REVIEW 里写过一句话：

> 这说明它现在是"偶得奖励"，不是"策略"。玩家没法主动规划——槽落在哪是随机的，
> 你只是恰好打中。

这一轮玩家直接问"这两个亮的长方形不知道啥意义"。**这是同一个判断，从两端说出来了**：
我这边是"它没形成决策"，玩家那边是"我看不懂它"。

一个机制如果需要玩家先读懂一个隐藏判定区（消除段的**中心弧长**是否落在槽里），
而回报又是纯数值翻倍，那它大概率只会被读成背景装饰。删掉比留着好。

删的时候是连根拔的，没留死代码：

- `CFG` 里 `padEvery / padHalf / padAvoid` 三行配置
- `Game` 的 `pads / padClock / padHits` 三个字段和 `rollPads()`
- `update()` 里的换位计时器、`resolve()` 里 12 行判定
- `render` 的 `pads()` 方法（约 85 行）和 `chassis()` 里的调用
- `main.js` 的 `padmove` 事件分支、`×2 双倍` 浮字、`?pads=0` 开关
- `rules.mjs` 里那条三连断言

`circDist` 也跟着删了——它只为槽判定存在，没有别的调用者。
**一个函数只有一种用途，那个用途没了，函数就该走。**

### 28.5 分数下移 20%，但难度没动

删掉 ×2 之后重跑 40 局（两批种子各 20）：

| 模式 | p10 | p25 | p50 | p75 | p85 | 爆仓 |
|---|---|---|---|---|---|---|
| 标准 | 8932 | 11028 | 12093 | 13903 | 14899 | 0/40 |
| 小轮 | 3891 | 4287 | 4798 | 5970 | 6699 | 0/40 |
| 大轮 | 13156 | 14072 | 15278 | 18455 | 19841 | 0/40 |
| 三射口 | 6046 | 6360 | 7238 | 8520 | 10081 | 0/40 |

标准局中位 13721 → 12093，降 12%；小轮降得更多。但**爆仓 0/40，和上一版一致**，
说明挪走的是分数，不是难度。段位线按分位重划，形状不变：

```
标准 [0, 8900, 11000, 12100, 14300]
小轮 [0, 3900, 4300, 4800, 6300]
大轮 [0, 13100, 14100, 15300, 18700]
三射口 [0, 6000, 6600, 7300, 8900]
```

**这是"绝对分数没有意义"的又一次证明**：同一个玩家、同一套操作，只因为删了一个
奖励源，他的历史最高分就从 S 掉到 B。如果段位线是硬编码的，这次改动会一次性
废掉所有人的记录。

### 28.6 遗留

1. **滑动中的珠子会和邻居短暂重叠**。恒速补位必然如此（位移不同步），
   只在 dx ≥ 3 时看得出来。要彻底消除得做"整列同步推进"，那就又回到"同时归位"了。
2. **飞行距离仍然是恒定的**3.7 世界单位。所以"速度制"目前和"时长制"等价，
   真正的好处要等到炮管变长或斜射时才会兑现。

## 29. 连消分档与消除驱动的奖励球

需求原话是两件事：「需要不同的连击效果」，以及「4 个球相连下一个水晶前插入
炸弹球，5 个球会出彩虹万能球」。

第二件事我先做了，然后实测发现它**触发不了**。这一节记的是从"照做"到
"改设计"的全过程，因为判断依据是数据，不是偏好。

### 29.1 实测：4 连在这个盘面上几乎不存在

第一版直接按原案实现：`run.len === 4` 给爆破球，`>= 5` 给万能球。
跑 40 局，结果 `rewards = 0`——**一颗都没发出去**。

拆开看，10 局标准模式的首段匹配长度分布：

```
3: 85 次
4: 0 次
5: 0 次
```

再看 5 局连打，85 次首段全是 3 连，一次 4 连也没有。大轮（40 格）10 局里
出现过 1 次 4 连，其余模式 0 次。

### 29.2 为什么：链条上不可能存在三颗相邻同色

这是几何决定的，不是概率偏低：

1. 链条上任何 3 颗相邻同色会**立即被消除**，所以稳态下链上不存在 "XXX"；
2. 因此落一颗球能形成的最大连续段，取决于落点两侧的同色数——左 2 右 1
   才凑得成 4 连，也就是必须恰好落在 `XX_X` 这种缝里；
3. 玩家还得先把这条缝转到炮口下。

第 2 条在 4 色盘面上的理论频率约 1/16，再乘上"缝正好在射程内"，实测就是
**每 10 局 1 次**。

顺带排除了一个错误结论：机器人打不出 4 连，不等于人类打不出。查了 `evalSlot`，
它对 4 连是识别的（l2+l1+r1 同色 = 152 分，对 3 连 140 分），只是**没有机会**。

### 29.3 改设计：双轨，而不是降低门槛

三条路都试过：

| 方案 | 结果 |
|---|---|
| 门槛降到 3 连 | 3 连是基础消除，每局 14 次，奖励泛滥 |
| 改成"一次结算总消 ≥8" | 标准局 0.13 次/局，比 5 连还稀有 |
| 改成按连消档位触发 | 每局 4 次，频率合适——**采用** |

最终是**两条路线并存，一次结算只发一颗，长度路线优先**：

| 触发 | 奖励 | 实测频率（标准局） |
|---|---|---|
| 首段 ≥ 5 连 | 万能球 | ~0（10 局 0 次） |
| 首段 ≥ 4 连 | 爆破球 | 0.1 次/局 |
| 跨入「凌厉」(combo 6) | 爆破球 | 3.25 次/局 |
| 跨入「爆发」(combo 12) | 万能球 | 1.25 次/局 |

长度路线保留，是因为它一旦出现就该重奖——玩家真把 4 颗拼到一起时，系统必须认账。
但**常规供给必须挂在玩家能主动追求的东西上**：

- 4 连是**结果**，玩家不能"决定"消 4 颗，只能希望；
- 连消是**动作**，玩家可以决定"这一下别断"。

### 29.4 随机炸弹归零，随机万能保留

两套供给会叠加。改之前随机炸弹 0.042 × 54 次补球 = 2.3 颗/局，
加上 4 连奖励 2.9 颗（当时的错误数据），合计 5.2 颗 × 5 格 = 26 格，
超过标准盘面 28 格的一半——**盘面会被炸到再也凑不出四连，机制把自己的触发条件吃掉**。

所以：

```
bombRate: 0            // 炸弹完全由消除挣来
wildRate: 0.030        // 万能仍需随机货源：5 连太稀有，不能当唯一来源
```

为什么炸弹可以完全断供而万能不行：炸弹是**手段**（清场），万能是**补洞**（续命）。
手段可以挣，补给断了就是断了。一局 4.7 颗万能会失去稀缺感，
降到 1.5（随机 1.3 + 档位 1.25）回到原来的量级。

### 29.5 连消五档

上一版 `combo === 3 || 6 || 10 || 15` 各播一次**同一个**浮字、同一个音效。
问题不是不好看，是**玩家读不出自己在爬坡**——10 连和 3 连的反馈长得一样。

| 档 | combo | 颜色 | 演出 |
|---|---|---|---|
| 起势 | 3 | 青 `#7FD8FF` | 浮字 + 单环 + 音高 1 音 |
| 凌厉 | 6 | 绿松 `#4CF0C0` | 双环 + 抖动；**给爆破球** |
| 爆发 | 12 | 金 `#FFD65A` | 三环 + 闪白；**给万能球** |
| 极限 | 17 | 橙 `#FF9A4D` | 全向粒子 + 中心横幅 |
| RUSH | 22 | 玫红 `#FF5C8A` | 屏幕边缘辉光 + 中心横幅 |

两个细节：

1. **跨档才播，不是每次消除都播**。combo 一次可能加 4 或 5，
   写成 `combo === 6` 会从 4 直接跳到 8、把第 6 那颗整段跳过——
   打得越猛反而越听不到里程碑。改成"当前档位 > 已播报档位"。
2. **低档位不放浮字**。底部控制台已经在显示"凌厉 · 连消 6"，
   两处同时出现就是重影（实测低档连跳时三行字会叠在轨道上）。
   档位信息交给控制台（持续可见），档位冲击交给冲击波和辉光，
   只有最高两档才在画面中心喊一句。

连消条也跟着改：11 格 × 每格 2 点 = 满格 22（正好是 RUSH 线），
整条按**当前档位**统一上色。上一版按格子位置配色（前三格蓝、中间金、末尾红），
那读的是"进度到哪了"，不是"我在第几档"。

### 29.6 奖励球插待发位，挤掉末尾预览

```
q.pop();        // 挤掉末尾那颗
q.unshift(ci);  // 奖励球成为下一发
```

为什么插最前面：奖励必须**下一发就能用**，否则 4 连和两拍后的某颗球之间
建立不了因果。

为什么必须挤掉一颗：队列定长 3 是有意义的（待发 + 两个预览 = 我能规划两步）。
变长会悄悄改掉节奏。挤掉末尾是**代价**，也是这个奖励唯一的分量——
你用一个已知信息换了一个强力球。

### 29.7 数据（两批种子各 20 局，共 40 局）

| 模式 | p10 | p25 | p50 | p75 | p85 | 爆仓 |
|---|---|---|---|---|---|---|
| 标准 | 10210 | 11293 | **13191** | 15142 | 15855 | 0/40 |
| 小轮 | 4027 | 5107 | 5703 | 6423 | 6970 | 0/40 |
| 大轮 | 14552 | 16411 | 18528 | 23110 | 25083 | 0/40 |
| 三射口 | 6439 | 7358 | 9122 | 10679 | 10916 | 1/40 |

标准局中位从 12093 涨到 13191（+9%），来源是炸弹从 2.3 颗涨到 3.05 颗。
爆仓率没变，说明涨的是"清场能力"，不是难度。

段位线按等分位重划（每档约 20%）：

```
标准 [0, 10900, 12400, 15000, 19000]
小轮 [0, 4750, 5460, 5990, 6900]
大轮 [0, 15800, 17700, 20400, 24100]
三射口 [0, 7050, 8400, 9750, 10800]
```

### 29.8 遗留

1. **档位奖励的「凌厉」可以反复触发**。combo 断一次重来，又能拿一颗炸弹。
   一局 3.25 颗是实测值，但如果玩家刻意维持低强度连消刷档，收益会高于拼高分。
   目前没做抑制，因为没观察到这个行为（机器人不会刻意刷）。
2. **5 连奖励实际上永远拿不到**。它现在更像一条"如果真发生，系统认账"的兜底规则，
   而不是玩家能规划的目标。要么接受它作为传说，要么等盘面机制改了再说。
3. **小轮模式的爆发档几乎不可达**（40 局只触发 3 次）。20 格盘面上连消很难堆到 12。
   如果小轮要公平，档位门槛应该按盘面大小缩放，但那样"同样的 12 连"在不同模式
   价值不同，玩家会更困惑。暂不处理。

## 30. 轮流发射，以及"反应时间"到底由谁决定

这一轮的需求只有两句：

> 多个发射口不应该一起出，应该是轮流出。
> 还有发射口和轮盘距离要远一点，需要些时间玩家可以反应来的及。

第一句改机制，第二句改几何。但它们最后动到的是同一件事：
**玩家在一颗球上能花多少注意力。**

### 30.1 齐射的真正问题不是"一次两颗"，是一颗也没看清

上一版每拍 `nextVolley()` 返回全组射口，两个口同帧出球、同帧落地。
当时的理由是"压力相等、节奏整齐"，但漏了一件事：

**两颗球共享同一个落点时刻。**

链条的相位只有一个自由度，所以两颗球其实绑死成一个事件——
玩家做一个决定，屏幕上却有两颗球要读。信息量翻倍，决策量不变，
多出来的那一半是纯噪声。三射口模式更糟：每拍两个口开火、一个口休息，
玩家还得先分辨"这拍是哪两个"。

### 30.2 轮流：`volleyIndex` 从"下一个休息的口"变成"下一个开火的口"

```
fire() {
  const idx = this.volleyIndex % n;
  this.volleyIndex = (idx + 1) % n;
  this.balls = [{ ci, off: this.nozzleOff[idx], idx, t: 0, dur }];
}
```

一次只有一颗。`nextVolley()` 也从"返回一组"缩成"返回一个"——
它的所有调用方（准星、预告环、机器人）都只是少了一层循环，
语义却从"这一拍打哪些落点"变成了"这一发打哪个落点"。

三射口模式的 `rotate` / `volley` 两个字段直接删了：轮流是全局规则，
不需要每个模式再声明一次"我这拍开几个口"。

### 30.3 beat 的语义变了：从"一拍"到"两颗之间的间隔"

这是最容易漏的一处。齐射取消后，`beat` 不再是"一拍的时长"，
而是"两颗球之间的间隔"——虽然数值上两者都叫 beat，但含义换了一层。

各模式的数值约等于原来的一半（原来一拍两颗）：

| 模式 | 旧 beat | 新 beat | 折算球/秒（旧→新） |
|---|---|---|---|
| 标准 | 3.40 → 2.05 | 2.20 → 1.45 | 0.59~0.98 → 0.45~0.69 |
| 小轮 | 2.50 → 1.50 | 2.50 → 1.55 | 0.40~0.67 → 0.40~0.65 |
| 大轮 | 3.80 → 2.20 | 2.45 → 1.50 | 0.53~0.91 → 0.41~0.67 |
| 三射口 | 3.90 → 2.60 | 2.05 → 1.50 | 0.51~0.77 → 0.49~0.67 |

总球数确实少了（标准 90 秒从约 58 颗降到约 53 颗）。这不是"变简单"，
是"每颗球都值得看"。以前 2.05 秒里出两颗、两颗同时落地，玩家只能赌；
现在 1.45 秒一颗，每一颗都能单独瞄准。

### 30.4 反应时间 = 距离 / 速度，所以两个数必须一起改

用户说"距离远一点、要给反应时间"。如果只拉远距离：

```
dur = gap / speed
```

速度不变，时长会跟着距离涨——但涨得很慢，因为屏幕就那么大。
如果只减速，炮口会贴在轮盘边上，画面局促。

所以这一版同时动两个：

```
nozzleGap    3.7 → 4.6      (+24%)
flightSpeed  4.6 → 3.5      (-24%)
dur          0.80 → 1.31s   (+64%)
```

`dur` 依然只由这两个数推出来，没有第三个"飞行时长"参数——
这条约束从上一版就立了：**调时长要调几何或速度，不许直接写秒数。**

### 30.5 画布预算：轮盘为什么缩了 11%、为什么下移 40px

炮口在轮盘上方，`stand` 每增加一格，纵向就要多吃一格。原来的预算式是：

```
S = min(34, 300/(R + 3.2), 790/(2(C+R)))
```

300 只算了炮口，漏了**挂板**。实测标准模式 S=34 时，挂板上沿在 y=21，
而标题行在 y=36——一直在压着标题，只是压得浅、没人细看。

这一版把预算改成三项相加：

```
S = min(34, 261/(R + nozzleGap), 790/(2(C+R)))
```

261 = 轮盘中心 440 − 挂板顶到炮口的 109px − 标题下留白 70px。

配套两件事：

1. **CY 从 400 下移到 440**。轮盘下移 40px，把上方让给炮台。
   屏幕上因此出现一条清楚的"上炮台 / 下轮盘"分界，
   比原来"轮盘垂直居中、炮口压标题"要稳。
2. **标准轮 S 从 34 降到 30.35**，珠子半径 28 → 25px（-11%）。
   这是拉远炮口必须付的钱：`nozzleGap` 从 3.2 涨到 4.6，
   纵向多吃 1.4 格，轮盘只能让出一部分。

代价写在明处：**珠子小了 11%，形状编码的余量变薄**。
星芒的六个尖、八面体的四个面在 25px 上仍然分得开（这一版截图逐个确认过），
但再往下到 22px 就不敢保证。这也是 `nozzleGap` 停在 4.6 而不是 5.2 的原因。

### 30.6 视觉：状态用"光"表达，不用"亮度"

这一轮在视觉上花的时间比机制多，因为轮流之后出现了一个新问题：
**没轮到的那门炮该长什么样。**

试了五个值，全部失败：

| dim | 结果 |
|---|---|
| 0.30 | 炮身消失，只剩挂板浮着，像"那门炮坏了" |
| 0.45 | 只剩一颗待发球悬在虚空里 |
| 0.70 | 轮廓勉强能看到，但读不出"这是炮" |
| 0.78 | 同上，只是亮一点 |
| 0.92 | 炮身完整，但和 active 几乎没差别 |

根因是炮身填充色 `#0A0F16` 本来就接近背景 `#05070C`。
**任何程度的 alpha 压缩都会先吃掉轮廓**——这是配色决定的下限，不是参数问题。

最后改了两件事：

1. 炮身配色整体提亮一档（`#3E4F67` → `#4C607C`），并用 0.92 的 alpha
   而不是更低的——剪影永远是完整的。
2. 状态改由光表达：轮到的那门炮，炮口有一团随充能呼吸的冷光；
   没轮到的没有光，只有炮口本身那一圈固定的椭圆环。

这条规则和 §30.6 的"状态用光表达，不用亮度"是同一条。
待命环（虚线）试过，会和炮口椭圆叠在一起，读成"炮口有污渍"，已删。

### 30.7 一个隐藏 bug：准星必须跟球，不能跟"下一发"

`volleyIndex` 在 `fire()` 里是**先取后进**：

```
const idx = this.volleyIndex % n;
this.volleyIndex = (idx + 1) % n;   // 开火瞬间就指向下一门
```

于是球刚出膛的那一帧，`nextVolley()` 已经指向另一门炮。
准星（reticle）原来直接读 `nextVolley()`，结果就是：
**球从左炮飞出去，准星却挂在右炮下面。**

玩家看到的是"球飞错了炮口"，比没有准星更糟。修法是让准星优先读飞行球：

```
const active = game.balls.length
  ? game.balls.map((b) => b.idx)
  : game.nextVolley();
```

这条 bug 只有真的截一帧飞行中段的画面才会暴露——
靠 `--virtual-time-budget` 撞帧撞不到（飞行只占 1.3/1.9 的时间），
所以顺手加了 `?hold=0.5`：强制出一颗球并钉在飞行进度的 50%。
**能被稳定复现的 bug，才谈得上被修好。**

### 30.8 数据（机器人 40 局，1/120 步长）

| 模式 | p10 | p25 | p50 | p75 | p85 | 均值 | 爆仓 |
|---|---|---|---|---|---|---|---|
| 标准 | 6417 | 7503 | **9248** | 11158 | 12343 | 9312 | 4/40 |
| 小轮 | 3480 | 4158 | **5113** | 5961 | 6612 | 5129 | 0/40 |
| 大轮 | 9347 | 11554 | **12885** | 13831 | 14626 | 12875 | 1/40 |
| 三射口 | 4609 | 5543 | **7264** | 9294 | 9999 | 7473 | 2/40 |

标准局中位 12093（齐射末版）→ 9248，降 24%。两个来源各占一半：
球少了 9%，以及"一次只能消一组"（两颗同落时能凑 4~5 长的段，现在基本锁在 3）。

段位线按 p25 / p50 / p75 / p85 各上移 5~12% 重划：

```
标准 [0, 8200, 10200, 11600, 13400]
小轮 [0, 4600, 5700, 6300, 7000]
大轮 [0, 11800, 12800, 13900, 15100]

```

其中大轮是特例：120 秒长局的分数分布比标准局窄得多（p50→p75 只差 7.3%），

但实际代码用的是 p25/p50/p75/p85 各上移一点，不是等分位。
那句话是当时的设计意图，没有落进代码，文档比代码乐观了一档。

### 30.9 遗留

1. **三射口的下方两炮离底部 HUD 很近**。`nozzleGap` 4.6 在上下各占 4.6 格，
   800px 画布刚好放得下，但下方炮身到提示行只剩 ~35px。
   要根治得给三射口单独的 gap（会更短、飞行更快），等于破坏"四模式同一手感"。
   暂不处理，先看上手感受。
2. **`beat` 的下限会吃掉末期节奏**。`beat` 不能短于 `dur + 0.08`，
   所以 `beatEnd` 小于 1.39 的模式（标准 1.45、大轮 1.50、三射口 1.50）
   实际都被这个下限托住，后半程的"越来越快"是平的。
   想再快只能缩短飞行，但那就把这一轮的目的抵掉了。
3. **两门炮的"待命"仍然不够明显**。0.92 的 alpha 差别在动态里靠光区分，
   静帧要盯着看才分得出。如果上手后玩家抱怨"不知道下一发从哪出"，
   下一步是给 active 炮加一条从炮口垂到轨道的细光线，而不是继续压暗待命炮。

## 31. 节奏：把"越打越快"从观感变成机制

这一轮的原始需求是一句话：

> 随分数增加，节奏要变快一些。节奏越快获得的分数越高，越难达成分数获得的越高。
> 标准是风险和收益成正比。

拆开是四条，其中三条互相咬合，剩下一条（风险）在旧版本里**根本不存在**：

1. 分数 ↑ → 节奏 ↑；
2. 节奏 ↑ → 分数 ↑；
3. 难度 ↑ → 分数 ↑；
4. 风险与收益成正比。

### 31.1 旧版本的三处硬伤

`beat` 以前只是时间的线性函数（90 秒内 2.20 → 1.45）。三处问题：

**（一）它是时间的函数，不是表现的函数。** 打得好和打得烂走同一条曲线，
节奏不携带任何信息。玩家看到数字变小，读不出"这是因为我打得好"。

**（二）1.45 秒已经贴着地板了。** 飞行 1.31 + 间隔 0.08 = 1.39，
只剩 0.06 秒余量。上一轮为了"让玩家看清"把飞行拉长到 1.31 秒，
同时就把节奏的上限锁死了——想更快，只有先缩短飞行。

**（三）"快"的收益是隐含的。** 唯一的回报是"单位时间发球更多"，
玩家完全看不见。没有倍率、没有读数、没有音效，等于没有这条机制。

### 31.2 两条曲线取 min，不是加权平均

```
beatTime  = lerp(beatStart, beatEnd,  time / rampSec)     // 时间地板
beatScore = lerp(beatStart, beatRush, (score / tempoRef)^0.85)  // 分数曲线
beat = max(beatRush, min(beatTime, beatScore))
```

为什么是 `min` 而不是平均：两条曲线各自守一种玩家。

- 打得差的玩家，分数曲线抬不动，只剩时间地板把他推到 `beatEnd`——
  他也能体验到机器在加速，只是上限低；
- 打得好的玩家早就把时间地板甩在后面，被自己的分数一路推到 `beatRush`。

平均会让两种人一起被拖到中间：差的觉得太快，好的觉得没劲。

`0.85` 次幂的理由：线性的话，前 20% 的分数只换来 20% 的加速。
而开局那一段最需要"我做的每件事都有反应"的即时回馈——先快一点抬起来，
后段再放缓，手感比严格线性好。

### 31.3 先还飞行的债，节奏才可能更快

`beat` 有硬地板 `flight + fireGap`，所以"让节奏更快"这件事**必须先动飞行**。
新规则：

```
flightDur = min(nozzleGap / flightSpeed, beat × flightRatio)   // flightRatio = 0.86
```

含义换了一层：飞行不再是"固定 1.31 秒的物理过程"，而是"一拍里占 86% 的一段"。
机器越快，球飞得越快。起手 1.31 秒（球能被读完），满速 0.88 秒（还能看清，但不容错）。

好处不只是"能更快"：

- `beat` 不再需要 `max(beat, flight + fireGap)` 这个事后夹逼。
  只要 `flightRatio < 1`，飞行永远装得进一拍——"空中最多一颗球"从
  「靠一个容易忘的 clamp 守住」变成「由几何保证」。
- 那 14% 的空档是有用的：它让"落地"和"下一发出膛"永远是两个可分辨的事件。
  实测最小空档 0.143 秒（rules 第 14 条断言守着它）。

代价：**反应窗口真的变短了**。满速下从"这颗球出膛"到"它落地"只有 0.88 秒。
这是这一轮唯一一个直接针对玩家手速的改动，也是"风险"的来源。

### 31.4 把"快"变成显式倍率

```
tempo = (beatStart - beat) / (beatStart - beatRush)   // 0..1
tempoMult = 1 + tempoGain × tempo                    // tempoGain = 0.45
```

`tempo` 用的是**实际节奏**而不是分数进度。理由：时间地板也在加速，
如果 `tempo` 只看分数，一个从不消球的玩家会看到机器越转越快、
倍率却一直是 1.00——那是在骗他。

`tempoMult` 乘在**每一次消除**上（含爆破和清空跑道）。所以"快"是双重收益：
发球率 ↑（1/1.02 vs 1/2.20 = 2.16 倍）× 单次价值 ↑（1.45 倍）。
理论峰值 3.1 倍，实测从开局到满速的得分率增长约 1.7 倍
（因为起手盘面更密，清除率高，把差距抵消了一部分）。

### 31.5 长消除重新定价

`BASE_SCORE` 从 `3→300 / 4→500 / 5→800+400n` 改成 `3→300 / 4→700 / 5→1500+700n`。

这不是平衡改动，是**叙事改动**：4 连在 4 色盘面上的实测频率是
"10 局出 1 次"，它出现时应该被记住，而不是只比三消多 200 分。
真正撑起分数的仍然是连锁倍率和连消倍率——那两条是玩家能主动追的，
4 连是撞上的。

### 31.6 这个正反馈为什么不会跑飞

分数 ↑ → 节奏 ↑ → 发球率 ↑ → 分数 ↑，这是正反馈。它不会失控，因为：

1. **有界。** 满速封顶（`beatRush`），倍率封顶（1.45）。
2. **自我惩罚。** 加速会把盘面压力一起抬起来：球来得快，清除跟不上就爆仓，
   收益直接归零。玩家能撑多快，就只能赚到多快——这就是"风险与收益成正比"
   在机制层的落点。
3. **单调。** `beatTime` 和 `beatScore` 都只减不增，所以 `beat` 单调不增。
   这条由一个断言守着（rules 第 12 条），因为抖动往往只有 0.02 秒，
   肉眼看不见，但玩家会觉得"机器突然卡了一下"。

副作用有两个，都写在这里：

- **分数后置。** 标准局前 20 秒只产出约 400 分，最后 30 秒产出一半以上。
  段位在局内会长时间停在 C，直到最后 20 秒才跳。这是设计的必然结果
  （节奏越到后面越值钱），不是 bug。
- **方差变大。** 运气好的一局会滚雪球，运气差的滚不起来。
  机器人 40 局的 p10→p90 跨度从 1.9 倍拉到 2.6 倍。

### 31.7 读得出来才算数：HUD 与音频

**HUD。** 左侧那块 `BEAT 1.45s` 换成了 TEMPO 读数：倍率（大）、拍长（小）、
进度条（带两个刻度）。上一版那个数字是**结果**，不是**理由**——
玩家看到它在变小，但不知道这跟他打得好不好有关。倍率直接出现在每一次得分里，
所以它是这一块唯一真正驱动决策的信息。

**里程碑。** 三档（提速 0.34 / 过载 0.68 / 红线 1.00）各播一次浮字 + 冲击波 + 音效。
位置在左侧读表盘下方，不放画面中心：它不是"这一下赚了多少"，
而是"机器状态变了"，属于仪表盘语义。中心横幅留给段位和最高两档连消。

**音乐。** BPM 96 → 142，随 `tempo` 连续变化。没有这一下，HUD 上写着 ×1.45、
耳朵听到的还是同一首歌，"机器变快了"就只是仪表盘上的一个数字。
**节奏感首先是听出来的**——人耳对周期性的敏感度远高于对数值的敏感度。
选 BPM 而不是升 key：升 key 会让同一段旋律听起来"变了首歌"，
改拍速只是"同一首歌唱得更急"，游戏里的加速要的是后者。

**结算页。** 新增"满速 X%"——这一局有多少比例的时间跑在满速。
它比"最高连消"更贴近整局的手感：连消是爆发，满速是奔跑状态。

### 31.8 校准：段位线不该取机器人的分位

这是这一轮方法上最大的一处改动。

以前的做法是"机器人跑 40 局 → 取分位 → 再加一点当段位线"。问题是：
**机器人是完美感知，它的分数分布顶端很窄**（标准局 p10→p90 只有 1.6 倍，
而且一半的方差来自运气）。用它定义段位，等于用一个人的运气分布
去给所有人排名。

现在改成 **技能阶梯**：把"感知预算"作为技能变量。
一颗球只分到**一拍**的注意力，扫一个候选槽约 `scan` 秒，
于是一拍里能评估的候选数 = `beat / scan`：

| scan | 代表 | 起手能扫 | 满速能扫 |
|---|---|---|---|
| 0.35 | 新手 | 6 槽 | 3 槽 |
| 0.22 | 普通 | 10 槽 | 5 槽 |
| 0.12 | 熟练 | 18 槽 | 8 槽 |
| 0.07 | 高手 | 31 槽（全环） | 15 槽 |
| 0 | 完美 | 全环 | 全环 |

这条约束**随节奏自动收紧**，不需要额外接线——这正是它可信的原因：
节奏越快 → 能看的候选越少 → 落点越差 → 越容易崩。
它也是唯一一条能同时解释"分数下降"和"爆仓率上升"的模型。

两版失败的人类模型记录在 REVIEW §21.3，这里只留结论：
**这个游戏的瞄准是连续可达的**（vMax 13 格/秒 × 一拍 > 半个环），
所以限制玩家的不是手，是眼睛。

### 31.9 数据（24 局/档，标准模式）

| 档位 | p50 | 爆仓率 | 满速局 | 末盘占用 |
|---|---|---|---|---|
| 新手 | 9905 | **50%** | 42% | 28/28 |
| 普通 | 12967 | 33% | 58% | 19/28 |
| 熟练 | 17485 | 13% | 88% | 15/28 |
| 高手 | 16738 | 4% | 88% | 14/28 |
| 完美 | 18939 | **0%** | 100% | 6/28 |

爆仓率 50% → 0%、末盘占用 28 → 6，两条都随技能单调下降。
这就是"风险和收益成正比"的可执行定义：**分越高的人，越不容易崩。**

段位线因此按技能档位的中位数取，而不是分位：

```
标准 [0, 12000, 15500, 18000, 21000]
小轮 [0, 6800, 8200, 9400, 10800]
大轮 [0, 14000, 19000, 23000, 28000]
三射口 [0, 12000, 14000, 16000, 19000]
```

### 31.10 `tempoRef` 必须和段位线解耦

第一版偷懒，让 `tempoRef = tiers[3]`（S 线），理由是"S 段 = 满速"读起来很漂亮。
结果一重划段位线，整条节奏曲线跟着变——那是两个不该耦合的东西：

- 段位线回答"这局值多少名"；
- `tempoRef` 回答"机器什么时候满速"。

现在每个模式显式写 `tempoRef`，取值是"好手在 2/3 局时能到的分数"，
于是满速总落在进度的 65~80% 上，跟段位线怎么划无关。

### 31.11 遗留

1. **顶端分位太挤。** 满速之后所有人的得分率都被同一组上限（1.02 秒 × 1.45 倍）
   压在同一个量级，S→SS 的间距只有 10% 左右，而单局方差是 ±40%。
   结果是一局的段位有很大运气成分。要拉开顶端，只能让满速之后还有东西可涨
   （更高的倍率上限、更长窗口的连消），那是下一轮的事。当前靠"保留最佳成绩"缓解。
2. **小轮模式 20 局没有一次爆仓。** 20 格 + 三色起手对"普通"玩家太宽松，
   风险曲线在这一档几乎是平的。要么给它单独的五彩难度，要么承认它是练习场。
3. **三射口的技能阶梯出现了反常**：熟练（12456）打不过普通（13449）。
   25 局样本还不足以下结论，可能是三落点换位的成本在中段水平上更明显。
   留待下一轮复查。
4. **色弱模式仍未真人验证**（连续五轮）。

## 32. 落空补位：珠子要"走"过去，不能"跳"过去

> **【第十三轮修正 · 现行】** 球落到轨道上的 k 格后，**球自己**滑到离它最近的球
> **旁边的空槽**里，与那颗球相切——移动的是球，链上的球一颗都不动。
> 前后各扫到第一颗球，近者胜；相等时优先右边（+1 顺时针，屏幕右侧那颗）。
> 落点 k 就在链边（最近球只差 1 格）时无需滑行；空盘时留在 k。
> 三消判定不在落地帧，而在 `dx` 归零、球真正贴上链的那一刻（见 §41）。
> 第十三轮前 `snap()` 返回的是最近球**占用的槽**，于是 `dropAt` 走插入分支
> 把别人的球推开——玩家反馈"变成其它球让位置"，已改为返回旁边的空槽。

需求原话：

> 球到轨道时候离末尾球有距离的时候移动速度过快。

### 32.1 先量了一下"有距离"到底有多远

写了个探针跑 6 局标准模式，记录每次落球时**球落点 k** 与**实际插入槽 target** 的偏差：

| 偏差（格） | 次数 |
|---|---|
| 0（打中链条） | 174 |
| 1 | 119 |
| 2~3 | 23 |
| 4~5 | 16 |
| 6~11 | 25 |

非零的 183 次里，超过 4 格的有 41 次（22%）。成因清楚：链条很短
（机器人打到后半程盘面只剩 1~7 颗）时，链条只占环的一小段，
而落点是固定的——球经常落在空弧上，`snap()` 把它吸到最近的珠子旁边。

### 32.2 问题不在速度，在于"没有过程"

上一版 `dropAt` 里，新珠子是 `makeBead()` 出来的，`dx = 0`。
也就是说：球垂直落在 k，珠子**瞬间出现在 target**。差 6 格时，
这 6 格是零帧完成的。

玩家看到的是"球落在空处，珠子凭空在另一边冒出来"。
把这件事描述成"移动速度过快"是很自然的——无限快的移动，读起来就是瞬移。

所以修法不是调 `dxSpeed`（那个值早就被证明过：11 太快、7 会让整列珠子
叠在邻居身上），而是**把这段位移补上、让它真的发生**：

```js
const drift = mod(target - k + N / 2, N) - N / 2;   // 带符号的最短路径
bead.dx = -drift;                                    // 视觉位置落在落点上
```

### 32.3 两档速度，因为这是两种动作

原来的 `dxSpeed = 11` 只管一件事：插入时整列珠子各让一格（`dx = ±1`）。
那个必须快——慢了整列珠子会长时间叠在邻居身上，读起来像"珠子堆住了"。

落空补位是另一回事：一颗珠子要从落点走到链条，位移 2~11 格。
用同一个 11 格/秒，6 格只要 0.55 秒，眼睛根本跟不上。

```
|dx| ≤ 1   → 11 格/秒   （插入让位）
|dx| > 1   → 4.6 格/秒  （落空补位），且总时长不超过 1.5 秒
```

速度值记在珠子自己身上（`dv`），不是每帧按当前距离现算。
现算会退化成指数衰减：`sp = |dx| / 1.5` 在 |dx| 大时是比例衰减，
尾巴拖不完（实测 12 格的收拢要 2.3 秒，而恒速只要 1.5 秒）。

副作用：`makeBead` 里那个从来没人读的 `pop: 0` 字段被换成了 `dv`。

### 32.4 数值

| 偏差 | 时长 | 观感 |
|---|---|---|
| 1 格 | 0.09s | 插入让位，几乎无感 |
| 2 格 | 0.43s | 看得见挪了一下 |
| 4 格 | 0.87s | 明显在滑 |
| 6 格 | 1.30s | 能数出它在走 |
| 11 格 | 1.50s（封顶） | 最远的极端情况 |

封顶 1.5 秒是会跨拍的（满速拍长 1.02s），也就是极端情况下空中会出现
"两颗珠子同时在滑"。这个代价是主动接受的：链条只剩两三颗时，
落点差 11 格本来就是罕见状态（2/357），而按 4.6 格/秒硬滑要 2.4 秒，
那才会真的和下一颗球打架。

### 32.5 一条新断言

`rules` 第 6b 条：跑 60 秒，检查每次 `insert`/`lone` 事件的 `s`
（视觉位置）是否**精确等于** `dropSlot` 换算出来的位置。

这条守的不是数值，是"那一步有没有补上"。少了它，以后谁把
`bead.dx = -drift` 那行删掉，游戏照样跑、测试照样过，
只有玩家会觉得"珠子怎么突然就到了"。

同时加了反向条件：样本里必须**存在**偏差 > 3 格的落球，
否则这条断言等于没验。

## 33. 骰子模式：把「颜色」换成「点数」，和两个静默失效的规则

> 注：本节的第二喷头与「双响同点」已在 §36 回退中移除；骰子规则族本身保留。

需求原话：

> 1、再添加模式，喷出来的改成骰子

附一整份设计稿：色点双辨识、双通道消除计分（豹子 / 顺子）、+1 翻面槽、
四种特殊骰、连消续时、4~5 关的节奏衔接。

这一节只写**设计稿落到代码时被迫做的判断**，以及两个"看起来完全正常、
实际上规则从未生效"的 bug。后者是本轮最有价值的部分：它们不报错、不崩、
画面和数字都在动，只有把设计稿的数值写成断言才看得见。

### 33.1 为什么是「规则族」，不是「第六种球」

基础模式的匹配键是**同色 ≥3**，骰子是**同点 ≥3 / 连续顺子**。差别不只是
"换成另一个维度"，而是 `findMatch` 的返回值结构都变了：骰子要带
`kind / sum / value / jackpot` 才能计价。

这套规则要在五个地方同时成立：

```
sim.findMatch      判定哪些珠子该消
sim.chooseWildColor 金骰定型成哪一点
bot.evalSlot       机器人怎么评估落点
render.ballBody    这颗珠子画成什么
rules.mjs          设计稿的数字对不对
```

分散实现的第一种死法不是算法写错，是**两处对顺子的定义差一个等号**——
画面上表现为"明明看着是顺子却不消"，而查起来要在五个文件之间来回对。

所以加一个模块级的规则族开关：

```js
let RULES = 'color';                       // 'color' | 'dice'
export function setRules(r) { RULES = r === 'dice' ? 'dice' : 'color'; }
```

`ballSkin / isColor / findMatch / evalSlot` 全部按它分派。
**加一个模式不改管线，只换语言。** 这也是后来能在一个下午里
把第 5 个模式接上去的原因：没有一处 if 是在"渲染层"或者"音效层"里判模式的。

编码表（不新增队列字段）：

| ci | 含义 | 备注 |
|---|---|---|
| `0..5` | 普通骰，1~6 点 | `pip = ci + 1` |
| `20..25` | 翻面骰，1~6 点 | `pip = ci % 20 + 1` |
| `10` | 万能金骰 | 落地定型成最优点数 |
| `11` | 爆破红骰 | 落地即炸，不插入 |
| `12` | 空白铅骰 | 复用 RUST，无点、不参与匹配 |

翻面骰**用 20+pip 编码，而不是给珠子加一个 `flip` 标志**。理由是项目里
`queues / balls / events` 全都只传一个整数，加字段就得在四处同步复制——
任何一处漏了，翻面骰会在那个环节悄悄变回普通骰，而且只在特定路径下出现。
20 段和 0..5 段用 `ci % 20 + 1` 就能统一成点数，代价只有一处取模。

### 33.2 计分：顺子比豹子贵，六连顺必须是固定值

| 牌型 | 公式 | 例 |
|---|---|---|
| 豹子（≥3 同点） | 点数和 × 40 | 4-4-4 = 480 |
| └ 6-6-6 | 上式 × 1.5（JACKPOT） | 720 → **1080** |
| 小顺子（3 连） | 点数和 × 50 | 1-2-3 = 300 |
| 大顺子（4~5 连） | 点数和 × 90 | 1-2-3-4 = 900 |
| 六连顺（6 连） | 上式 **+5000** | 1-2-3-4-5-6 = **6890** |

两处取舍：

1. **顺子单价（50/90）高于豹子（40）**。不是因为顺子更难"摆出来"，
   而是因为它更难**故意**做出来：豹子只要把同点凑到一起，顺子还要求
   方向一致（1-2-3 和 3-2-1 都算，1-2-2-3 不算），而盘面是随机装填的。
2. **六连顺是固定 +5000，不是把单价再翻一倍**。按倍率算它只有 3400 上下，
   和一次大豹子（6-6-6 已经是 1080）拉不开数量级。固定值才能让
   "我遇到过一次"变成可以复述的事。这是这条规则存在的全部理由。

**冲突时取「最值钱」而不是「最长」**：

```
1 1 1 1 4 5 6   →   4 连豹子 = 4×1×40 = 160
                    3 连顺 4-5-6 = 15×50 = 750   ← 选它
```

按长度挑会选那 4 颗，按价值挑才选这 3 颗。玩家看到的是盘面，心里算的是收益；
让他得到更多分的那一种，才是"系统更聪明"的那一种。

连消与续时（设计稿原案，未改）：

| chain | 倍率 | 续时 |
|---|---|---|
| 1 | ×1 | — |
| 2 | ×2 | +2.5s |
| 3 | ×4 | +4s |
| 4 | ×8 | +6s |
| 5+ | ×12 | +8s（全局封顶 +24s） |

封顶不是为了平衡，是为了让"这局还剩多久"算得出来——无限续时会让
HUD 上的倒计时变成一句谎话。

续时这张表第一版整个比设计稿低了一档（2.5s 挂在 chain 3 上），
实测一局只续 3.0 秒。按设计稿对齐之后是 5.0 秒/局——仍然不多，
原因是**结构性**的：骰子模式的连锁本来就短（平均最长连锁 2.0），
牌型要求 ≥3 颗，一次消除很难顺带把下一段牌型也摆好。
这条机制在骰子模式里是"偶尔的甜头"，不是主要时长来源。

### 33.3 静默失效之一：算出来的分数没有写回去

`findPattern` 用 `patternValue` 挑出最值钱的那段，但最初只把分数用来比较：

```js
const take = (start, len, kind, sum, jackpot) => {
  const p = { start, len, kind, sum, jackpot };
  const v = patternValue(p);        // ← 只用来比大小
  if (v > bestV) { bestV = v; best = p; }   // ← p 里没有 value
};
```

而 `resolve` 读的是 `run.value`：

```js
const base = (run.value || BASE_SCORE(run.len)) + rustN * 200;
```

`run.value` 恒为 `undefined`，于是整张骰子计分表**从来没生效过**，
一直在用基础模式的 `BASE_SCORE(len)`（3 颗 300 / 4 颗 700）。
6-6-6 的 1080 不存在，六连顺的 6890 不存在。

这个 bug 的形态很有代表性：

| 维度 | 表现 |
|---|---|
| 报错 | 没有。`undefined || 300` 是一个合法表达式 |
| 崩溃 | 没有 |
| 画面 | 分数照涨、浮字照弹（浮字读的是另一条路径） |
| 数据 | 段位线、平衡表、技能阶梯全部基于错的分数测的 |

发现方式是**写断言时看输出**：原本只想核对"豹子 = 480"，
断言打出来的是 300。第一个反应是"断言写错了"，第二个反应才是"等等，
`BASE_SCORE(3)` 正好是 300"。

教训写进注释里了：**凡是"计算只用于排序"的代码，必须有一条断言去读
最终产物，而不是读那个中间变量。** 中间变量是对的（`patternValue` 本身
单测永远绿），产物是错的，两者之间只差一行赋值。

修复后的连锁反应：平均分从 40134 回到 50936，全部段位线重划（见 33.8）。

### 33.4 静默失效之二：在「合拢前」的盘面上做穷举

翻面骰的设计是"被消除时把左右邻骰翻成同一点数"。选哪一点？
设计意图是**翻成最值钱的**，所以穷举 1..6，每次跑一遍 `findPattern` 取最优。

问题在于调用时机：`flipNeighbors` 必须在**清除之后、合拢之前**调用
（先合拢的话，左右邻的邻居关系已经变了，翻出来的点数对不上）。
但"左右邻合拢之后才会相邻"——在翻的那一刻，它们之间还隔着被清掉的 3 格。

于是每一次穷举扫的都是**带洞的盘面**：

```
盘面：6 [1] × × × [6] 6      ← × 是刚被清掉的三格
      ↑L           ↑R
findPattern 看到的：6 1 _ _ _ 6 6   →  没有牌型
六个候选点数全部 0 分  →  bestPip 恒等于 1
```

"替你翻成最值钱的那一点"实际永远翻成 1 点。同样不报错、不崩，
浮字照样弹"翻面"，只是这条规则等于不存在。

修法是**在副本上复刻一次 compact**，让穷举看到"翻完并合拢"的样子：

```js
const probe = this.slots.slice();
// 复刻 compact 的位移（只搬清除段后面那段连续珠链）
```

之后同一局面（`6 1 [3][3][3] 6 6`）会翻成 6，并直接接上 6-6-6 的连锁。

两个 bug 的共同点值得单独提一句：**它们的验证成本都在"写一条能读出
最终数值的断言"上，而不在"读代码"上。** 读代码时 `p.value` 那一行
看起来完全正常——它确实算了，只是没存。

### 33.5 主动槽：状态必须写在骰子脸上

上一版的 ×2 槽判据是"消除段的中心弧长落在槽的半长区间内"（REVIEW §18.4）。
它死于一件事：玩家读不出来。要理解它，你得知道"消除段"是什么、
"中心弧长"怎么算——那是一份要读代码才能用的说明书。

这一版换了判据，也换了回报的形态：

| 槽 | 判据 | 回报 | 玩家看到什么 |
|---|---|---|---|
| +1 翻面 | 这颗骰子落在这一格 | 点数 +1（6 → 1 循环） | 那颗骰子当着他的面翻了一次 |
| ×2 镀金 | 同上 | 这颗骰子镀金，消除时整段 ×2 | 右上角一道金折角 + 外圈金环 |

关键不是"判定更简单"，而是**因果落在玩家正在盯着的那颗骰子上**。
他不需要读规则，他只需要看到自己那颗 5 点变成了 6 点。

两个实现细节：

- `+1` 对翻面骰要保留翻面身份：`ci = isFlipDie(ci) ? 20 + np - 1 : np - 1`。
  少了这个三元式，翻面骰经过一次 +1 就退化成普通骰——一条只在
  "特殊骰正好落在特殊槽上"时出现的路径。
- `×2` 按**整段**翻倍，不按颗。因为顺子是整体计价的，拆不出"这一颗值多少"；
  而"整段翻倍"恰好是玩家能预期的规则：把金骰塞进一次大消除才有意义。

槽位是在构造时按 0 号射口算死的（`slot = nozzleOff[0] + rel`），
渲染时按 `(slot + phase)` 画——于是它**随轮鼓转**，玩家能把某一格
主动转到炮口下。这是"槽"和"固定装饰"的分界线。

位置也刻意避开 `rel = 0`：落在炮口正下方本来就该是为消除服务的，
如果那儿正好是镀金槽，每颗球都会镀金，"选择"就消失了。

### 33.6 装填即设计：为什么发牌要"贴心"

骰子模式最初是均匀发 1~6。实测（探针跑了 12 局、约 700 次开火）发现：

```
开火时"全环最优落点"的收益分布
  0 分（整条环无解）  4 次
  36 分（只能凑对子） 5 次
  312 分（能成 3 连） 17 次
  346 分（能成 4 连） 5 次
```

按球数算是 **29% 的球在整条环上都找不到任何能成牌型的落点**。
玩家体验到的是"连续三发都不知道该往哪打"，然后被塞三颗铅骰。
那种挫败感和"我没想清楚"无关，纯粹是抽签。

改成**按"这一点现在有没有用"加权发牌**（74% 智能 / 26% 均匀）：

```js
w[v] = max(4, 全环最优 evalPlacement(v) - 4)
```

可消率 29% → 32%，实测"可打点占比"22%（基础模式 51%~60%）。
保留 26% 的均匀抽样是刻意的：全按最优发牌，玩家会发现"每颗球都有解"，
于是不再预判，只做反应——那是另一种无聊。

### 33.7 4~5 关压成一条 110 秒曲线

设计稿写了 4~5 个关卡（第 1 关单喷头仅 1-4 点、第 2 关全点数 + 特殊骰、
第 3 关双喷头 + 双响同点、第 4~5 关两个 ×2 槽）。项目的结构是
"模式 + 时间阶段"，真做成 5 关会让段位线 / 记录 / 标题卡全部乘 5 份。

压成一条曲线：

| 时刻 | 开放 |
|---|---|
| 0s | 单喷头 · 仅 1~4 点 · ×2 镀金槽 |
| 20s | 1~6 点全开 · 三种特殊骰 · 铅骰规则 · +1 翻面槽 |
| 44s | 第二喷头上线 · 每 14 秒一次「双响同点」 |
| 70s | 第二个 ×2 槽 |

前 20 秒只有 1~4 点不是"简单版"：4 个点数时相邻点数的概率是 6 个点数时的
2.25 倍，顺子反而更容易成型。所以那一段是"教学 + 爽"，不是"热身"。

**开局是手工摆的，不是随机生成的。** 设计稿的原话是"开局预设 1-2-4-4-3，
让玩家 10 秒内体验先消豹子再合拢出顺子"。这句话藏着一条很硬的约束：
两段之间必须由 **compact（合拢）** 自动完成，不能靠第二枪——

```
开局：... 1 2 [4] 4 3 4 1 ...      第一发锁定 4 点
打一枪：4-4-4 豹子 → 清掉三格 → 合拢
合拢后：... 1 2 3 4 ...            ← 1-2-3-4 大顺子，自动发生
```

一枪两段，第二段是送的。这是那条曲线能从头教起的原因：
玩家不需要先学会转盘，就能看到"消除会让盘面重新排列"。

### 33.8 骰子怎么画：这是编码问题，不是美术问题

23px 的珠子上画不出六个面。所以骰子是 **2.5D**：正面恒为同一面，
用三点撑立体（顶部提亮 / 底部压暗 / 右下投影），翻滚用 `|cos(πk)|` 压扁——
抓的是"翻滚的剪影"，不是真的转过去。

编码上做了一个和基础模式**相反**的决定：

| | 第一编码 | 第二编码 |
|---|---|---|
| 基础模式 | 形状（剪影） | 颜色 |
| 骰子模式 | **点数** | 色相 |

骰子本来就是方的，剪影没有信息量；而点数比色相更抗色弱、更抗高速模糊，
并且在 15px 下仍然数得出来。色相退化成加速读盘的线索（1 红 2 橙 3 金
4 青 5 蓝 6 紫），不承担辨识。

四个视觉误读，全部是靠截图发现的（无头 Chrome，`?ff=&pause=1`）：

| 症状 | 真因 | 修法 |
|---|---|---|
| 读成"糖果色瓷砖" | 亮面铺满上半面 | 尺寸 0.84 + 窄亮带（0.18 处已是本色） |
| 1 点读成 2 点 | 点带右下偏移阴影，阴影自己成了第二个圆 | 改成填充 + 描边，不做投影 |
| 镀金的 `×2` 字压在点数上 | 角标的位置正好是 5/6 点的点位 | 换成右上金折角 + 外圈金环（在 0.62a 之外） |
| 未开放的槽像个黑洞 | 填了 `rgba(120,150,190,0.05)` 底，叠上 `globalAlpha` 后变深 | 未启用只画虚线框，不填底 |

第三条要写成纪律：**数点游戏的图形里，任何多余的圆都是 bug。**
第四条同理——半透明底在某些合成路径下不是"更淡"，而是"更黑"。


这是**双峰**分布：3 局掉在 40k 以下（整局没摸到一次大牌型），其余挤在
50~60k，中间 40k~50k 一个样本都没有。所以段位线按簇划而不是等距划：

```

```

| 项 | 每局 |
|---|---|
| 出球 | 84 |

32 格是为了让六连顺"真的可能"才选的，但实测 12 局的最长顺子全是 4。
那个 +5000 的 JACKPOT 目前是**存在但不可达**的规则——
要么放宽牌池（比如允许 1~6 点之外的点数循环），要么接受它是一张彩票。

段位线这一轮**测了两次都是废的**，两次都是"仪器坏了"而不是"游戏坏了"：

1. 第一次：计分表没生效（33.3），测出来的分数是错的。
2. 第二次：`tempoRef = 32000` 在一局里根本到不了——机器人跑到 246 秒

   改成 26000 后满速落在 76 秒（69%），和其他模式"65~75% 进程满速"对齐。

第二条尤其值得记：修好计分后平均分**反而降低了 20%**（50463 → 40134）。
"修了 bug 分数应该涨"是错的直觉——分数同时依赖计分表和节奏倍率，
而后者是一个独立的、也会失效的东西。

## 34. 扑克模式：把「点数」拆成「花色 + 点数」

> 注：本节的第二喷头已在 §36 回退中移除；底牌槽、筹码槽、狂热与牌型规则保留。

需求原话：

> 2、再添加模式，喷出来的改成扑克牌，按扑克牌的规则

设计稿给了整份规则：20 张精简牌池（10/J/Q/K/A × 四花）、同花 / 三条 /
顺子 / 同花顺、底牌暂存槽、筹码倍槽、四种特殊牌（小丑、爆破王牌、染花牌、
背面暗牌）。这一节只写**落到代码时被迫做的判断**，以及实测之后不得不
改的三处平衡。

### 34.1 为什么又是「规则族」，而且编码从 30 起

扑克的匹配键有两个维度（花色 + 点数），`findMatch` 的返回值又比骰子多
一层——它要说明"这一段是同花、三条、顺子还是同花顺"。所以沿用骰子的
规则族开关，再加一个 `poker.js`：

```
sim.findMatch      判定哪些牌该消
sim.chooseWildColor 小丑不在落地定型（和骰子相反）
bot.evalSlot       机器人怎么评估落点
render.cardBody    这张牌画成什么
rules.mjs          设计稿的数字对不对
```

编码表：

| ci | 含义 |
|---|---|
| `30..49` | 普通牌 = 30 + rank×4 + suit（rank 0..4 = 10/J/Q/K/A） |
| `60..79` | 染花牌，牌面同上，消除时把左右邻改成同花 |
| `10` | 小丑牌（任意花色 + 任意点数，**落地不定型**） |
| `11` | 爆破王牌（按 A 参与牌型，消除时炸左右各一张） |
| `12` | 背面暗牌（无花无点，不参与牌型） |

为什么普通牌不从 0 起：0..19 会和 `10/11/12` 三个特殊 ci 撞车。
把 20 张牌放到 30 段，`ci === BOMB` 这类判断天然不会误命中；代价只有
`ci - CARD_BASE` 一处减法。染花牌用 `60 + 牌面`，而不是给珠子加
`shift` 标志——队列 / 事件只传整数，加字段就得在四处同步。

### 34.2 牌型：顺序是规则，不是集合

设计稿的原话是"连续 ≥3 张相邻点数 10 - J - Q"。这里的"连续"是
**链上顺序**，不是"点数集合连续"。实现 `handOfWindow` 时第一版犯了
一个很典型的错：

```
盘面：10♥ A♦ K♠ Q♣ J♥
rank 集合：0,4,3,2,1 —— 恰好是 10..A 的全集
第一版：判成 5 连顺（2500）
```

玩家看到的是 10-A-K-Q-J，根本不是顺子。修正后的判据是：
非小丑位必须落在同一条等差线上（递增或递减），小丑填空位；
`10-A-K-Q-J` 两个方向都失败。

计分表（设计稿给的数字原样保留，没给的格位按"每多一张加一档"补）：

| 牌型 | 条件 | 分数 |
|---|---|---|
| 同花 | ≥3 张同花 | 300（4 张 500 / 5 张 900） |
| 三条 | ≥3 张同点 | 600（四条 1500） |
| 顺子 | ≥3 张链上连续 | 700（4 连 1300 / 5 连 2500） |
| 同花顺 | 同花 + 连续 | 2000（统一价） |
| 连消 | 消除合拢后再次成型 | ×2 / ×4 / ×8 / ×12 |
| 同花顺奖励 | 触发时 | 7 秒狂热 ×2 + 续时 5 秒 |

同花顺的 2000 是统一价，不随长度涨。原因和骰子的六连顺不同：它的
价值主要来自狂热和续时，长度再加价会让"3 张同花顺"变成一张不该
追的牌。排序时额外 +1500 参与"谁更值钱"的比较，但事件里的 base 仍是 2000。

### 34.3 平衡第一刀：发牌不能太贴心

第一版照搬骰子的 74% 智能发牌。实测（12 局瞄准机器人）：

```
瞄准 101190 / 乱按 62249 / 挂机 72784
技巧倍率 2.23×（其他模式 4~5×）
```

挂机 72k 的原因不是"机器人太强"，是**机器自己在玩**：20 张牌里同花的
自然概率就有 1/16，再按"这张牌有没有用"发牌，盘面会不断自己成型。
这不是"反转祖玛"，是老虎机自己在摇。

改成 30% 智能 / 70% 均匀，并把权重压缩到 0.06；同时把节拍从
2.28→1.04 放慢到 2.75→1.30：

| | 改前 | 改后 |
|---|---|---|
| 瞄准 | 101190 | 77066 |
| 乱按 | 62249 | 27994 |
| 挂机 | 72784 | 26821 |
| 技巧倍率 | 2.23× | 3.14× |

放慢节拍不是为了"简单"，是为了让每一颗牌都值得算。扑克 3 张就能成型，
1.04 秒一颗时机器会替玩家把盘面消空；1.30 秒一颗时，玩家的每一次转盘
才对应一个真实的牌型决定。

### 34.4 平衡第二刀：连消倍率封顶

扑克 3 张就能成型，3 秒窗口里的连消几乎是常驻的。实测连消峰值 11.2，
`COMBO_MULT` 会把它乘到 4 倍以上——一次 300 分的同花变成 1200，
"我做了哪种牌型"完全被倍率盖过去。

所以扑克模式加了一条 `comboCap: 2.0`。这不是削弱玩家，是把"牌型选择"
重新放回收益的主位；控制台显示的倍率也读同一个上限，避免出现
"显示 ×4.2、实际按 ×2.0 结算"的谎话。

### 34.5 三种特殊牌：它们各自改变哪一步

| 特殊牌 | 怎么参与牌型 | 被消除时额外做什么 |
|---|---|---|
| 小丑（8%） | 任意花色 + 任意点数；**落地不转化** | 无 |
| 爆破王牌（6%） | 按 A 参与；花色视为任意 | 左右各炸一张，每张 +150 |
| 染花牌（5%） | 有真实牌面，按那张牌参与 | 左右邻改成同一花色（穷举 4 色取最值钱） |

小丑和骰子的万能骰最大的区别是**它不在落地定型**。骰子必须落地定型，
因为"万能在链上仍可变点"会让游程扫描多解；扑克这里反过来——设计稿
要的就是"它插进任何空隙都能同时激活同花 / 三条 / 顺子"，所以
`findHand` 直接把 `10` 当作 `-1` 参与两条约束，而不是先转成某张真牌。

染花牌和翻面骰共用同一条时间线：清除之后、compact 之前改左右邻，
并在**合拢后的副本**上穷举花色。少了"合拢后"这一步，就会重演 §33.4
的 bug——左右邻此刻还隔着被清掉的几格，扫不出任何牌型，穷举结果恒为
第一种花色。

### 34.6 底牌槽与筹码槽：一个在操作台，一个在轨道上

底牌槽（E / 右键）只动**下一发**：

- 空槽按下：把待发牌扣进槽，发牌机补一张新牌；
- 有牌按下：把槽里的牌换回待发位，原来那张扣进槽。

为什么只动待发位：玩家的规划窗口是"待发 + 两张预览"，如果允许从预览里挑，
一个槽就要管理三张牌，规则会变成记忆负担。只动待发位，规则一句话说完。

筹码槽是**消除时**结算，不是落地时：

- 牌型里只要有一张牌压在金色槽上，整段 ×2；
- 在槽里打出三条 / 同花顺，额外送一张小丑牌。

它和骰子的 ×2 镀金槽共用金色，但因果位置不同：骰子是"这颗骰子镀金"，
扑克是"整段牌型覆盖了槽"。所以 `dropAt` 里的落地槽逻辑必须按规则族
分支，否则扑克牌会莫名其妙被"翻面"。

### 34.7 开局：第一枪就同花，但不是同花顺

开局手工摆（从 0 号射口左边两格起算）：

```
... ♠Q  ♥10  [♥K]  ♣A  ♦J  ♠Q ...
              ↑ 第一发 ♥Q 插在 ♥K 前面
```

♥10 ♥Q ♥K 三张同花 → 300 分。目标格**必须是满的**：游戏的落点规则是
"落到空格会吸附到最近的链条"，摆一个真空隙，♥Q 会被吸到旁边，
根本进不了 ♥10 和 ♥K 中间。

刻意避开 10-J-Q / J-Q-K，因为那会是同花顺（2000 + 狂热），
开局第一枪就给太大的东西，后面的三条 / 顺子就教不动了。

其余槽位随机补牌，每补一张都要求全环没有现成牌型；40 次试不出来就
**留空**，而不是把会成型的那张留在盘上——开局有一个现成牌型，等于
第一枪之前系统自己先消了一次。

### 34.8 牌怎么画：长方形是第一剪影

骰子是 2.5D 方块，扑克是**纯 2D 长方形**。理由很实际：骰子本来就是方的，
剪影没有信息量；扑克如果不画成长方形，玩家第一眼不会认为那是牌。

读法顺序：

1. 花色：四色描边（♥ 红 / ♦ 金 / ♠ 青 / ♣ 紫）；
2. 点数：中间的字形（10 用更小一号，否则两个字会顶到边框）；
3. 角标：右下角一个小花色，作为"近看"的确认；
4. 特殊牌：小丑是彩虹边 + ★，爆破王牌是 A + 爆点，暗牌是斜纹 + ?。

牌在轨道上**永远正着放**，不随切向旋转。跟着轨道转 90° 的 K 和 A
需要重新学；而高速下玩家先认的是字形。

### 34.11 这一轮抓到的两个跨模式 bug

1. **标题页的色点用了全局规则族**：`ballSkin(ci)` 按当前选中的模式解析，
   选到扑克时，标准模式的 4 个色点会被解释成 4 张红心，全变红。
   修法是标题页按**每张卡自己的 `m.rules`** 取色，而不是读全局开关。

2. **顺子按集合而不是按顺序判定**：见 34.2。开局随机补牌会直接凑出

   记成 -1，穷举递增 / 递减两条等差线。

所以本轮把断言写成了"打一枪 / 切一次模式 / 跑一次真实结算"，
而不是读数组。

## 35. 跑道拓扑：同一套规则，四种机器

需求原话：

> 3、添加关卡设计：新关卡 跑道拓扑变体
> 解锁 8 字交叉双轮（喷头瞄准交叉口）、一大一小变速轮（前大盘后小飞轮）、三轮三角链
> 零新按键就能让后期关卡和隐藏模式焕然一新，视觉极具记忆点

这一轮没有动规则族：三个新关卡仍然是四色球、同色三消、连消和奖励球，
变的只有**跑道几何**和**炮口位置**。这也是"零新按键"能成立的原因——
玩家已经会的"转轮盘 / 开火"原样有效，只是盘子的形状变了。

### 35.1 为什么用弧长采样器，而不是每条拓扑一套解析式

椭圆能用解析式，是因为它由直线和圆弧拼成，弧长积分有闭式。
8 字（Gerono 双纽线）和三角链的弧长没有初等闭式，硬写公式会在
"槽位等距"上出错——槽位必须沿**弧长**均匀，不是按参数 t 均匀。

所以新增三条拓扑共用一个折线采样器：

```
参数曲线 → 2400 个点 → 累计弧长 cum[] → 按 s 二分查找 + 线性插值
```

`pointAt / tangentAt / normalAt` 都走同一份采样器，代价是一次性采样，
收益是三种拓扑、所有渲染和判定只认三个几何函数。椭圆保留原解析式，
避免第一至第六个模式因为"统一"而悄悄改变手感。

### 35.2 8 字交叉：槽位 0 必须精确落在交叉口

Gerono 双纽线：

```
x = a cos t
y = (b/2) sin 2t
```

在 (0,0) 处交叉两次（t=π/2 与 3π/2）。炮口固定在交叉口正上方，
两个交叉槽位里只有 `nozzleOff = 0` 的那一个会被命中——另一条是干扰线。

三个必须做的判断：

1. **把交叉点旋成弧长 0**。第一版用"离原点最近的槽位"（slot 9），
   结果炮口锚点在 (0,0)、槽位坐标在 (-0.6,-0.5)——球落在交叉口，
   珠子却插在斜边上，玩家看到的是"球落空了"。修法是把采样点列表
   从交叉点开始重新拼接，槽位 0 精确等于交叉口。
2. **桥面**。两条管子在中心会糊成一块 200px 的黑胶囊（第一版 1.9 倍轮径），
   实测读成"黑洞"。缩到 0.95 倍轮径并加一道青色桥沿之后，
   交叉口才重新读成"两条线在上下交叠"。
3. **上下层珠子**。交叉口会同时出现两颗珠子，精确重合。渲染层把
   "另一条支线也在交叉口"的那颗压到 0.34 alpha，命中环只套在
   `nozzleOff` 指定的那颗上。没有这一步，命中环套在哪颗上读不出来。

### 35.3 大小轮：外公切线 + 两个必须踩过的坑

两个圆的外公切线角度：

```
α = acos((R1-R2)/d)     // 等径时 α=90°，退化成上下水平切线
```

路径 = 两条公切线 + 小轮外侧弧 + 大轮外侧弧。链条线速度恒定，
所以角速度 ∝ 1/r：小轮在画面里转得比大轮快一倍。这就是"变速轮"
的全部实现——没有额外按键，也没有改节奏。

两个坑：

1. **包围盒没有居中**。大轮向左伸得更远，第一版把 `dx=(R1-R2)/2`
   写成了 `-dx`，整条皮带在画面里左偏 2.5 个世界单位（约 68px），
   左炮口几乎贴到左侧 HUD。改成 `+dx` 之后 `x0+x1 ≈ 0`。
2. **路径是逆时针的**。采样器按"下切线 → 小弧 → 上切线 → 大弧"拼出来，
   方向是逆时针；`outwardNormal` 假设顺时针，于是炮口全被算到皮带
   **里面**，大轮左炮压在自己的齿轮上。修法是 `pts.reverse()`，
   再按"最靠近目标点"重新找炮口槽位。

炮口位置也试了三版：

| 方案 | 结果 |
|---|---|
| 两条切线正中 | 两个炮口挤在机器中央，互相遮挡 |
| 两轮外侧弧中点 | 退到画面最左/最右，压住左右 HUD |
| 上切线偏大盘端 + 下切线偏小盘端 | 上下错开、不压 HUD，能看出"这一发来自哪个轮" |

### 35.4 三轮三角：把炮口全部放到上半圈

三个等径圆的外公切线组成一个圆角三角形：三条偏移直线 + 三段 120° 外圆弧。
三角形顶点按 上 → 右下 → 左下 排列，路径顺时针；顶点整体下移 c/4，
让包围盒以原点为中心。

炮口位置是这一轮唯一一次"为 HUD 让路"的设计：

- 三个边中点各放一个炮口，是最直觉的方案；
- 但三角链比椭圆高，底部炮口会跑到 y≈700，正压住连消控制台；
- 改成"顶弧中点 + 左上边中点 + 右上边中点"，三个炮口全部在上半圈，
  底部边保持干净。

"三轮"的视觉记忆点在三个齿轮和三角骨架，不在"三个边都必须有炮"。
三个炮口仍然按 0→1→2 轮转，零新按键。

### 35.5 渲染：椭圆保留整块托盘，新拓扑改走"管"

椭圆的 `plate / groove` 是围绕跑道填充的整块托盘。新拓扑的内部是空的
（8 字的两个洞、三角链的三角洞），再填一块板会把空洞糊死。

所以非椭圆拓扑走另一套：

```
tubePlate   沿轨道描一条 CHANNEL_W+44 的粗管（落影 + 外发光 + 双色）
flywheels   在 PULLEYS 处画齿轮；8 字改画 X 形交叉枢纽
tubeGroove  沿轨道描深槽 + 双轨脊 + 青色底光
topologyCore 大小轮画一根轴；三角链画三根辐条 + 中央轴承
```

`TRACK_PTS` 在 `syncGeo` 里一次性采样 520 个屏幕点，之后 6 条描边复用；
每帧现算 3000 次 `pointAt` 会白烧 CPU。`S` 也改成由几何层给出的
`BOUND` 推，不再用椭圆的 `C/R`——三角链的纵向包围盒是 6.3 而不是 R=2.4，
用 R 算会把机器画到标题行上。

### 35.6 标题页第 2 页：零新按键的隐藏关卡

9 个模式塞不进一行。标题页按 `ui.sel >= 6` 分成两页：

- 第 1 页：6 个基础模式；
- 第 2 页：3 个隐藏拓扑（8 字 / 大小轮 / 三轮三角）；
- ← → 循环会自然翻页，数字键 7-9 直接选中；
- 页码 `HIDDEN TOPOLOGY · 2 / 2` 在玩家按 → 之前就说明"还有第二页"。

第 7~9 个模式的 `hidden: true` 只是标题页的分页标记，不影响存档、
段位或直接 `?mode=` 启动。

|---|---|---|
| `timer`（默认） | `max(beatRush, min(beatTime, beatScore))`，时间地板与分数曲线取较快者 | 音频跟随 `tempo` 走 96→142 |
| `music` | 半小节一颗，`beat = 2 × 60 / bpm` | 88 → 104 → 124 → 148 四段平台 + 8~10% 斜坡 |

入口：标题页 `T` 切换、URL `?fire=music`、localStorage 记忆（`bcj.fire.v1`）。
切换只影响发球节拍，不改几何、计分或段位线。

### 37.2 为什么 BPM 用半小节

88→148 BPM 对应颗间隔 1.36s→0.81s。慢段能读清盘面，快段明显"赶"。
相位用逐帧累加而不是 `time / 拍长`，这样 BPM 换段时炮口蓄力不会跳一下。

### 37.3 外部 BGM 与锁拍

默认 BGM 是两首 **CC0 轻音乐**播放列表（`song18.mp3` Crystal Cave 49.56s、
`song21.mp3` Mysterious Ambience 42.91s），同作者 cynicmusic、同调式，
曾被第三方拼成无缝 loop。曲末用 `onended` 自动接下一首，两曲交替，避免 49s 单曲循环听腻；
不用 `loop=true`（会把尾巴硬接到开头）。`stopBgm()` 递增 token 让过期的 `onended` 不误切歌。

只有「BGM 来源 = 轻音乐」**且**「出球模式 = 音乐」时才锁到 98.5 BPM；
定时出球不吃锁拍，否则两次加速曲线会互相打架。切换键 `B`，
URL `?bgm=file|proc`，localStorage 记忆（`bcj.bgm.v1`）。
**新玩家默认 `file`（轻音乐）**，老存档里显式选过 `proc` 的仍被尊重。

> 用户反馈"程序化音乐不好听"，故把默认值从 `proc` 改为 `file`；程序化合成保留为备选，
> 它承载的动态 BPM 反馈（96→142）仍在，只是不再默认播放。

> 注意区分两条 BPM 曲线：§31.7 的 96→142 是 `tempo` 驱动的**程序化 BGM**，
> 本节 88→148 是**音乐出球**的拍子。它们描述同一台机器在不同模式下的两条曲线，不能合并叙述。

### 37.4 四层音画映射（角度 → 音高 + 声像）

7 个固定角度档位（−24° / −16° / −8° / 0° / +8° / +16° / +24°）映射到
五声音阶 C4 / D4 / E4 / G4 / A4 / C5 / E5，声像从 −0.65 线性到 +0.65。
连续角度只用于炮身视觉倾斜；音高必须吸附到档位，否则连续滑音会像警报器。
出膛音用当前档位，消除音沿用上一发的根音与声像——于是"左边打出的连锁"
真的从低音区、左声道响起。断言见 `rules.mjs` 第 37 条。

## 39. 第十一轮：落空球追上链尾（放置目标在落地时算）

> **【历史 · 第十二轮回退】** 这一轮把 `snap()` 改成"固定追前方球"，
> 玩家反馈球最终位置不对（应该滑到最近球、平局优先右），已在第十二轮回退。
> 保留本节是因为"目标在落地时算、不在发射时锁"这条约束仍然成立，
> 且"不能追全局链尾"的实测结论（§39.2）解释了为什么不能简单改成链尾吸附。

### 39.1 改了什么

`sim.js` 的 `snap()` 原来在落空时取"落点前后最近的珠子，近者胜"——判据里没有链条方向，
球可能被吸到身后的珠子。现在固定取 **+1（顺时针）方向的第一颗珠**，也就是追上前方那段链条的末尾球；
只有前方整圈都没有珠子（空盘）时才退回落点。`dropAt()` 仍在落地那一帧调用它，
发射时 `fire()` 只保存 `ci / off / 时长`，不锁定落点。

### 39.2 为什么不能追全局链尾

先试过把球直接追加到整条链的尾端（`tail+1`），结果普通玩家爆仓率飙升到 50%
（standard）、30%（grand / dice）——球全堆在尾巴上，颜色凑不成三消。
所以"追尾"的正确尺度是**落点前方那一段的末尾球**，不是全局末端。

### 39.3 平衡重标（段位线未动）

追尾让补位更集中、链条更容易变长，两项参数随之调整：

| standard | `rustStart` | 30 → 40 | 普通爆仓 3/20 → 0/20，均分 15.6k → 17.0k |
| poker | `shiftRate` | 0.05 → 0.02 | 挂机/普通 0.93 → 0.55，单调保持 |

## 41. 第十三轮：球贴最近球旁边的空槽 + 三消等碰到才算

> **【现行】** 两条反馈："球在轨道目标位置出错了，要的是向最近的球移动，
> 你变成其它球让位置了"、"不要一到轨道就开始三消判断，应该是碰到一起的时候计算"。

### 41.1 目标槽：最近球旁边的空位，链不动

`snap(k)` 原来返回最近**球**的槽位（已占用），`dropAt` 于是走"插入"分支，
把那颗球和整列邻居推开一格给它腾地方。现在改成返回那颗球**前方 / 后方的空槽**：
球从落点 k 滑到那里，与最近球相切，其余珠子引用和位置都不变。
前后等距时优先右边的球（+1），与上一轮约定一致。
落在已占用槽（直接命中）仍走插入——这时球本来就贴在链上，不需要滑。

### 41.2 三消时机：dx 归零那一刻

`dropAt` 不再当场 `resolve()`，而是在新珠子上打 `pending` 标记；
`step()` 的补位循环里，当 `dx` 走到 0（球真正碰到链）才把这一发放进 `justLanded`，
循环结束后统一 `resolve()`（resolve 会清珠 + compact，不能在遍历 slots 时改盘面）。
落帧与碰帧分离后，无头测试里直接 `dropAt()` 的断言改用 `settle()` 多跑几帧；
"远距离吸附"断言改成"目标总在最近球旁边的空槽"（偏差最多 1 格）。

残影的缩小幅度 0.68 → 0.52、实心保持时间 65% → 55%：珠子要在原处多停一会儿。

### 43.3 特效锚点改用视觉位置

合拢变慢之后，第二段连锁的珠子在逻辑槽位上已经就位、视觉上还带着
第一段留下的 `dx`。`clear` 事件的 `positions` / `s0` 现在加上 `b.dx`，
火花和光带画在玩家看到的位置，而不是前面的空槽上。
（临时断言：第二段 `s0` 与视觉位置误差 < 1e-6，与逻辑槽位相差 3 格。）

## 44. 第十六轮：转速、转动出球、小星星与辅助线

> **【历史】** 需求原文："需要添加转速概念，按的越快速度越快。射口的球高亮改成辅助线。
> 还有音乐用小星星。不转的话不会出现球，按转的距离来出下下一个球。还有出球尽可能在节拍附近出。"

### 44.1 转速：按住是基础档，连打才快

```
按住方向键      → 目标转速 = 0.42 × vMax
每次按下（含反向）→ 按两次按下的间隔给节奏分 tapRate（tapFast 0.10s → 1，tapSlow 0.36s → 0）
目标转速        → (0.42 + tapRate × 0.58) × vMax
```

比例而不是绝对格数：各模式 vMax 是 11~15.4，写死会出现"大轮里连打比按住还慢"。
`spinK = 5`：朝目标靠拢太快会冲过头，落点直接废掉。松开后仍按 `dampK = 9` 回到 drift。

### 44.2 转动距离驱动出球（"不转不出球"）

- `spinAccum` 只在 `input ≠ 0` 时累计 `|v| × dt`：松手后链条的 drift 是机器惯性，不算玩家转的。
- 攒满 `spinFireDist = 7` 格 → 请求出球；空中最多 `maxAirBalls = 2` 颗。
- 攒够后最多等 `beatSnapWin = 0.5` 个拍长去贴下一个拍点；等不到就立即出。
  节拍是服务手感，不是卡玩家的闸门。
- 飞行时长随转速收紧：`1.48s → 约 0.98s × (1 - 0.34 × spinNorm)`。
  这一条是反馈不是物理——快必须同时体现在球和节奏上，否则转快只剩"更难瞄"。
- 出球时刻不再由 `beatClock` 决定；它只作为拍内相位给演出用。
- `land()` 改成一次只落最前面一颗：多球并行时，整组清空会让后面的球凭空消失。

### 44.3 音乐：小星星（公有领域）

程序化 BGM 从 4 小节鼓组换成 48 拍的小星星（12 小节）：每拍一个字，
'-' 为延音；低音每小节一个根音；底鼓每拍一下但音量压到旋律之下。
BPM 仍是 96 → 142（随分数），所以"机器越快，同一首歌唱得越急"。
出球贴的就是这条 BPM 网格；选外部 CC0 轻音乐时 `bgmLockBpm = 98.5`，锁到它的拍。

默认 BGM 从 `file` 改为 `proc`（小星星），localStorage key 升到 `bcj.bgm.v2`。

### 44.4 射口高亮 → 辅助线

删除 `hitRing`（珠子上的白环），改成 `aimGuide()`：
- 炮口 → 落点的流动虚线（dashOffset 随时间走）；
- 落点处沿轨道外侧的一段弧（法线外移一个珠径）+ 两端刻度。
珠子不再被盖住，"从哪儿来、落在哪一段"同时可读。

### 44.5 移除两种出球模式

`timer / music` 出球模式随"转动驱动"一起删除：标题页的出球开关、T 键、
`?fire=` 参数、`Game.fireMode` 全部移除。BGM 来源（小星星 / 轻音乐）仍在，用 B 切换。

### 44.6 测试与段位线重标

- `rules.mjs`：11 改为"不转 60 秒 0 颗 / 按住 60 秒 ≥12 颗 / 空中 ≤2 颗"；
  14 改为"多球并行上限 + 每颗都真的落地"；36 改为"快按比慢按转得多、按住到基础档、有球踩在拍点上"；
  38/39 改为"锁拍"与"按住攒够再软降"。
- `test.mjs`：技能阶梯的判据从"爆仓率反向"改成"末盘占用反向"——
  不转就不会有球，爆仓不再是普通玩家的默认结局；风险变成"转多快"。
- 段位线按 oracle 24 局分位重划（B≈p42 / A≈p70 / S≈p86 / SS≈p94）：
  standard `[0, 8600, 11400, 12600, 13600]`、mini `[0, 5400, 7200, 8000, 9000]`、
  grand `[0, 16000, 17900, 18800, 19600]`、dice `[0, 21000, 25700, 29100, 33000]`、
  poker `[0, 28200, 37400, 40100, 43000]`。

## 45. 珐琅弹珠机视觉与交互改版

> 【历史】机台视觉与模式入口由 §46 更新。

标准模式的第一项决策是辨认待发弹珠，再转动轨道，让相配的珠子到达接球口。原先的模式卡盖在盘面上，对局读数分散在画布四周，通用点击还会直接开局。新版让盘面从标题页开始就可见，模式选择、开局和切换配乐均有各自的按钮。

| 位置 | 表现 | 玩家要读到的信息 |
|---|---|---|
| 机台 | 深青台面、青绿珐琅外壳、奶油轨沿与珊瑚红喷头 | 固定喷头投球，只有一条接球环 |
| 接球口 | 奶油色虚线连到固定的倒 V 接球标记，括号标出预测槽 | 发球时锁定飞行轨迹。括号提示飞行中的第一颗球在松手后预计落入的槽位 |
| 弹珠 | 莓紫菱形、琥珀方块、朱红星形、青蓝三角 | 形状与颜色同时编码，骰子和纸牌沿用点数、花色 |
| 对局仪表 | 分数、剩余时间、待发三格、转动蓄能、占用与连消 | 下一发是什么、还需转多少、盘面还能容纳多少 |
| 触屏 | 轨道下方放左转、右转、刹车和加速落球，支持同时按住转向与加速 | 拇指操作时仍能看到接球区 |
| 结算 | 结束原因、段位差距、模式战绩、重开与换模式 | 分辨时间到和轨道塞满，直接决定下一局 |

概念图只按玩法描述创作。游戏内用 Canvas 绘制同一套材质与轨道，盘面由模式几何和当前局状态驱动。标题页使用按规则族切换的布珠示意，保证选择模式时能看到弹珠、骰子或纸牌的外形。

## 46. 三模式、主动转距出球与潮玩街机

- **模式入口**为标准轮、骰子轮盘和加速模式。标准轮为 28 格、90 秒。加速模式沿用标准轮的盘面规则，最高转速为 18 格/秒。小轮、大轮和扑克牌链的旧链接会打开标准轮。
- **操作**按住 A / D 或 ← / → 控制方向并逐渐加速，松手沿最后一次选择的方向回到巡航速度。反向时转速连续经过零点。触屏使用左右两个大按钮。高速时轨沿亮起随轨道移动的光带。
- **出球**在 120 Hz 固定步累计主动转向时的绝对转距。每满 7 格出一颗，余量留给下一发。默认巡航为 1.35 格/秒，标准轮满速为 13 格/秒。新球飞行速度随出膛时的转速提高。
- **仪表**把实时转速和累计转距并排显示。出球进度紧挨待发队列，倒计时与暂停集中在同一行。页面默认英文，可切换简体中文并保存选择。
- **视觉**采用浅雾蓝台面、模塑蓝色外壳、靛蓝凹槽与亮橙喷头。菜单从左侧选择模式，对局把仪表移到右侧。窄屏把仪表与轨道垂直排布。
