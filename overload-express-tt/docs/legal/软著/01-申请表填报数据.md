## 三、软件功能与技术特点（500–1300 字）

2026 年 3 月 15 日起，新版申请表要求功能描述 500–1300 字，须说明研发背景、核心架构、技术实现与应用场景。模板化简略描述会被退回。

### 版本 A（约 890 字，推荐）

本软件是一款运行于抖音小游戏平台的横屏休闲物理模拟游戏。研发背景是移动端休闲游戏对首屏启动时间极度敏感，传统引擎小游戏常因资源包体过大、加载链路过长导致用户流失。本软件研发目标是在平台严格的主包体积限制下（实测主包 262 KB，构建门限 300 KB 内），通过纯代码算法实现具备高度物理深度与表现力的列车堆叠避障玩法，验证超轻包体与深度物理玩法并存的可行性。

软件采用六层模块化架构。平台适配层屏蔽不同运行环境差异，统一封装存储、振动、安全区、动画帧与生命周期；数据配置层以常量表集中定义十个主线关卡、六类乘客物理属性、特色左右分流专列、三项车队升级、六套纯矢量涂装、八个升星强化词条、每日任务与二十四项成就卡牌；物理仿真层以固定步长推进二维位置约束动力学，输出质点位移、多点抓握拓扑、发车物理快照与名场面成就事件；舞台表现层以纯 Canvas 2D 路径绘制全部场景、列车、乘客姿态与粒子特效，不加载任何外置位图与音频文件；交互界面层实现全矢量界面绘制、弹窗栈管理与触控分区；商务合规层封装激励视频、自动录屏分享、平台排行榜与 8+ 适龄合规提示。

核心技术实现包含三项突破。其一，物理求解采用 1/120 秒固定时间步长与每步六次约束迭代，严格按照骨骼形变、多点抓握、接触分离与车体表面约束的顺序求解，并在发车瞬间捕获车顶全员物理状态快照，支持无缝重跑与护盾重试。其二，每名乘客抽象为双脚与头部双质点模型，通过四个点对组合支持任意姿态下的碰撞与多类型抓握（含托肩、跨堆拉索、车门直挂与菜篮承接）。其三，基于 32 位种子发生器实现全流程确定性物理模拟，确保每日专列全服一致性与录像回放的一致还原。

软件主要面向大众碎片化单机休闲场景。玩家在装车阶段根据站台候车队伍策略性放置乘客，发车后通过缩头与压重心操作避让低矮涵洞与横风，同时可通过特色左右分流专列进行盲分配重挑战；局外可通过运达人数与通关评价获取车票金币，升级车顶防滑漆、减震弹簧与全员能量壶，在成就卡馆中亲手翻牌领取二十四张热梗成就卡牌，集齐单套大奖并冲刺全图鉴大满贯星耀涂装。软件不含任何内购充值与账号体系，数据严格保存在本地设备，无隐私采集风险。

### 版本 B（约 620 字，备用）

本软件是一款运行于抖音小游戏平台的横屏休闲物理模拟游戏。研发目标是在严格的主包体积限制下（实测 262 KB，门限 300 KB 内），通过纯代码二维位置约束动力学与矢量渲染，实现结果高度可复现、操作具备物理深度的列车乘客堆叠与避障玩法。

软件按平台适配层、数据配置层、物理仿真层、舞台表现层、交互界面层与商务合规层六层组织。平台适配层屏蔽宿主差异；数据配置层集中定义十关主线、特色左右分流专列、六类乘客、三项车队升级、六套涂装、八个强化词条、每日任务与二十四项成就卡牌；物理仿真层以固定步长推进二维位置约束动力学，输出抓握、碰撞、发车快照与成就事件；表现层以纯 Canvas 2D 路径绘制全部画面与粒子；界面层管理弹窗栈（含成就卡馆与每日任务）与触控分区；商务层封装激励视频、分享与排行榜。

技术实现上，仿真采用固定步长 1/120 秒，每步执行六次约束迭代，迭代内按骨骼、抓握、分离、表面四阶段顺序求解，并在发车时记录全员物理快照支持护盾重试。乘客由双脚与头部双质点表示，通过四个点对组合完成接触判定；抓握关系为带类型的约束列表，区分普通抓握、托肩、跨堆拉索、车门直挂与菜篮承接五类。随机数使用 32 位种子发生器，保证轨迹可复现。

玩家在站台阶段放置乘客，发车后通过缩头与压重心避让桥洞与阵风，也可在左右分流专列中进行盲分配重挑战；局外升级车顶防滑漆、减震弹簧与能量壶，在卡馆翻牌收集二十四张成就卡牌冲刺全图鉴大满贯。软件为纯单机，无付费与账号体系，数据仅存本地。

## 六、个人申请的身份证件要求

官方指南对自然人申请只要求**身份证正反面**。《计算机软件著作权登记申请所需文件》的身份证明清单列举了企业法人、事业单位法人、机关法人、社团法人、民办非企业单位、非法人组织、外国自然人、外国机构，自然人一项由北京市政务服务网的办事指南补充为「有效的自然人身份证复印件（正反面）」。

**《非职务开发证明》不是必备材料。** 它是「可以」提交的补充材料，不是「必须」提交。百度百科等二手资料容易把这一条写成硬性要求，属于误传。

什么情况下建议主动补交：

| 情形 | 建议 |
|---|---|
| 已离职，软件与原公司业务无关 | 可以不交 |
| 开发期间在职，但软件与本职工作无关 | 建议补一份《非职务开发保证书》，成本低、可强化权利归属 |
| 开发期间在职，且软件与原公司业务相关 | 必须谨慎判断是否构成职务作品，建议咨询专业人士后再申报 |

无论哪种情形，保留能证明开发时间与独立性的材料（本地 git 提交记录、代码时间戳、设计文档）都比一纸声明更有用。本项目已有 git 历史与代码指纹，见 `04-登记版本代码指纹.md`。

## 七、提交路径

1. 访问中国版权保护中心官网，注册账号并完成实名认证（个人核验身份证）。
2. 进入「我的登记 → 新增申请」，选择 R11 计算机软件著作权登记申请。
3. 按第一节至第三节填写表格。
4. 上传源程序 PDF 与说明书 PDF。
5. 上传身份证正反面（非职务开发证明按第六节判断是否补交）。
6. 在线打印申请确认签章页，手抄承诺、签名、填身份证号，扫描为 PDF 上传。
7. 提交，获取受理号，等待受理与审查。

**官方给出的时间节点**（不是估算，是登记办法的规定）：

| 环节 | 规定 |
|---|---|
| 受理 | 材料符合要求的予以受理；签章页无签章、未上传正确的签章页或鉴别材料，视为未提交，**不予受理** |
| 审查 | 自受理日起 **60 日内**审查完成 |
| 补正 | 收到通知后 **30 日内**提交，逾期视为撤回 |
| 发证 | 审查通过后可在用户中心下载电子证书（PDF，带电子签章） |

**关于版本号的一条官方说明**：登记证书中的软件版本号以**申请表填报的为准**；鉴别材料页眉的版本号应与申请表一致，但**有无「V」以申请表中填报的为准**。本套材料申请表填 `V1.0`，两个 PDF 页眉均为「超载快车游戏软件 V1.0」，三处一致，不存在这个风险点。
