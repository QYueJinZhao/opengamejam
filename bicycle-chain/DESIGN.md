## 0. 三处必须拍板的底层定义

原方案最大的问题不是数值，而是**三件事没说清**，而这三件事决定其余全部实现。本文档先定死，后面所有内容从这三点推导。

### 0.1 发射权：炮口自动开火，玩家只控制"落点"

这是"反向"玩法的全部意义。**玩家不是射手，是接球方。**

- 炮口按关卡节拍**自动**发射，不需要也不允许玩家按开火键。
- 玩家唯一能改变的是**跑道相位**——也就是"这一发会落在哪一格"。
- 因此"放空"是一个**真实存在的动作**：把空隙转到落点上，让球飞过去。

原文档同时写了"自动节拍（2.10s 周期）"和"瞄准/急停/插入/插进两颗同色球正中"，等于把玩家当成射手，两套模型并存，无法编码。**本版只保留接球模型。**

> 反例检验：如果是手动发射，那么"放空累计 3 发惩罚"这条规则毫无意义（不按开火键就够了），而它占了数值表一整行——说明设计者的本意就是自动开火。

### 0.2 珠子与皮带：柔性珠链，可沿带自由滑动

- 珠子**焊死在皮带上**的话，插入必然撕裂皮带 → 物理不成立。
- 所以珠子是**可沿带自由滑动的珠子**，带速只决定整体相位。

推论（后续章节全部依赖）：
- 插入 = 落点两侧各推开半格，向最近的空位方向整体推移；
- 消除 = 断口两侧以 0.14s 合拢，空位被"挤"到别处；
- 容量 = 珠子总数，达 28 即爆仓，与空位在哪无关。

### 0.3 双喷头 = 同一个环上的两个落点，产生两个断口

- 两个落点相距**半圈 = 14 格**（验算：49.1327 / 2 / 1.7547 = 14.0）。
- 因此 L3 之后环上**同时存在两个断口**，不是一条"蛇"。
- 术语统一：**轮盘 / 珠链 / 槽位 / 落点 / 接球 / 放空**。"蛇身"一词全部废弃（它暗示一条有头有尾的链，与闭环矛盾）。

**这三条一旦定了，原文档里 60% 的歧义自动消失。**

## 2. 核心循环

一拍（beat）= 一个关卡节拍周期。所有状态都在这 6 步里循环：

```
[1] 充能 CHARGE      炮口蓄力，颜色已确定并可见（预警 ≥ 0.6×拍长）
        ↓
[2] 发射 FIRE        球以 32 u/s 沿弹道飞向落点，飞行 0.203s
        ↓
[3] 判落 LAND        到达瞬间判定落点格：有珠 → 插入；空位 → 放空
        ↓
[4] 结算 RESOLVE     插入后判 ≥3 同色；消除 → 记分 → 断口 0.14s 合拢
        ↓
[5] 连锁 CHAIN       合拢后再次 ≥3 → 倍率升级，回到 [4]
        ↓
[6] 检查 CHECK       爆仓 / 达标 / 超时，任一命中即结算关卡
```

**关键时序约束**：逻辑层在第 4–5 步**瞬时结算**（同一帧内算完所有连锁），表现层再用 0.30s/级 的动画依次播放。逻辑不等待动画。理由见 §5.4。

## 3. 玩家能动性模型

玩家只有 **1 个连续自由度**：跑道相位 φ ∈ [0, L)。

```
φ' = φ + v · dt
v' = clamp(v + input · a · dt, -v_max, +v_max)
input ∈ {-1, 0, +1}
```

- 松手时 `v *= exp(-k·dt)`，k = 9.049 /s（等价 60fps 下 ×0.86/帧，但**帧率无关**）
- 无输入且 |v| < 0.15 格/s → 直接归零（防抖）

**为什么只有一个自由度是对的**：接球类玩法的乐趣来自"预测 + 提前量"，不是"多键组合"。任何第二个自由度（喷头摆角、第二根独立跑道）都会稀释因果直觉。原方案 L2 给喷头加了 ±12° 摆动，等于引入第二个自由度，**与"转到对的位置"这个核心动作抢戏**——本版删除，改为由节拍与可达半径制造难度。

## 4. 空间模型

### 4.1 几何（已逐项验算）

| 符号 | 值 | 单位 | 推导 |
|---|---|---|---|
| r | 4.0 | u | 轮半径 |
| d | 12.0 | u | 两轮中心距 |
| **L** | **49.1327** | u | 闭合带长 = 2d + 2πr = 24 + 25.1327 |
| **N** | **28** | slot | 槽位数（设计定值） |
| **Δ** | **1.7547** | u | 槽距 = L / N |
| ρ | 0.8774 | u | 珠子半径 = Δ/2（相切，无重叠） |
| 喷头 A | (0, −10.5) | u | 落点 (0, −4)，射程 6.5 u |
| 喷头 B | (0, +10.5) | u | 落点 (0, +4)，射程 6.5 u |
| 两落点弧距 | 24.566 | u | = L/2 = **14 格** |

验算结论：`49.1327 / 1.7547 = 28.000`，`28 / 14 = 2.0s`（满圈时间）——原文档这三个数自洽，可以用。

### 4.2 槽位坐标

一维弧长坐标 `s ∈ [0, L)`，从喷头 A 落点起算，顺时针为正。

```
槽 i 的中心： s_i = (i + 0.5) · Δ
喷头 A 落点： s = 0
喷头 B 落点： s = L/2（第 14 号槽边界）
```

> 注意：落点落在**槽的边界**上，不是槽心。这意味着接球判定天然是"落在两格之间"，需要一个明确规则。**本版规定：落点对齐到"顺时针一侧"的槽心**，即落点所在格 = `floor((s_at_impact mod L) / Δ)`。这条必须写死，否则插入位置会随浮点误差抖动。

### 4.3 双喷头

- L1–L2：仅喷头 A。
- L3+：A/B 交替，**同一时刻只有一颗球在飞**（拍长 0.85s > 飞行 0.203s，天然不重叠）。
- 两个落点共用同一个相位 φ → 转一次同时影响两个落点。这正是 L3 的核心技巧"一转双消"的来源。

### 4.4 可达半径 —— 本方案真正的难度主旋钮

一拍之内，跑道最多能转多远？

```
最大位移 R = s_acc + (T − τ) · v_max
其中 τ = v_max / a = 0.2917s，s_acc = ½·a·τ² = 2.042 格
```

| 关卡 | 节拍 T | v·T（理想） | **R（含加速）** | 半圈覆盖率 = min(R,14)/14 |
|---|---|---|---|---|
| L1 | 2.10s | 29.4 | **27.36** | 100% |
| L2 | 1.75s | 24.5 | **22.46** | 100% |
| L3 | 1.20s | 16.8 | **14.76** | 100% |
| L4 | 1.00s | 14.0 | **11.96** | 85.4% |
| L5 | 0.85s | 11.9 | **9.86** | 70.4% |

**这张表暴露了原方案最大的结构性缺陷**：闭环上任意两点的最远距离是 14 格（半圈），而前三关的 R 全部 ≥14.76 → **L1–L3 的转轮没有任何"够不到"的压力**，难度 100% 来自节拍，转轮沦为装饰。真正的空间决策只从 L4 才开始。

**修正**：把 R 提升为显式关卡参数，五关按 20 → 17 → 15 → 12 → 10 递减（通过降 v_max 而非只压节拍）。这样每一关都同时有"反应压力"和"空间压力"，且曲线连续。

## 5. 时间模型

### 5.1 关键时长

| 阶段 | 时长 | 备注 |
|---|---|---|
| 充能预警 | ≥ 0.6 × T | 颜色 + 弹道虚线段可见 |
| 飞行 | **0.2031s** | 6.5 u / 32 u·s⁻¹ |
| 插入推挤 | 0.12s | 期间不接受新插入 |
| 消除爆裂 | 0.16s | 纯表现 |
| 断口合拢 | 0.14s | 纯表现，逻辑已结算 |
| 连锁单级 | 0.30s | = 0.16 + 0.14，仅表现层 |

### 5.2 飞行期的相位漂移 —— 原方案的隐藏 bug

飞行 0.203s 内，跑道最多位移 `14 × 0.2031 = 2.84 格`，而急停磁吸容差只有 ±0.25 格——**相差 11 倍**。

所以"发射瞬间算好的落点"和"球到达时的落点"根本不是同一格。原方案没定义按哪个判定，两种实现都能写出来，但手感完全不同：

- **方案 A（发射快照）**：球锁定发射瞬间的槽位，飞行中跑道从球下面滑过。视觉上"球穿模"。
- **方案 B（到达判定）**：球落在到达时的槽位上。这才是"接球"的正确语义。

**本版采用 B**，并且必须补一个原方案完全没有的 UI：

> **落点预测环**：在落点上游显示一条随速度伸缩的虚线刻度，标出 `t_flight` 之后会到达落点的 3 个槽位（1 个主判 + 2 个次判）。没有这个元件，2.84 格的漂移就是纯随机，玩家会觉得"我明明对准了"。

这是全案**性价比最高的一个改动**：一个 UI 元件把"不可控"变成"可预判"。

### 5.3 连锁期间的时间

原方案给了 0.30s/级 的动画，却没说什么 5 连消（1.5s）期间新球怎么办。L5 拍长 0.85s，1.5s 内会来 1.76 颗球。

三种解法里只有一种是对的：

| 解法 | 问题 |
|---|---|
| 连锁期间暂停发球 | 节奏断裂，高手会利用它刷分 |
| 全局 timeScale 0.3 | 影响确定性，且"变慢"会让操作手感漂移 |
| **逻辑瞬时 + 表现排队** | ✅ 逻辑零等待，动画可重叠，确定性最好 |

本版取第三种。表现层允许动画重叠/降级（同屏 >3 组连锁时合并爆裂特效）。

### 5.4 固定步长

- 逻辑步长固定 `1/60s`，累加器最多补 5 步（超出则丢弃，防 tab 切回后的死亡螺旋）。
- 输入在**每个子步**采样一次，不在渲染帧采样。
- 表现层用 `alpha = acc / dt` 插值渲染，避免 60Hz 逻辑在 144Hz 屏上的抖动。

## 6. 球与颜色

### 6.1 基础色（4 色，L1 只用 3 色）

| 色 | HEX | 亮度 L* | 形符（色盲冗余） |
|---|---|---|---|
| 红 | `#FF4D5A` | 55 | ● 实心 |
| 蓝 | `#3FA9FF` | 62 | ▲ 三角 |
| 金 | `#FFC53D` | 78 | ■ 方块 |
| 紫 | `#B26BFF` | 52 | ◆ 菱形 |

红/紫亮度接近（55 vs 52），**必须靠形符区分**。原方案只有色相，色盲玩家与低端屏会直接玩不了。

### 6.2 特殊球

| 球 | 权重 | 效果 | 触发关卡 |
|---|---|---|---|
| 彩虹 | 8% | 插入后**分别**与左右两侧结算，可同时消两侧 | L2+ |
| 炸弹 | 7% | 参与消除时额外炸掉左右各 1 颗（含锈球） | L2+ |
| 狂热金 | 5% | 消除后 7s 全局得分 ×2 | L2+ |
| 锁色 | 5% | 消除后**接下来 3 发**强制为场上最多色（增益，非惩罚） | L2+ |
| 锈球 | — | 不可消除，仅能被相邻消除震碎；占 1 格 | 放空惩罚 |

> **命名修正**：原文档叫"锁色球"却给的是增益，名字暗示惩罚。改叫**同色球 / 归色球**。名字与效果反了，实现时一定有人写错。

### 6.3 发色权重（防脸黑）

```
if 场上珠子数 ≥ 20:                 # 濒危保护
    最多色 65% | 彩虹/炸弹 20% | 其他 15%
else:
    按现存色数量加权 70% | 缺色球 15% | 特殊球 15%
连续非现存色上限：2 发（第 3 发强制回到现存色）
```

权重必须**基于当前盘面**计算，不能用纯随机。这是 Zuma 类游戏"看起来随机其实不气人"的关键。

## 7. 消除、连锁、断口

### 7.1 判定

插入后，从插入点向**两侧**各扩展同色连续段：

```
run = 1 + leftRun + rightRun
if run ≥ 3 and 该段不全是锈球: 消除
```

彩虹球：插入后分别与左段、右段独立判定，两侧可同时成立（这是最爽的一击，必须做）。

### 7.2 消除结算顺序（确定性要求）

同一帧内有多个可消除段时，**必须按固定顺序**结算，否则回放/排行榜不可复现：

1. 插入点触发的主消除
2. 断口合拢后，从合拢点向两侧扫描的连锁消除
3. 炸弹球附带的额外炸除
4. 多个候选段同时成立 → **按弧长坐标 s 升序**

### 7.3 连锁倍率

| 连锁级 | 1 | 2 | 3 | 4 | 5+ |
|---|---|---|---|---|---|
| 倍率 | ×1 | ×2 | ×4 | ×8 | ×12 |
| 续时 | 0 | +2.5s | +4.0s | +6.0s | +8.0s |

### 7.4 断口合拢

- 消除后，断口两侧珠子以 0.14s 缓动靠拢，空位被"挤"向最近的另一断口。
- **双断口时**：优先向较近断口合拢；等距时向顺时针侧合拢（写死，别让浮点决定）。
- 合拢完成后立即做一次连锁扫描。

## 8. 输入与手感

### 8.1 键位

| 输入 | 动作 |
|---|---|
| A / ← | 逆时针加速 |
| D / → | 顺时针加速 |
| Space | 急停（见 8.4） |
| 滚轮 | **删除**（理由见 8.4） |
| Esc / P | 暂停 |

### 8.2 物理参数（帧率无关）

```
a        = 48.0 slot/s²      # 线加速度（原文档误标为"角加速度"）
v_max    = 14.0 slot/s       # 建议按关卡下调，见 §4.4
k        = 9.049 /s          # 阻尼系数，等价 60fps 下每帧 ×0.86
停机阈值 = 0.15 slot/s
```

**原方案的 `v *= 0.86` 是逐帧乘法，直接绑定 60fps。** 在 144Hz 屏上停得比 60Hz 快 2.4 倍，手感完全变样。必须改成 `v *= exp(-k·dt)`。

顺带修正一个数据错误：原文档说"约 0.16s 停稳"。实测从 v_max 松手，0.16s 时速度仍有 **3.29 格/s**，真正停到 <1 格/s 需要 **0.29s**，滑行距离 **1.55 格**。这 1.55 格不是小事——它约等于一个槽距的 88%，是"刹车早了/晚了"的全部操作空间。

### 8.3 刹车的意义

滑行 1.55 格 + 加速 2.04 格，意味着"急转急停"一次操作要吃掉 3.6 格的空间。这是本作操作深度的真正来源：**你要提前 3.6 格开始规划**。这比"按一下停一下"有意思得多。

### 8.4 关于 Space 与滚轮：删掉滚轮

原方案有三套互相抵消的精确输入：

| 机制 | 性质 | 问题 |
|---|---|---|
| 惯性 + 阻尼 | 模拟量，考手感 | — |
| 滚轮 ±1.0 格 | 离散精确 | **一格格拨，等于关掉了手感** |
| Space 急停 + ±0.25 磁吸 | 自动瞄准 | **等于关掉了时机** |

三种同时存在，最优解永远是"滚轮拨到位 → 点 Space"。转轮就死了。

**本版处理**：
- **删除滚轮**。它是给触屏/无障碍留的后路，桌面版不需要。
- **Space 保留，但磁吸改为有条件**：仅当 |v| ≤ 4 格/s 时生效，容差 ±0.25 格；高速按 Space 只是硬刹车，无磁吸。

理由：v = 14 时，±0.25 格的窗口只有 **36ms**，等价于音游判定，此时磁吸等于送分；v ≤ 4 时窗口 125ms，磁吸只是"防手抖"。这样 Space 的定位清晰了——**它是精修工具，不是万能键**。

## 9. 计分

### 9.1 公式

```
单次消除 = 组内球数分 × 连锁倍率 × 精准系数 × 倍槽系数 × 狂热系数 × 关卡系数 k_L
```

| 项 | 值 |
|---|---|
| 组内球数分 | 3 球 300 / 4 球 500 / 5 球 800 / 6+ 球 800 + 400×(n−5) |
| 连锁倍率 | ×1 / ×2 / ×4 / ×8 / ×12 |
| 精准系数 | 插入两同色正中 ×1.5（要求两侧同色且长度相等） |
| 倍槽系数 | ×2.0（L4+） |
| 狂热系数 | ×2.0（7s） |
| **关卡系数 k_L** | **1.0 / 1.15 / 1.30 / 1.50 / 1.70** |

### 9.2 为什么必须有关卡系数

原方案没有 k_L，靠"目标分涨 10 倍"制造后期感。但分数上限由**发球数**决定，发球数由节拍决定，于是目标分直接变成了难度要求。反推原方案隐含的"平均连锁倍率"：

| 关卡 | 发球数 | 无连消上限（122 分/球） | 原目标分 | **隐含平均倍率** |
|---|---|---|---|---|
| L1 | 29 | 3,538 | 4,500 | **1.27** |
| L2 | 43 | 5,246 | 10,000 | **1.91** |
| L3 | 71 | 8,662 | 18,000 | **2.08** |
| L4 | 90 | 10,980 | 28,000 | **2.55** |
| L5 | 112 | 13,664 | 45,000 | **3.29** |

倍率阶梯是 1/2/4/8/12。**平均 3.29 意味着几乎每一波都得是 4 连以上**——这是顶尖玩家的线，被设成了 L5 的通关线。而 L1 要 1.27，对第一次玩的人等于"教学关就要求你会连锁"。

**这解释了为什么原方案读起来"很完整"但实际不可玩：所有目标分都是按理想操作拍的，没有一个是跑出来的。**

### 9.3 重定目标分（按"参考跑分 × 0.75"定通关线）

| 关卡 | 建议目标分 | 说明 |
|---|---|---|
| L1 | **2,650** | 会接球就能过，连锁是加分项 |
| L2 | **4,500** | 需要 2–3 次有效连锁 |
| L3 | **8,400** | 需要理解"一转双落点" |
| L4 | **12,300** | 需要主动布置倍槽 |
| L5 | **17,400** | 需要 4 连以上 |

**评级线**（单局总分，用于段位，不做通关门槛）：

| 段位 | 门槛 | 含义 |
|---|---|---|
| C | < 0.75× | 通关线以下 |
| B | 0.75×–1.0× | 及格 |
| A | 1.0×–1.4× | 熟练 |
| S | 1.4×–2.0× | 精通 |
| SS | > 2.0× | 极限 |

这样"通关"和"高分"分开了：**通关是 0.75 分位，SS 是 2 倍分位**。原方案把两者混成了一个数字。

### 9.4 续时

| 连锁级 | 续时 |
|---|---|
| 2 | +2.5s |
| 3 | +4.0s |
| 4 | +6.0s |
| 5+ | +8.0s |

**必须加封顶**：单关续时总量 ≤ 基础时长 × 50%（L1 最多 +30s）。

原方案续时无上限。在 60s、29 发的关里，只要每 2.5s 出一次连锁就能无限续命；配合"容量 28 很宽松"，结果是**高手永远不会输**——没有失败条件的游戏，压力全是假的。

### 9.5 全清奖励

- 一击把珠子清零：+3,000 × k_L，+5.0s，立刻补 5 颗（`红-蓝-蓝-红-金`）。
- 注意补的这 5 颗**不构成三消**，是给你下一波的引子，别写成直接送分。

### 9.6 放空的经济模型（本版核心修正）

原方案：放空累计 3 发 → 塞 1 颗锈球。问题：

> 环形跑道上的空位会随相位一起转。所以**任何时刻玩家都能把空位转到落点下面**，放空是零成本的。L1 甚至明写"无锈球惩罚"。于是最优策略 = 只接完美球，其余全放。容量永远填不满，接球压力消失。

**修正规则（M0 实装版，已取代原设想）**：

1. **球永远会落下**，不存在"让球飞过去"的动作。落点若压在已有珠上 → 插入并推开；落点若在空档 → 球直接停在空皮带上，成为一颗**孤立珠**。
2. 所以"放空"的真实含义是**把球停进空档**：不污染已有色段，但白占一格，且暂时接不上任何色段。
3. 每次占位都实打实消耗容量 → 容量成为每发的硬成本，三消是唯一的回收手段。

> 这条修改的原因：M0 实现时发现，若"落点为空 = 球飞走"，那么在 10 珠 / 28 格的盘面上，78% 的球会飞走，游戏第一秒就崩。而"落点为空 = 停在空皮带"既解决了这个问题，又保留了"我要不要让这颗球进链"的取舍——它只是把代价从"锈球惩罚"换成了"占格 + 孤立"。
>
> **原方案的"锈球"系统在 M0 中已删除**：它要解决的问题（放空无代价）已经被"落点必占格"从根上解决，再叠一层惩罚是重复设计。

## 10. 关卡脚本

| 关卡 | 时长 | 节拍 | 喷头 | 颜色 | 初始 | **v_max（新）** | **R（新）** | 新变量 | 目标分 |
|---|---|---|---|---|---|---|---|---|---|
| L1 启轮 | 60s | 2.10s | A | 3 色 | 6 | 20 | 20.0 | 基础循环 | 2,650 |
| L2 变奏 | 75s | 1.60s | A | 4 色 | 8 | 17 | 13.6 | 第 4 色 + 特殊球 | 4,500 |
| L3 双响 | 85s | 1.20s | A+B | 4 色 | 8 | 15 | 12.6 | 第二落点 | 8,400 |

## 11. 失败、预警、保护

### 11.1 失败三条件（判定顺序写死）

1. **达标**：`score ≥ target` → 立刻过关（即使同帧爆仓，以达标优先）
2. **爆仓**：珠子数 = 28 且需要插入 → 失败
3. **超时**：计时 ≤ 0 → 失败

### 11.2 爆仓预警（原方案缺失）

- 剩 6 格：跑道外圈亮起琥珀色呼吸光
- 剩 4 格：边框脉冲 + 低频嗡鸣
- 剩 2 格：屏幕边缘红晕 + 每拍心跳音
- 剩 1 格：全场降饱和，只留球色

**没有这三段预警，爆仓就是"突然死亡"，玩家只会觉得被坑。**

### 11.3 软锁防护

若同时满足「未达标」+「不会爆仓」+「不断续时」，关卡可能无限延长。硬性规则：

- 单关续时封顶（§9.4）
- **绝对时限 = 基础时长 × 2.0**，到点强制结算（未达标则失败）

### 11.4 濒危保护

珠子 ≥ 20 时，发色权重切到"最多色 + 功能球"模式（§6.3）。把"运气差致死"改成"残局翻盘"。

## 12. 状态机

```
BOOT
 └→ TITLE ──(start)──→ LEVEL_INTRO (1.2s 关卡名 + 目标分)
                          └→ PLAY
                              ├→ PAUSED ──(resume)──→ PLAY
                              ├→ LEVEL_CLEAR ──→ RESULT ──→ next LEVEL_INTRO / TITLE
                              └→ LEVEL_FAIL  ──→ RESULT ──→ retry / TITLE
```

PLAY 内部子状态（单拍）：

```
CHARGE ─(T−t_flight)→ FIRE ─(0.203s)→ LAND ─→ RESOLVE ─(有连锁)→ CHAIN ─┐
  ↑                                                                      │
  └──────────────────── 无连锁 ←────────────────────────────────────────┘
```

约束：
- `PAUSED` 期间累加器清零，恢复时重新计时，不补帧。
- `LAND` 到 `RESOLVE` 之间不接受新的相位输入覆盖（球已落地，输入只影响下一拍）。
- 所有状态迁移都是**逻辑帧内**发生，表现层跟随，不反向驱动。

## 13. 数据结构

### 13.1 珠链（推荐：本地坐标 + 全局相位）

```js
// 不要用原方案的"单一 offset"模型：它假设珠子焊在带上，
// 一旦需要"插入推挤"和"断口合拢"的逐珠动画就崩。
const belt = {
  phase: 0,                    // 全局相位 [0, L)
  beads: [                     // 按 sLocal 升序，最多 28 个
    { id, color, sLocal, state } // state: IDLE | PUSH | CLEAR | MERGE
  ]
};

// 世界坐标 = (sLocal + phase) mod L
// 旋转：只改 phase（O(1)）
// 插入/消除：只改 sLocal（O(n)，n ≤ 28，无所谓）
```

这个拆分的好处：旋转是 O(1) 且不产生浮点漂移；局部动画只动受影响的珠子；渲染时统一 `(sLocal + phase) % L`。

### 13.2 事件队列

逻辑层不碰渲染/音频，只 push 事件：

```js
{ type: 'insert', slot, color }
{ type: 'clear',  ids: [], chainLevel, scoreDelta }
{ type: 'whiff',  color }
{ type: 'overflow' }
{ type: 'levelClear', score }
```

### 13.3 确定性要求

- 随机数：`mulberry32(seed)`，种子 = `hash(日期, 关卡)`。
- 逻辑层禁止 `Math.random()`、`Date.now()`、`performance.now()`。
- 同种子 + 同输入序列 → 逐帧一致（用于回放校验与榜单防作弊）。

## 14. 渲染与音频

### 14.1 渲染技术选型

**建议 Canvas2D，不建议 Three.js。**

理由：全场景是"一个平面上的 28 个圆 + 粒子 + 飘字"，2D 立即模式足够，60fps 毫无压力；Three.js 会为了 3 个后处理效果引入 600KB 运行时和一整套矩阵/材质心智负担。旧方案用 Three 是因为它是 3D 弹幕，本作不是。

如果一定要 3D 球体质感：用 WebGL 单 pass，**后处理只在半分辨率做一次 bloom**，别开 EffectComposer 全链路。

### 14.2 图层顺序

```
0  背景（暗场 + 双轮轮廓 + 齿轮齿纹，慢速自转）
1  轨道（内外描边 + 槽位刻度，刻度随 R 高亮可及范围）
2  珠链（球体 / 高光 / 形符）
3  落点预测环 ★ 核心 UI
4  弹道（虚线 + 落点准心 + 充能进度）
5  特效（爆裂粒子 / 涟漪 / 飘字）
6  HUD（分数 / 计时 / 目标进度 / 连击）
```

### 14.3 落点预测环（必做）

在落点上游按 `t_flight` 画 3 个渐隐圆环，标出"0.2s 后会到这里的槽"。随 |v| 增大，环间距按 `v·t_flight` 拉开。**这是全作唯一必须做到完美的表现元件。**

### 14.4 音频

| 事件 | 设计 |
|---|---|
| 转轮摩擦 | 滤波噪声，音高 ∝ |v|，v=0 时静音 |
| 棘轮咔哒 | **不要每格一次**（14 格/s = 14 次/s，会变成嗡嗡声）；改为 <4 格/s 每格、4–10 每 2 格、>10 用摩擦音替代 |
| 接球 | 短促木质击打，音高随槽位微调 |
| 连锁 | 五声音阶 C5-D5-E5-G5-A5-C6 逐级升调 |
| 放空 | 低频漏气 + 短混响 |
| 爆仓预警 | 心跳式低频脉冲，频率随剩余格数加快 |
| BGM | 120 BPM，节拍与关卡节拍对齐（L1 2.10s ≈ 2 小节） |

**音乐必须与发球节拍同源**，让"听节奏"成为可用的辅助输入。原方案没提这件事，浪费了最大的免费难度调节器。

## 18. M0 落地纪要（实现推翻了哪些设计假设）

原型在 `bicycle-chain/src/`，可直接 `npm run dev` 跑。以下是"设计时以为"和"实现后实测"的差异，**后续开发以本节为准**。

### 18.1 必须加"基础带速"（原方案没有）

**现象**：玩家完全不操作时，球反复落在同一格，把同色珠一路推开堆叠，40 秒白拿 4500 分。

**原因**：闭环珠链静止时，"往同一点反复插"等价于"往同色堆里塞"——祖玛类游戏的"链在动"不是演出，是**防堆叠机制**。

**实装**：`CFG.drift = 1.35` 格/秒。皮带永远在走，玩家是在它之上加减速，松手只会回落到带速而不是停死。这同时让"自行车链条"的名字第一次有了物理依据。

### 18.2 "28 格爆仓"在结构上几乎不可达

**现象**：机器人 20 局里，瞄准型 0 次爆仓、挂机型 0 次爆仓，最高只到 26/28 就自动回落。

**原因**：盘面越满 → 可凑三消的位置越多 → 下一发几乎必消。**密度本身就是解药**，所以容量永远够不到 28。

**结论**：容量不是失败条件，是**计分约束**（满载时你没法做长链布局，只能被迫清场）。真正的失败条件只有超时。原方案把"塞满 28 格"当核心威胁，是误判。

**影响**：关卡曲线必须靠**节拍 + 目标分**施压，不能靠容量。

### 18.3 "选位置"的收益低于"选时机"

**实测**：每发时刻，28 个落点里平均只有 **2.88 个**能直接凑成三消（10.3%），16% 的发球**一个好位置都没有**。

**含义**：
- 技巧空间是真实存在的（乱放 10% vs 瞄准 40%+），但**上限不在"选哪里"，而在"能不能在节拍内把那个位置转到落点"**。
- 所以本作的技巧本质是**提前量 + 刹车距离**，不是空间解谜。这决定了后续所有关卡设计都该压节拍，而不是加几何复杂度。

### 18.4 M0 实装参数（可玩版本 baseline）

| 参数 | 值 | 说明 |
|---|---|---|
| 关卡时长 | 90s | 原 120s 太长，90s 更适合迭代 |
| 节拍 | 2.40s → 1.30s 线性 | 90s 内压完 |
| 起始珠数 | 10 | 18 珠版本 60 局挂机死 60 局，太苛刻 |
| 颜色 | 3 色 → 25s 后 4 色 | 3 色期把"接球"教会，4 色期才考布局 |
| 最大带速 | 13 格/s | 冲一圈 2.15s |
| 带速漂移 | 1.35 格/s | 见 18.1 |
| 加速 / 阻尼 | 55 格/s² / k=9.0 | 刹车滑行 1.44 格 |
| 目标分 | 10,000 | 挂机 baseline ≈ 6,500，目标线压在它之上 |
| 评级 | B 5k / A 8k / S 13k / SS 18k | 待人类玩家校准 |

### 18.5 遗留问题（M1 要解决）

1. **挂机 baseline 偏高**（6,500/10,000）。原因是三消太容易，需要靠"连锁质量"拉开差距——目前连锁平均只有 2.3 级。
2. **连锁收益不明显**。×1/×2/×4 的阶梯在 90 秒里几乎摸不到 ×4，倍率设计需要重估（或改成"跨发连击"）。
3. **双喷头未实装**。M0 只有顶部喷头，L3 的核心技巧"一转双落点"还没验证。
4. **没有存档与排行榜**，也没接 OpenGame SDK。

## 19. M1 落地纪要：双喷头

M0 的核心缺陷是**没有压力源**：单个落点、容量永远塞不满、挂机与瞄准得分几乎相同（6,530 vs 6,545）。M1 用双喷头同时解决"没有取舍"和"没有压力"。

### 19.1 双喷头的几何解法：共用同一个 phase

两个落点在 slot 坐标下相距半圈（`NOZZLE_OFF = [0, 14]`），但**共用同一个 `phase`**：

```
落点A = mod(round(-phase) + 0,  N)
落点B = mod(round(-phase) + 14, N)
```

这一条是整个 M1 的关键。它意味着：

- 玩家操作的仍是**一个**转轮盘，不是两套控制；
- 但一次转动会**同时**改变两个落点的格局；
- 两个落点相距 14 格，节拍只有 2–3 秒，**结构上不可能两边都照顾到**。

机会成本不是靠惩罚规则堆出来的，是几何内生出来的。这是本作和普通祖玛最本质的区别。

### 19.2 落点为空时，球吸附进链（不是钉在空皮带上）

M0 的实现是"落点是空槽 → 球停在空皮带上变成孤立珠"。实测这条让 **46–54% 的落球都变成了孤立珠**，直接导致：

1. 玩家转轮盘失去意义（落点附近没珠，转了也白转）；
2. 盘面被孤立珠填满，形成不可解的死锁。

**修正**：落点为空时，球吸附到最近的珠子、插进链里（`snap()`）。这是祖玛的正统行为——球永远属于某条链。"接空"的代价从"占一格"变成"插到了你不想要的位置"，这个代价更符合直觉，也更能被玩家理解。

配套的渲染：落点为空时，从炮口指向画一条虚线连到实际插入点，并在插到位画一个小环。**不做这个可视化，玩家会以为球钉在了空处。**

### 19.3 单喷头教学期

双喷头第一秒就要求玩家同时看两个地方，实测乱按 20/20 全灭。加入 20 秒的单喷头期（`nozzle2At = 20`）：先教会"接球"，再教"取舍"。

### 19.4 五色的引入必须强制

`pickColor()` 原本 22% 概率做均匀抽样来引入新颜色。实测 5 色解锁后，青色在整局里几乎不出现——因为它在盘面上 count 为 0，永远进不了"按存量加权"的候选池，只能等那 22% × 20% ≈ 4.4% 的运气。

**修正**：当 `present.length < maxCi`（有颜色缺席）时，38% 概率直接返回缺席色。这一条同时修好了"某色被消光后不再出现"的问题。

### 19.5 M1 实装参数

| 参数 | M0 | M1 | 理由 |
|---|---|---|---|
| 喷头数 | 1 | 2（20s 后） | 压力源 + 取舍 |
| 落点间距 | — | 14 格（半圈） | 一个 phase 无法同时满足两边 |
| 节拍 | 2.40→1.30s | 3.40→2.05s | 每拍落 2 球，信息量翻倍，必须放松 |
| 起始珠数 | 10 | 8（两段各 4） | 两段落点各自有货可接 |
| 颜色 | 3 色 → 25s 后 4 色 | 4 色起手 → 45s 后 5 色 | 3 色太容易消，盘面会被抽干 |
| 目标分 | 10,000 | 5,500 | 按 M1 实测 baseline 重定 |
| 评级 | B5k/A8k/S13k/SS18k | B2.8k/A4.5k/S6.2k/SS8k | 同上 |

### 19.6 M1 实测（20 局 × 90 秒）

| 玩法 | 爆仓 | 存活 | 平均分 | 消除/落球 |
|---|---|---|---|---|
| 挂机（零输入） | 10/10 | 0/10 | 990 | 0.10 |
| 乱按（每 14 帧随机换向） | 20/20 | 0/20 | 1,390 | 0.12 |
| 瞄准机器人 | 1/20 | **19/20** | **5,585** | 0.28 |

**这是 M0 → M1 最关键的读数变化**：

| | M0 | M1 |
|---|---|---|
| 挂机 vs 瞄准 得分比 | 1.00× | **5.6×** |
| 挂机存活率 | 10/10 | **0/10** |
| 乱按存活率 | — | **0/20** |

M0 里"瞄准"完全不兑现成分数；M1 里它直接决定生死。

### 19.7 技巧空间量化

在每次发球时刻，遍历全部 28 个整相位，计算两个落点的总收益：

| 指标 | 数值 |
|---|---|
| 最优相位收益 | 119.6 |
| 随机相位收益 | 32.0 |
| **技巧倍率** | **3.74×** |
| 两个落点同时可消的相位占比 | **1%** |

最后一行是设计结论：**99% 的节拍里，玩家必须主动放弃一边**。这不是难度失衡，这就是玩法本身。

### 19.8 M1 遗留问题

1. **连锁仍然起不来**（平均 1.8–2.1 段）。原因是双喷头每拍两颗球，落点分散，很难让"第一次消除后的合拢"恰好拼出第二组。倍率阶梯（×1/×2/×4/×8/×12）实际上摸不到 ×4。**M2 需要重做连锁：改成"跨节拍连击"而不是"单次落球内的连锁"。**
2. **吸附率仍偏高**（39–44%）。根因是珠子在闭环上会聚成段、留下大段空白，落点常落在空白里。真正的解法是让珠子沿环均匀化，但那会破坏"推挤-合拢"的手感，暂不动。
3. **没有真人数据**。所有平衡数字都来自机器人，必须用真人 5 局校准。
4. 无存档、无排行榜、未接 OpenGame SDK。

## 20. M2 落地纪要：多模式、球种编码、连消、音频

M1 的遗留问题里，最硬的一条是「连锁起不来」。M2 没有绕过去加系统，而是先改掉了产生这个问题的规则，再补齐模式、可读性与表现。

### 20.1 几何必须参数化，否则「大小轮」只能靠复制代码

原实现里 `R / C / N / L / D` 是模块常量，`NOZZLE_POS` 与 `IMPACTS` 直接写死在渲染层。M2 把它们全部改成可配置：

```js
// geom.js
export let R = 4, C = 6, N = 28, L = 4*C + 2*Math.PI*R, D = L / N;
export function configure({ r, c, n }) { ... }
```

用的是 **ES 模块 live binding**：`export let` 被重新赋值后，所有 `import { N }` 的模块读到的都是新值。代价是同一时刻只能有一个 `Game` 实例——本项目成立，测试里也按模式串行跑。

炮口位置不再写死，而是由落点沿**外法向**推出：

```
nozzle = pointAt(off*D) + normalAt(off*D) * 3.7
```

`normalAt` 用「法向与位矢点乘」判朝向：跑道是闭合凸形，质心在环内，与位矢同向的那一支一定朝外。这样三射口模式下位于圆弧上的炮口也能自动朝外，不需要为每个模式写坐标。

### 20.2 四个模式

| 模式 | 格数 | 射口 | 节拍 | 时长 | 目标分 |
|---|---|---|---|---|---|
| 标准双轮 | 28 | 2（半圈） | 3.40→2.05s | 90s | 5,200 |
| 小轮练习 | 20 | 1 | 2.50→1.50s | 60s | 3,200 |
| 大轮长跑 | 40 | 2（半圈） | 3.80→2.20s | 120s | 9,000 |
| 三射口 | 30 | 3（三分环，轮转两发） | 3.90→2.60s | 75s | 4,500 |

所有参数集中在 `modes.js`，`sim.js` 只执行，界面只展示。调平衡不需要碰逻辑。

### 20.3 三射口不能「三球齐发」

这是 M2 唯一一个**结构性**判断。三消净减 2 颗，每拍落 3 球意味着每拍要凑出 3 组三消；30 格盘面在 4 色下根本给不出这么多位置。直接做必然每局 20 秒内爆仓。

做法：**轮转两发**。每拍有且只有一个口休息，下一拍换一个口休息。

```js
const idxs = [];
for (let k = 0; k < 2; k++) idxs.push((this.volleyIndex + k) % n);
this.volleyIndex = (this.volleyIndex + 1) % n;
```

三个落点仍然全部参与（每个口每 3 拍休 1 拍），压力却回到 2 球/拍。玩家能看见哪个口在休息（`REST` 标记），也能靠预览队列提前知道下一拍谁来。

### 20.4 三球预览队列

每个射口一个长度 3 的队列：`queues[i][0]` 是待发球，`[1][2]` 是预览。发球时 `shift()` 再 `push(pickColor())`。

实现上有两个细节：

1. **未激活的射口不消耗队列**。这样第 20 秒副炮上线时，玩家早就看见它要发什么颜色，而不是上线瞬间才第一次看到。
2. 预览必须画在**炮口切线方向**而不是法向外侧。法向外侧对顶部炮口是向上（会撞标题区），对底部炮口是向下（会撞连消条）；切线方向贴着跑道外缘排开，任意角度都不会侵入 HUD。

### 20.5 球的四重编码

原来只有色相 + 形符，色弱玩家仍然要靠色相猜。M2 改成四重：

| 维度 | 作用 |
|---|---|
| 色相 | 正常玩家的第一通道 |
| 明度 | 灰度下仍能区分（金/青亮，红/蓝/紫暗） |
| 内部纹样 | 环、斜纹、方板、六点、双环——轮廓之外的冗余 |
| 中心形符 | 实心圆、三角、方、菱、十字——最高对比通道 |

`V` 键切「高对比模式」：形符放进白色圆底徽章、用黑符，形状成为主要信息，颜色退成外圈。截图验证过五种形符在 40 格满盘下仍可逐一分辨。

### 20.6 连消：把「每拍都消」改成「窗口制」

M1 的连击规则是「连续每一拍都有消除才涨」。实测每拍平均只有 **0.56 次**消除，这个条件等于永远拿不到加成——机器人峰值连击只有 3.6，倍率几乎没上过 1.6×。

M2 改成：

- **按消掉的颗数累加**（一次四消直接 +4）；
- **3 秒内没有新消除才断**；
- 倍率表最多 5.3×（连消 20 颗）。

改完机器人峰值连消 6.5–14.8，倍率真正参与结算。这是 M2 对分数曲线影响最大的一处。

清空跑道额外 +1500，并给一次全屏冲击波——它鼓励「敢把盘面打空」，和「密度即解药」的结构正好互补。

### 20.7 特效与音频

消除事件现在携带 `s0 / len / chain / combo`，表现层据此生成：

- 沿跑道的**光带**（按弧长采样，跟随弯道）；
- 扩散**冲击环** + 粒子；
- 屏幕震动与瞬时闪光，强度随连锁与连消递增；
- 飘字：`+分数`、`连锁 ×N`、`连消 ×N`。

音频全部程序化合成，两条总线（music / sfx）。BGM 是 32 个八分音符的循环（96 BPM），用 `ctx.currentTime` 提前 0.2 秒调度，不随帧率漂移。强度由盘面占用率驱动：越挤，琶音越亮、踩镲越密。

### 20.8 M2 实测（每模式 12 局）

| 模式 | 瞄准得分 | 瞄准存活 | 乱按存活 | 挂机存活 | 技巧倍率 |
|---|---|---|---|---|---|
| 标准双轮 | 9,233 | 12/12 | 0/12 | 0/12 | 3.02× |
| 小轮练习 | 4,346 | 12/12 | 4/12 | 4/12 | 4.84× |
| 大轮长跑 | 12,146 | 12/12 | 1/12 | 1/12 | 4.74× |
| 三射口 | 6,950 | 12/12 | 2/12 | 1/12 | 3.98× |

不变量检查 38,455 项全部通过（队列长度、槽位占用上限、相位范围、分数有限性）。

### 20.9 M2 遗留

1. **小轮仍可挂机 4/12**。它是练习关，刻意留了容错；但「不操作也能过三分之一」还是偏高，M3 要么缩短时长，要么在 45 秒后强制提速。
2. **40 格满盘时珠子刚好相切**，视觉上偏挤。若要更松弛，需要把 D 与 BEAD_R 的比例从 0.94 降到 0.88，代价是「珠链感」变弱。
3. **连锁仍以 1–2 段为主**。合拢后的二次匹配天然稀少，这是几何决定的，不是参数问题。要让连锁常见，得引入「同色磁吸」之类的规则，但那会改变玩法内核，暂不做。
4. 仍无真人数据、无排行榜、未接 OpenGame SDK。

## 21. 飞行时长：0.203 → 0.34s，以及它带来的连锁改动

> **本节已被 §24 取代。** 0.34s 仍被玩家认为太快，最终值是 0.80s。保留本节是因为它记录的那条因果链（飞行越久 → 落点漂移越大 → 必须给预告）依然成立，只是当时对"屏幕速度"的理解是错的，见 §24.1。

需求原话是"射出的球追到链条的时间要慢一点"。这不是一个纯视觉参数 —— 球在飞的时候链条一直在动，**飞行越久，落点离"你按下那一刻对准的位置"越远**。

### 21.1 先算清楚代价

落点是在 `land()` 用**当帧 phase** 算的，所以飞行期的位移直接决定命中：

| 飞行时长 | 静止时漂移位移 | 满速时的位移 |
|---|---|---|
| 0.203s（旧） | 0.27 槽（在 ±0.5 取整窗口内） | 2.6 槽 |
| 0.34s（新） | **0.46 槽**（贴到窗口边缘） | 4.4 槽 |

第三列说明：**只要玩家在球飞行时还在转轮盘，落点就会被自己的输入带偏**。这不是 bug，是"提前量"这个技能的物理来源；但 0.34s 下它变成了必须遵守的纪律。

### 21.2 实测：三种控制方式的存活率（标准模式，32 局）

| 控制方式 | 存活 | 均分 |
|---|---|---|
| 边飞边改（持续追最优相位） | 8/32 | 6,228 |
| 发射后收手（飞行期不动） | 24/32 | 7,270 |
| 旧参数 0.203s + 边飞边改 | 30/32 | 7,612 |

结论：**球变慢不是"难度变高"，是"操作节奏变了"** —— 需要从"持续微调"改成"发射 → 松手 → 落地 → 再动"。所以渲染层必须把这条规则教给玩家，否则就是纯挫败。

### 21.3 三条配套修正（缺一不可）

1. **落点预告环**：在链条上圈住"球落地时会被击中的那颗珠"（白环 + 珠色外发光）。
   - 只在**开火前 0.55 秒到落地之间**显示 —— 没有球在飞时，松手预测要跨过整整一拍（4 格以上），那不是玩家正在做的决定。
   - 只给**真正会开火的口**画环。三射口模式有一个口在轮休，给它也画环等于骗人。
   - 预测公式与 sim 的 `land()` 完全一致（用阻尼解析积分算"松手后滑多远"），实测 **404 次落点，0 次偏差**。

2. **珠链命中高亮的方向修正**：`arrivalAlpha()` 原来把峰值放在 `dist=0`，也就是**即将离开炮口**的那颗珠。球越快这个错越不明显（0.203s 时误差小于半格），球一慢就原形毕露 —— 玩家会发现自己一直瞄的是"上一颗"。现在峰值落在 `dist≈|coast|`，即真正会被击中的那颗。

3. **飞行轨迹**：沿**切线**方向起弧 + 「半线性半 smoothstep」缓动。
   - 弧线原来沿外法向鼓，正好顶在前进方向的反面，球看起来像卡在炮口没动。
   - 纯 smoothstep 的峰值速度是平均值的 1.5 倍，那一下"窜"正是"一闪就到"的来源；混一半线性后接近匀速。

### 21.4 新的操作纪律

**发射 → 松手 → 落地 → 再动。**

球在空中时继续转轮盘，会把这一发打偏。这条规则由"预告环亮起"来提示：环亮 = 你已经进入承诺期。

| 模式 | 瞄准得分 | 存活 | 对比 M2 |
|---|---|---|---|
| 标准双轮 | 8,815 | 10/12 | 9,233 / 12/12 |
| 小轮练习 | 4,855 | 12/12 | 4,346 / 12/12 |
| 大轮长跑 | 10,644 | 12/12 | 12,146 / 12/12 |
| 三射口 | 5,952 | 12/12 | 6,950 / 12/12 |

标准模式掉了 2 局，其余持平或更好；四个目标分仍然全部可达。

## 22. 分数段与段位反馈

### 22.1 「按分数段变色」这个提议只对了一半

颜色是**状态**，不是**动机**。把分数从白色改成金色，玩家看到的是"我现在是什么颜色"，而不是"我要去打更高"。持续状态不会产生驱动力，只会变成装饰；更糟的是，如果阈值定得不对，它还会传递错误信息（"随便打打就是 SS"）。

真正能推动复玩的是三件事，缺一不可：

1. **可见的下一档**（目标梯度效应：离目标越近，投入越强）
2. **跨档那一瞬间的爆发**（事件才形成记忆点）
3. **跨局的身份**（"我在这关是 S"，而不是"我打了 8,200 分"）

所以本轮做的是三件套，颜色只是其中最低成本的一层。

### 22.2 落地清单

| 位置 | 内容 | 作用 |
|---|---|---|
| HUD 分数 | 数字按档位着色 + 段位徽章（C/B/A/S/SS） | 状态识别，余光可读 |
| HUD 分数下方 | 档内进度条 + 右端"下一档"刻度（越近越亮） | 目标梯度，告诉玩家"就差一点" |
| HUD 进度条下 | `NEXT A −1,240` | 把"差多少"变成确切数字，不说模糊的"加油" |
| 跨档瞬间 | `RANK A` 浮字 + 冲击波 + 闪光 + 上行琶音 | 把状态变化变成事件 |
| 结算页 | `距 S 还差 420 分` | 复玩钩子：差得越少，重开率越高 |
| 标题页卡片 | 右上角历史最高段位徽章 | 跨局身份，存档有意义 |

SS 段额外加了呼吸明灭（`0.74 + 0.26·sin(4t)`），让最高档"看起来在烧"，和下面四档拉开体感差异。

### 22.3 阈值怎么定：分位数 + 人类左移

每个模式跑 20 局完美瞄准机器人（**1/120 真实步长**），取分位数：

| 模式 | p10 | p25 | p50 | p75 | p90 |
|---|---|---|---|---|---|
| 标准双轮 | 3,900 | 6,500 | 7,800 | 9,600 | 10,800 |
| 小轮练习 | 3,400 | 3,800 | 4,300 | 5,000 | 6,200 |
| 大轮长跑 | 7,900 | 9,000 | 9,300 | 11,000 | 13,100 |
| 三射口 | 4,600 | 4,900 | 5,400 | 7,300 | 8,500 |

映射规则：**B≈p10 / A≈p25 / S≈p50 / SS≈p75~p85**。

关键在"为什么不用 p90 当 SS"。机器人每帧计算最优相位、零反应延迟，人类达不到它的水平。如果把机器人 p90 定为 SS，人类最好的玩家也只能摸到 S —— **拿不到的顶级等于不存在**，玩家会直接放弃追求。所以整条分位映射要往左移一档，让机器人当"人类高手"的替身。

另一条约束：**档间距不窄于总分的一成**。三射口和大轮的中段分布很密（p25 到 p50 只差 400~500 分），按原始分位画线会导致"一次三消跨两档"，跨档演出就不稀缺了。

### 22.4 颜色选型的两个硬约束

1. **不能和球色撞**。球已占用红/蓝/黄/紫/青五色，并靠色相 + 明度 + 纹样 + 形符四重编码。分数段若用紫色，会和球紫混淆。所以走「等级色阶」惯例：灰 → 绿 → 蓝 → 橙 → 白热，避开紫。
2. **不能和警告撞**。右侧 CHAIN LOAD 用红（危险）/黄（警告），TIME 最后 15 秒也转红。这些是**紧急信号**，优先级必须高于段位。段位是静态色、警告是闪烁色，位置也分离（左上 vs 右侧），才不打架。

C 段原本用 `#8B9BB4`，实测在深底上几乎读不出来，提亮到 `#AEBED2`。**深色主题下"低调"和"看不见"只差一档**。

### 22.5 顺手修掉的一个真 bug：测试步长 ≠ 运行步长

做分档时发现同一批种子对不上，查明：`main.js` 用 `DT = 1/120`，而 `test.mjs` 用 `1/60`。

这个游戏是"精确相位对准"，对时序混沌敏感。实测同一个种子在两种步长下会走向完全不同的分支：

| seed | 1/60 得分 | 1/120 得分 |
|---|---|---|
| 19 | 6,600 | 14,469 |
| 13 | 11,181 | 6,537 |
| 4 | 8,637 | 3,015 |

也就是说，**§21.5 那张表、以及之前所有平衡结论，测的都是"另一个游戏"**。已把 `test.mjs` 统一到 `1/120`，并重跑全部数据。

顺带修掉：`?ff=` 快进到死时直接切结果页、不写 `best`，导致调试截图与真实游玩战绩不一致。现在统一走 `finishRun()`。

| 模式 | C | B | A | S | SS |
|---|---|---|---|---|---|
| 标准双轮 | 1 | 1 | 5 | 2 | 3 |
| 小轮练习 | 2 | 3 | 1 | 2 | 4 |
| 大轮长跑 | 2 | 4 | 2 | 1 | 3 |

### 23.2 品类不是 Zuma 发明的

- 1998 年 Mitchell Corporation 街机《Puzz Loop》（北美名 Ballistic，DS 名 Magnetica）是该品类的源头。
- Mitchell 曾指控 Zuma 抄袭，未有胜诉结果；PopCap 创始人 Jason Kapalka 公开表示"乐于见到游戏被克隆"。
- PopCap 商务负责人 James Gwertzman 在 Gamasutra 上被问及中国大量 Zuma 克隆时明确表态：**不生气，选择"不诉讼，而是把正版带进中国市场参与竞争"**。
- 同品类的 Luxor（MumboJumbo，2005）与 Zuma 共存二十年，未被判侵权。

这些事实说明：**玩法层面的维权在实践中极难成立，权利方自己也清楚**。所以真正的风险不在"像不像"，而在"叫什么"。

### 23.3 本作天然具备的防御性差异

万一被比对，以下几个差异点是结构性成立的，不是贴皮：

1. **视角反转**：玩家是接球方，炮口自动开火，玩家只控制落点相位。原品类是玩家当射手。
2. **闭环双轮**：跑道首尾相接，两个落点共用同一 `phase`，机会成本由几何内生（见 §0.1、M1 纪要）。
3. **吸附而非孤立珠**：落点为空时球插进最近的珠子，保留"球永远属于某条链"的品类正统性。
4. **视觉体系完全不同**：几何光效 + 球种四重编码 + 色弱模式；无阿兹特克、无石蛙、无神庙、无骷髅口。
5. **独立创作证据链**：完整的设计文档演进（§18~§22 的每次推翻）+ git 提交历史，可证明从零推导而非照搬。

第 5 条最实用。**git 历史就是最便宜的原创证据**，不要 squash 掉。

## 24. 飞行时长第二刀：0.34 → 0.80s，以及一个骗了很久的机器人缺陷

### 24.1 先把问题重新定义对

上一轮（§21）把"球到得太快"当成"球飞得快"，于是把 `flightTime` 从 0.203 拉到 0.34。玩家仍然反馈"追上末尾球的时间太短"。

第二次才想清楚：屏幕上的速度不是球的速度，是**球的位移 + 链条迎面滑过来的位移**之和。

| 项 | 0.34s | 0.80s |
|---|---|---|
| 球速（炮口→跑道约 113px） | 332 px/s | 141 px/s |
| 链条迎面速度（drift 1.35 槽/s） | 72 px/s | 72 px/s |
| **眼睛看到的接近速度** | **404 px/s ≈ 8 球径/秒** | **213 px/s ≈ 3 球径/秒** |

8 球径/秒超出人眼追踪单体的舒适区，玩家只能看到"一闪"，看不到"追"这个动作。3 球径/秒才留得住过程。

### 24.2 反直觉结论：加长飞行几乎不增加难度

这是本轮最有价值的一条，也是它一开始让我不敢下手的原因。

改完 0.66 之后我准备重调所有平衡，结果发现 `flightTime` 从 0.66 到 0.80，四模式的机器人得分差异在 1% 以内：

| 模式 | 0.66s | 0.80s |
|---|---|---|
| 标准双轮 | 7,648 | 7,648 |
| 小轮练习 | 4,643 | 4,643 |
| 大轮长跑 | 10,171 | 10,010 |
| 三射口 | 6,447 | 6,447 |

三个模式的 12 局分数**逐位相同**。原因是落点漂移完全可解析（`coast = drift·T + (v−drift)(1−e^{−kT})/k`），完美玩家会提前补偿，所以"球在空中多久"对它没有影响。

**飞行时长只消耗人类的预判窗口，不改变游戏的数学难度。** 这正好是我们要的：让反应慢的玩家看得清，而不是把游戏改简单或改难。

### 24.3 但它炸出了机器人控制律的真实缺陷

在拿到上面这个结论之前，我先踩了一个坑：`flightTime` 改成 0.66 时，标准模式的机器人爆仓 10/12、得分从 8,586 掉到 4,227。

第一反应是"飞行期滑移 0.9 格，游戏变难了"，于是去降 `drift`（1.35 → 0.90）。结果**更糟**：标准 4,370，大轮 6,584。降速本该让游戏更简单，反而更差——这个矛盾说明问题不在游戏，在测量工具。

查下去发现 `bot.js` 的控制律是一阶近似：

```js
nv = drift + err / T          // 旧
```

它把 `drift` 同时当成了"基础推进力"和"漂移量"。真实的位移是指数衰减的，`err/T` 只在 `T` 很小时成立。`flightTime` 从 0.34 拉到 0.66，`T` 变大，近似误差被放大到无法忽略；而降 `drift` 直接抽掉了这个公式的底座。

改成解析反解：

```js
// coast(v,T) = drift·T + (v−drift)(1−e^{−kT})/k  = gap
// ⇒ v = drift + (gap − drift·T)·k/(1−e^{−kT})
```

同一份 `flightTime = 0.66`，同一批种子：

| | 旧控制律 | 精确反解 |
|---|---|---|
| 标准双轮 | 4,227（爆仓 10/12） | **7,648（12/12 存活）** |
| 大轮长跑 | 7,597（爆仓 4/12） | **10,171（12/12）** |
| 三射口 | 5,867（爆仓 1/12） | **6,447（12/12）** |

也就是说，**"游戏变难了"这个判断完全是假的**，是机器人自己不会瞄准。

这是第三次同类事故：

| 次数 | 表面结论 | 真因 |
|---|---|---|
| §12.3 | 难度曲线不合理 | 机器人边飞边改，把落点带偏 |
| §22.5 | 分数分布不对 | 测试步长 1/60 ≠ 运行 1/120 |
| §24.3 | 加长飞行导致爆仓 | 控制律用一阶近似，T 变大后失效 |

三次都不是游戏的问题，都是**用代理去判断体验时，代理本身失真**。规律很清楚：只要动了"时间尺度"或"控制回路"的参数，就必须先验证代理在这个新尺度下还算不算数。

### 24.5 代价与遗留

1. **链条在飞行期间滑过 1.1 格**（超过一整格）。落点预告环从"辅助"变成"必需品"，关掉它这个时长就没法玩。目前没有关闭选项，等于隐性强制。
2. **小轮模式的拍长最短 1.5s，飞行占 53%**。球还没落地下一拍就要来了，画面上会有两批球交替。机器人不受影响，人类可能会觉得挤。
3. **0.80s 是估算的终点，不是验证过的终点**。舒适区在 0.6~0.9 之间，只有真人能定。如果还嫌快，下一档应该动炮口距离（把 3.7 单位拉远），而不是继续拉时间——时间再长，节奏会散。

## 25. 三消演出的时间预算：0.4s → 0.7s

### 25.1 先列清单，再动数值

"三消表现时间慢一些"不是一个参数，是四条并行的线。只拉其中一条，看起来会像"画面在回放、别的东西先走了"。

| 元素 | 原时长 | 现时长 | 作用 |
|---|---|---|---|
| 光带 beam | 0.36s | 0.62s | 告诉玩家"消的是这一段" |
| 冲击波 shock | 0.40s | 0.68s | 把能量推到周围 |
| 球体消散 ghost | 无 | 0.52s | 补上"大球碎成小点"之间断掉的那一拍 |
| 粒子 | 0.30~0.66s | 0.46~0.98s | 碎屑，负责密度 |
| 分数浮字 | 1.05s | 1.30s | 确认"这一下值多少" |
| 消除音效尾音 | 0.16s | 0.24s | 与视觉同收 |

浮字必须最长。如果数字先消失，玩家会处在"看到爆炸但不知道赚了多少"的状态——比不做特效更糟。

### 25.2 粒子要"减速"，不是"延长"

第一版只把粒子的 `life` 从 0.3~0.66 拉到 0.46~0.98，结果碎片飞得到处都是，甚至越过跑道压到 HUD 上，看起来像漏液。

初速不变而寿命变长，位移就是线性增加。所以正确做法是三件事一起做：

| 参数 | 原值 | 新值 |
|---|---|---|
| 初速 | 60 + rand·260 | 44 + rand·196 |
| 阻尼 | 2.6 | 2.0 |
| 重力 | 420 | 320 |

**"慢"是让同样的距离走更久，不是让它走更远。** 这一条在 §24 调球的飞行时也同样成立（那里是改成拉长时间而不是提高速度），但当时没抽象出来，这里才写清楚。

### 25.3 球消失的动画做了三次才对

这是本轮唯一反复的地方，三次都不对：

| 尝试 | 做法 | 结果 |
|---|---|---|
| 1 | 扩散光圈，半径 1.4 倍 | 消除后 `compact()` 会把后面的珠子前移占住原位，光圈必然和球重叠，读起来是"珠子描了一圈色" |
| 2 | 把光圈 alpha 压到 0.36 做成雾 | 几乎看不见，等于没做 |
| 3 | **原球原地缩小 + 全程叠白** | 成立 |

前两次的根因是同一个：**想用"新东西"去表示"消失"**。而消除后原位置立刻会被新珠子占据，任何画在原地的图形都会被读成新珠子的属性。

第三次改成让那颗球自己缩掉，语义就没有歧义了。但只缩小还不够——静态看缩小的球仍然是完整的球（有高光、有纹样），像"跑道上多了几颗小球"。所以叠了一层持续上升的白：白度 `k^0.7`，随缩小同步。读起来才是"过载 → 湮灭"。

白化只在尾段做也不够（第一版从 `k>0.25` 才开始），因为前半段缩短的球已经能被误认成小球了。

### 25.4 冲击波走缓出

半径原来是线性 `r = r0 + (r1−r0)·k`。线性扩张在整段时间里速度不变，观感是"匀速飘走"；改成缓出 `1−(1−k)²` 之后，前半程铺开、后半程几乎停住。**同样 0.68s，体感明显更慢，而且更有分量。**

这是个便宜的技巧：想让某个特效"变慢"，先看它的缓动，再看时长。线性运动的"慢"要靠加时间，缓出的"慢"不用。

### 25.5 遗留

1. **连续消除会叠加**。实测每拍平均 0.5~1 次消除，0.7s 的演出重叠概率不低。理论上会糊，但"糊"在消除品类里通常被读成"打得好"，这一条只能真人判断。
2. **三射口模式同时三个落点**，一次连锁最多 9 颗球同时消散。粒子上限没有做，帧率在低端机上可能掉。目前没测过真机。
3. **`?cb=1` 色弱模式下的对比度没复验**。白色叠加会降低球色辨识度，色弱玩家可能更难分辨"正在消失的是哪一色"。但这个信息在消失瞬间不重要（玩家已经看到消除了），暂不处理。
